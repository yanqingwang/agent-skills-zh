# tasteskill v2

模型做出的页面，通常像是它见过的所有页面的平均值：居中的标题配三行文字，标题上方一个小标签，一排图标卡片，一道柔和渐变，几条细线和一行等宽字体的说明文字。其中没有任何东西是错的，也没有任何东西是被决定出来的。

本 skill 用"决策"取代这些默认值，方式有四：

1. **方向由脚本抽牌给出，由你来挑。** 让模型凭空发明一种外观，它每次都会挑品类的默认值。`scripts/draw.mjs` 会从 20 个经过研究的方向中抽出 3 个；你选出能承载主题创意的那一个，然后脚本再从一座提炼自 247 个真实站点的资料库中，抽出它的字体系统、配色、hero 与各分区的构图。
2. **创意来自主题本身。** 在这项研究中，把最出色的站点与平庸易忘的站点区分开的，是一个取自事物本身的概念，而不是样式。
3. **一套不带装饰物的自有风格规范，** 由 `scripts/inspect.mjs` 在真实浏览器中度量，规则是被检查出来的，而不是被寄望的。
4. **你要亲眼看自己做出来的东西。** 三个宽度的截图、一套评委评分标准，修复，再看。

一条测试中换来的警告。去掉装饰物只完成了一半工作；一个失去了标签、细线与卡片、却没在原处得到任何补偿的页面，读起来单薄，盲测评委也理应更偏爱内容更充实但带生成痕迹的页面，而不是没有痕迹的空洞页面。另一半是实质：更大的字号、整片整片的色场、这个主题世界的真实图片（找到的或绘制的），以及每个分区都装满完整内容。本 skill 就是为把这些交到你手上而设计的，不要拿它们去换克制。

下文命令中的 `<skill>` 指本 skill 所在的文件夹。请从项目根目录运行它们，这样工作文件才会落在项目下的 `.taste-skill/` 中。这些脚本需要 Node 22+ 和一个已安装的 Chrome、Edge 或 Chromium，且不会安装任何东西。`assets.mjs` 还需要网络访问；它不使用任何 API key。

## 页面还是应用界面

先判断这属于两类工作中的哪一类。

- **页面（page）**是用来读、用来滚动的：落地页、营销站或产品站、作品集、活动页、餐馆页、单页站。它遵循下方的**执行流程**。
- **应用界面（app screen）**是在其中干活的：仪表盘、管理或数据分析视图、设置页、计费页、待处理的收件箱或队列、钱包、带筛选器的列表、编辑器或构建器。它遵循 **`references/app-screens.md`**：自己的流程、自己的抽牌（`draw.mjs --app`）、自己的内部规则（低调边框、小标签和重复面板在那里是正常的；渐变、发光、色底方块图标、彩虹图表和编造的虚荣数字则不是）以及 `inspect.mjs --app`。开始之前把那个文件完整读一遍；下方的页面流程不适用。

展示自家应用的产品站是页面；页面上的界面碎片，其内部遵循应用界面规则。对产品的应用风格做一次抽牌，放在专属文件夹中，并保留页面的配色与字体：

```bash
node <skill>/scripts/draw.mjs --app --kind <kind> --brief "<the product>" --keep palette,type --out .taste-skill/app
```

然后把这个页面展示的每个碎片（hero 区的实时界面、某个功能的裁切、一张图表）都构建成那个应用的真实一块：面板、表格和控件用 `assets/app.css`，图表用 `assets/charts.js`，数据要真实、能对得上账，讲出一个发现，并按页面蓝图处理一张图片的方式去裁切与缩放。一个看起来像真实运行中的产品的碎片，是软件类页面所能拥有的最强图片；灰色条块和 lorem 假数据是最弱的。当请求两者混有（一个落地页加上它背后的仪表盘）时，各自按自己的流程构建，共用一套配色和一种字体。

## 执行流程

按顺序执行以下步骤。第 1–5 步只需要几分钟，却决定这个页面到底好不好。

### 1. 阅读需求简报与项目

弄清什么是真实存在的：主题、受众、页面必须让访客做到的那一件事、技术栈、任何已有品牌（颜色、字体、logo），以及最重要的，**到底有哪些图像素材真实存在**：项目自己的照片或产品图、可以展示的真实界面、你可以调用的图像生成工具，或者什么都没有。不要围绕你手上没有的图片做规划。"什么都没有"很少真的是什么都没有：主题所在的城市、街道、材料和历史，都在开放档案与博物馆里，署名即可免费使用（见第 6 步、`scripts/assets.mjs`）。

如果需求含糊，就自己拿定主意，并用一行说明你的理解，而不是开口去问。只有当缺失的事实阻塞了工作（例如没有产品名）时才提问。

然后在你的笔记里**为主题做一份清单（inventory）**：写下 8 到 12 件只属于这个客户、不属于任何竞争对手的东西。找它的名字以及名字的含义；它的地址、门牌号、街道与街区，以及那个地方长什么样（它的瓷砖、招牌、漆色、店面上的字体、它的光线、它的天气）；简报里的数字（座位数、房间数、到海边的分钟数、价格、年份）；它所共处的约束（每月只做一批、冬季歇业、仅接受预约）；它的材料与颜色；它的仪式与时刻（五点生火的烤炉、七点开出的渡轮）；它世界里的印刷品（一张时刻表、一枚标签、一张票、一块牌子）。这份清单就是第 4 步创意的来源。在盲测中，每个简报下胜出的页面都是清单上某一条造就的（客户的名字及其含义、它所坐落的街道、那个让它成为它的约束），而落败的页面则有一个好构图，但创意停留在品类层面。这份清单同时也是你的图片检索表：上面的每个地点、材料和印刷品，都是第 6 步的一个检索词。

### 2. 写下论证

在动手设计之前，按照 `references/copy.md` §1 展示的方式，把页面列成一条条论断及其证据，每个分区一行。这些论断决定哪些分区存在、以什么顺序存在。删掉任何没有论断的分区。这样你才能避开 hero、logo 墙、三个功能、用户见证、定价、行动号召这套套路序列。

### 3. 抽出方向

```bash
node <skill>/scripts/draw.mjs --sector <sector> --brief "<one line about the subject>" \
  --sections <roles in the order of your argument> [--tone <tone>] [--have <assets>] [--keep palette,type] \
  --options 3
```

这一步会抽出 3 个方向，并打印每个方向的简短摘要。把每个方向对照你的清单来掂量：哪种构图方式能承载只有这个客户才有的东西？选那一个，而不是最眼熟的那个，并在笔记里用一行写下为什么。在测试中，一个不适合主题的随机方向，是页面羸弱的最常见原因。然后抽出完整的方向表：

```bash
node <skill>/scripts/draw.mjs <the same arguments, without --options> --direction <chosen id>
```

- `--sector`：运行 `node <skill>/scripts/draw.mjs --list sectors`。挑最接近的。
- `--sections`：来自 `--list roles` 的分区角色（features、showcase、how-it-works、testimonial、proof、stats、pricing、faq、cta、footer、intro、about、work、gallery、list、contact）。hero 无需列出，默认包含。
- `--tone`（可选）：quiet、bold、warm、technical、playful、luxury、editorial。只有当简报明确提出时才传。
- `--have`：真实存在的素材，逗号分隔：`photography`（项目自己拍摄的人物、场所或作品照片）、`product-photo`（具体产品的照片，或能生成它们的图像工具）、`product-ui`（真实截图）、`illustration`、`video`。一样都没有就整个省略：抽牌会因此避开依赖它们的构图，方向表也会说明如何诚实地填补图片槽位（软件展示用 HTML 构建的自家界面；没有照片的产品则用绘制呈现，并安放在其真实世界的图片之间，绝不用假产品图）。你稍后在开放图库中找到的图片不算项目自有素材；不要把它们填进 `--have`。
- `--keep palette,type`：当品牌已经固定了颜色或字体时使用。此时抽牌只抽出构图，由你把品牌的取值映射到各个角色上。

该命令会打印一份**方向表（direction sheet）**。它就是本次构建的艺术方向：

- **照单全收。** 不要把它和你本来就会做的那个版式掺在一起。如果它让你感到陌生，很好：那个眼熟的版式，正是本 skill 要防止的东西。
- 仅当你能说出理由时才重抽某个槽位（`--redraw hero | type | palette | photos | scenes | section:<role> | direction`）：理由是该槽位与某条明示的品牌约束相矛盾，或它需要一个并不存在的素材。绝不要为了换得更顺手而重抽。每一次重抽都要记入报告。
- 当抽到的分区装不下真实内容时（它设计成对比三个方案而实际只有一个价格；它想要五条用户引言而一条都没有），不要把内容掰弯去迁就。用 `--alternatives <role>` 列出其他选项，挑一个前提假设与内容相符的，再用 `--redraw section:<role>=<id>` 换上它。
- **把配色放到主题面前检验。** 抽到的配色既是颜色组合，也是一组比例（一个底色、一个墨色、一个强调色、几个色场）。如果它的颜色与主题自身的材质相冲（给泥煤威士忌配糖果粉彩，给山间小屋配霓虹色），重抽一次配色；如果主题拥有不可否认的自身颜色（它的材质、它所在街道的漆色、它窗外的风景），则保留抽到的比例、改从主题取色，并在报告中说明。
- 随时可以用 `node <skill>/scripts/draw.mjs --show` 重新打印它。在长会话中，构建每个分区之前都重读一遍。

### 4. 找到创意

方向是一种构图方式。创意则是让这个页面属于这个主题、而不属于任何其他主题的东西。把这句话写进你的笔记，在两个空格都从主题本身填上之前，不要开始构建：

> 在这个页面上，**[某个属于主题的东西]** 成为 **[方向所要求的手法（device）]**。

为第一个空格寻找素材的地方：

- **它的产出。** 这个东西生产什么？把真实的产出作为素材放上页面。（一台打印诗歌的相机，把它的作品做成一沓纸签呈现。）
- **它的形体或轮廓。** 它的实体长什么样？剖面是什么？剪影是什么？把它放大、裁切，让它成为画框或唯一的母题。
- **它的名字。** 这些字母能否承载一张照片、堆叠成一堵墙、拆分到两个角落？
- **它的所在地。** 有没有一个画面，让人看了就想去那里？
- **它的仪式。** 有没有一个序列，可以让页面随着滚动依次上演？
- **它的实物凭据（artefact）。** 它的世界里已经存在什么印刷品：票、菜单、标签、收据、请柬、档案夹、说明书？
- **它的对立面。** 哪个其他品类拥有本品类所缺少的那种感觉？

第一个空格要从你的清单（第 1 步）里填，而不是从品类里填。**竞对测试：** 把最近的那个真实竞争对手放进这句话里（两条街外的面包房、另一家橡木家具作坊、同一座山上的另一间小屋）。如果这句话依然成立，说明创意属于品类：一条面包属于每家面包房；而以它命名的那条街上的七扇门，只属于这一家。"干净而现代"不是一个创意。研究中评委会打分最低的站点，正是那些创意被记为"除标准公式外没有别的"的站点。

**一个互动活元素（live thing）。** 给页面一件访客能动手做的事，或者每次访问都不一样的东西，而且要从创意里长出来：挑一种木料，看到椅子从中显现；输入你的名字，看到它被铸字厂的字体切开；设定贷款金额，读到真实的月供数字；看看小屋的炉子此刻是否点着、距离末班渡轮还有多久；选一个尺寸，看看它摆在房间里的样子。在盲测中，每个胜出的页面都有一个这样的元素，而且评委总是第一个提到它。规则：它使用主题的真实内容；在手机上用拇指就能操作；没有脚本时有一个朴素的回退；绝不阻碍阅读；而且它是一件东西，不是游乐场。它在第 6 步作为页面的一部分被构建，而不是在第 9 步作为动效追加。

**场景同样承载创意。** 方向表上的滚动场景是一些等待主题填充的手法。在构建之前，先从清单决定每一个展示什么：穿越镜头穿过的是这间工作室自己的字卡；路线是这批货物实际走的公路；展开铺满全屏的那张图片，是客人醒来时所在的房间。一个塞满了谁都可能有的图片的场景，只是一张屏保。

### 5. 写下文字

在写标记之前，按照 `references/copy.md` 把整页内容写成一份文案清单（copy deck，纯文本）：

- **每一条标题在任何宽度下都不超过两行。** 在敲定一个句子之前，先做 copy.md §2 的算术：在足够自信的字号下，约 32 个字符在任何宽度都安全。研究过的画廊站点 hero 标题中位数为 5 个词、32 个字符。
- 一句支撑句，直接放在标题正下方（距标题 32–48px）并与标题一同显示，绝不停靠在首屏底部，也绝不被动画扣住不放。当标题是一个名字或一个修辞时，这句话直白地说清这东西是什么。一个主要动作，按它的功能命名，作为首屏上的真实按钮。
- **首屏用大字号回答访客的第一个问题。** 活动页：这是什么、何时何地（日期应放在标题里或第二级字号中，绝不能只出现在小字里）。产品页：它是什么、卖多少钱或能做什么。人物页：他是谁、他做什么。访客为之前来的每个分区（阵容、菜单、房型、价格）都有自己的标题，在导航中有自己的位置。
- **写出完整内容。** 简报要求的每个分区都要完整交付它的信息：带价格的整份菜单、每个房间各自的细节、每位讲者与每场演讲、价格及其包含的内容、每个真实问题的答案。内容单薄，是干净页面输给花哨页面最常见的原因。
- 简报留空之处（菜名、房间名与房价、项目名称）应填入示例细节，让设计以完整的密度被看到；把这些示例列入报告，请客户确认。证据绝不可编造：不编造客户、引言、评价、媒体报道、logo 或经营数据。

### 6. 构建页面：先保持静止

构建页面时，在脑中把动效关掉；一个需要动画才显得完成的页面，就是没有完成。工作顺序：

1. **Token。** 把方向表中的颜色与字体角色写成 CSS 自定义属性（custom properties）。下游一切只引用 token。`<skill>/assets/base.css` 是一个可供你起步的中性地基（reset、token 命名、流式字号阶梯、栅格、焦点与选区样式、动效辅助函数）；它自身没有任何外观倾向。
2. **hero 区，严格按蓝图所述的样子来做，** 桌面宽度与手机宽度都要。先让大的东西够大、小的东西够小，再考虑其他一切。
3. **每个分区都从它的蓝图出发，** 填入本项目的真实内容。保留几何结构，替换主题。相邻分区不得共用同一种版式。**把创意带进每一个分区，** 包括定价、FAQ 和页脚：研究中最常见的失败，即使发生在优秀站点身上，也是第一屏很独特、后面跟着一串套路块。
4. **图像，按以下优先顺序：**
   1. 项目自己的；
   2. 生成的，前提是你有图像工具；
   3. **来自开放图库的主题世界真实图片，** 只要存在一张诚实的就用。用 `node <skill>/scripts/assets.mjs "<query>"` 检索（Openverse、Wikimedia Commons、芝加哥艺术学院与大都会博物馆；默认仅限允许商业使用的授权）。检索清单，而不是品类：老明信片上它的街道、街区的一张旧地图、它的材料的特写、它的行当的版画、博物馆里同类的物件、植物图版、星图。大尺寸、有意图地使用：一张档案照片做 hero，一幅版画放大为页面的母题，那张真实的街道地图做联系分区。选用前逐一过目；`--get <ref>` 会把图片下载进 `assets/` 并记录其来源与授权，`--credits` 打印供页脚使用的署名行。找到的图片展示的是客户周边的世界，绝不能冒充客户自己的产品、房间、菜品、人物或团队；
   4. **以代码从主题本身绘制，** 用于那些不存在诚实图片的对象（它的器物、它的瓷砖、它的窗、它产品的界面，用配色中的真实颜色，做成一套统一的扁平图形语言）；
   5. 方向表里抽到的照片，只用在诚实地"通用"恰如其分的地方（海滨小屋配大海），绝不用作主题的替身；
   6. 只有字体与颜色。

   当项目有自己工艺或产品的视频或真实图片时，首屏就要大尺寸展示它（约占屏幕 40% 或更多）。绝不要在页面上写一句话去解释图片的来源或它们不是什么（"以下没有一张是我们酒吧的照片"）：说明图片是什么用图注，署名行小字号放在页脚。为简报虚构作品的作品集，要把每件作品绘制成该作品的成品剧照（带自有字体的字卡、一帧片尾、一张海报），细节要真实，绝不能画成客户产品的象形图标。

   **图像下限（floor），检查器会核查：** 页面上至少 4 张真实图片，通常 6 到 12 张（照片、档案图像、地图、版画、视频片段、位图作品；对软件而言，其裁切的界面碎片也计入）。SVG 绘制不计入下限：没有真实图片可用的对象才用绘制，页面仍然要有真实图片。凡存在诚实的视频片段之处，加一段动态影像：用 `assets.mjs --video "<query>"` 检索，以静音循环加封面帧的方式使用。模型之所以跳过图片和视频，是因为找它们费事；没有它们，页面就是不及格的。

   `references/imagery.md` 涵盖检索、授权与署名、视频、绘制、裁切与处理手法。
5. 来自第 4 步的**互动活元素**，构建进它所证明的那条论断所在的分区（通常是 hero 或预订处），内容要真实，提供拇指可操作的手机版和一个朴素回退。
6. **滚动场景，** 当方向表抽到它们时（第 9 节），每个场景连同它承载的分区一起做：页面的大时刻、穿过作品的飞行镜头、展开铺满全屏的图片、在滚动下弯折的词。从 `<skill>/assets/scenes/` 复制共享舞台和场景文件，用本项目自己的图片与文字填充场景，并设置页面 token，让它继承页面的外观。场景是构图的一部分：它决定页面有多长、每一屏展示什么，所以现在就要构建、每一轮查看都要过目，而不是最后再补。`references/scenes.md` 说明了如何把场景放上页面、填充、适配与检查；`assets/scenes/demo/<id>.html` 是每条场景的可运行示例。
7. **饱满。** 把每个桌面屏当作一张海报来看：一个主导元素，加上它承载的内容。一片大半空荡荡的屏幕是构建不足的分区，不是留白；每页至多一次有意安排的留白，出现两块及以上近乎全空的屏幕，检查器会判该页不合格。正文用足墨色、16px 或更大；灰色只用于次要注记。
8. **外框。** 页面在任何宽度下都有一对外边距相等的外框，且每个分区都使用页面设定的宽度：当它的文字位于左半边时，右半边要放上它的图片、第二栏、列表或图示，绝不能什么都没有。不对称只存在于栅格之内，绝不出现在外框上：一个空缺只有在远端有东西封住它时才允许出现。页面中不存在高于约半屏却空无一物的区段；桌面端各分区相距 120–240px。访客为之前来的每个分区，都以一个点名它的标题开场；首屏用 `h1` 承载页面标题。页面看起来不对劲时，读者最先点名的正是这些（"没有清楚的标题""莫名其妙的空白""所有东西都挤到一边"），而检查器对其中每一项都有度量。
9. **状态与语义。** 真实的链接与按钮、可见的焦点、alt 文本、一个自成构图的手机版布局。

需要某个决策背后的细节时，去读 `references/type.md`、`references/colour.md` 和 `references/layout.md`；下方的法则只是简版。

### 7. 闸门

```bash
node <skill>/scripts/lint.mjs <source files or folder>
node <skill>/scripts/inspect.mjs <url or path/to/index.html>
node <skill>/scripts/scenes.mjs <url or path/to/index.html>     # when the page has scroll scenes
```

`scenes.mjs` 会在每条滚动场景停留区间的 0、10…100% 处各拍一张照片，桌面与手机各来一遍，外加 reduced-motion 页面；当方向表含场景时，`inspect.mjs` 还会拍摄整段滚动（`desktop-film-NN.jpg`）。一条在桌面上从未启动、或中途停住的场景，判 `FAIL`。

`lint.mjs` 扫描源码中的违禁模式与套路短语。`inspect.mjs` 在真实浏览器中以 1440、768 和 390 像素打开页面并进行度量（标题行数、字号、实际加载的字体、颜色、细线、阴影、渐变、对比度、溢出，以及外框：外边距是否相等、分区是否挤在一边、空白区段、标题、无标题分区、贴着屏幕边缘的文字），并把截图保存到 `.taste-skill/inspect/`。修复每一个 `FAIL`。每一条 `WARN` 都按错误对待，除非你能用一句话向设计师辩护。反复运行直到没有 `FAIL`。不要和量尺争辩，也不要向它藏东西。检查器通过一个用完即弃的本地服务器提供本地文件；如果页面还必须能直接从文件系统打开，那么在收尾前用那种方式打开一次 `index.html`。

### 8. 查看

通过闸门只说明没有度量到任何违禁项，不说明页面是好的。打开检查器列出的每一张截图（每个视口都要，用你的图片查看器或 Read 工具），并按照 `references/critique.md` 对它们做评析：十四项检查、按 Awwwards 加权的分数、各项上限。按其格式写下评析，修复排前三的问题，再跑一次检查器，再看一遍。至多三轮。

只依据图片来评判。只要问题在截图里可见，它就是真的，无论代码怎么说。

### 9. 动起来

现在构建动效层。动效层是必需品，而且远不止一个淡入：检查器会统计页面加载与滚动过程中真正在动的元素数量，少于 8 个判不合格（少于 16 个给警告）。滚动场景（如果方向表抽到）已在第 6 步建好；围绕它们，动效层有四个组成部分：

1. **方向表点名的招牌动作**：一个，做精（抽到的场景可以充当它）。
2. **每个分区各部分的入场：** 先标题，再正文，再图片，错峰 60–90ms，上浮 16–32px 并伴随透明度变化，在分区进入视口时触发一次。不要给整块内容一个统一的淡入，更不要出现脚本失败后一直隐藏的内容。
3. **每个控件的反馈：** 按钮、链接、卡片和互动活元素的按压、悬停与聚焦反馈。
4. **一段动态影像：** 找到的片段做成静音循环，或对一张照片做缓慢的缩放或漂移，或对 hero 图片做滚动联动的移动。

只动 transform 和 opacity；每一个动作都有 `prefers-reduced-motion` 回退：保留内容、去掉位移。改变整屏颜色或版式的动作（按章节变色、钉住的长卷叙事）属于构图的一部分，所以要在第 6 步构建，让每一轮查看都能看到它。`references/motion.md` 提供了 token 与经过验证的配方。之后再跑一遍检查器，逐张检查截图中有无未能出现的内容。

### 10. 报告

以下各项全部满足之前不要报告；在一次结果很糟的试运行中，每一项都被跳过过：

- 在页面的最终版本上，`inspect.mjs` 在 1440、768 和 390 下均为 **0 FAIL**。
- 最后一次修改之后，检查器列出的每一张截图你都打开看过，而不只是第一屏。
- 有滚动场景时：`scenes.mjs` 在最终页面上运行无问题，且你读完了每一张样张（桌面、手机、reduced motion）。
- 一个陌生人盯着首屏读五秒钟，就能说出这是什么、该做什么。
- 每个分区都有标题；两侧外边距对称；页面没有任何空置区段。
- 最后一轮的评析已按 `references/critique.md` §4 的格式写下来。

简要告诉用户：抽到的方向（名称与 seed）以及每一次重抽及其理由；创意句和互动活元素；最后一轮评析的最终分数与仍然欠缺之处；每一张找到的图片与片段的标题、作者、授权与来源页面（`assets.mjs --credits` 会打印清单）及其署名在页面上的位置；哪些内置照片和哪些绘制图在充当摄影的替身（以便替换）；以及所有必须在上线前替换的示例内容。没有运行过的检查，不要声称运行过。

## 内部规则

无论抽到什么方向，以下规则对每一次构建都生效。`inspect.mjs` 会度量它们。

| 规则 | 替代做法 |
| --- | --- |
| **标题：任何宽度下不超过两行。** 所有 `h1`–`h6`，以及首屏主行（无论它用什么标签）。 | 先删词。然后加宽行宽。最后才动字号。 |
| **首屏有清楚的标题**，放在页面唯一的 `h1` 里，且每个分区都有标题。 | 说清这是什么：名字配上它是做什么的，产品配上它是给谁用的，活动配上日期与地点。 |
| **外边距两侧相等；没有分区挤在一边**，让另一半屏幕空着。 | 每个空缺都在远端用东西封住：分区的图片、第二栏、列表或图示。 |
| **没有高于约半屏的空白区段。** | 正常的分区间距。有意的留白是一张安排好的图片或一整片色场，每页至多一次。 |
| **陈述就该用段落。** 放大排版的导入句或引言，应标记为 `<p>` 或 `<blockquote>`，保持陈述字号（桌面不超过 36px，手机 24px），长度约 25 个词、三行以内。 | 超过这个尺度它就是标题，两行规则适用。盲测中，评委把跨四行的 42px 句子读成了四行标题。 |
| **不要眉题（eyebrow）。** 标题上方不放小标签，主标题上方不放药丸徽章，不用"New ·"小徽章。 | 把信息放进标题或第一句话，否则干脆去掉。 |
| **真实代码块之外不用等宽字体。** | 用正文文字字体。数字需要对齐处用等宽数字（tabular figures）。 |
| **不要序号编号。** 不用 01 / 02 / 03，不用 (001)，不用"第 2 步"。 | 顺序靠位置、字号或文字表达。顺序确有意义时用真正的 `<ol>`。 |
| **不要细线。** 不用发丝分隔线，不用 1px 描边框，不用栅格线、十字准星或裁切标记。 | 用留白。用背景色调的一个台阶。用尺度的变化。用一块实心形状。 |
| **不要渐变。** 背景不用，按钮不用，文字不用。 | 纯色，或真实照片。图片上文字下方的中性压暗层是唯一例外。 |
| **静止之物不投影。** 不用发光。 | 表面之间用色调台阶。阴影只给真正悬浮之物：菜单、对话框。 |
| **不要"AI 助手"配色。** 不用奶油黄底配陶土色或铁锈红；不用紫罗兰或靛蓝。 | 用抽到的配色。 |
| **不要小号、全大写、加字距的标签。** | 用可读字号的自然大小写。 |
| **不要图标打头的功能卡片，不要成排的雷同卡片。** | 用抽到的分区蓝图。 |
| **不要毛玻璃。** 不用背景模糊面板，不用悬浮药丸导航。 | 一条朴素的栏：字标、几个链接、一个动作。 |
| **不要 emoji，不要渐变色块，不要装饰形状，不要灰色条块拼成的假仪表盘。** | 一张真实图片、一个真实界面碎片，或者什么都不放。 |
| **标题里不要"造型强调词"**（斜体、衬线、变色、下划线）。 | 一种字体、一个颜色。强调靠文字本身。 |
| **至多两种字体，** 通常一种。 | 用抽到的字体系统。 |

有三处地方保留自己的惯例，检查器对它们放行：`<pre>`/`<code>` 中的真实代码（等宽字体在这里是正确的）、真实的表格与表单字段（它们可以有线条），以及根元素带 `data-ui` 属性的真实界面碎片（产品自己的边框与菜单；见 `references/imagery.md` §7）。

坦白说说为什么是这些。其中一些来自研究的实测：在 247 个站点中，评委会打 7.5 分及以上的站点，使用图标功能卡片的比例是 1%，而低于 6.5 分的站点是 28%；药丸徽章 14% 对 34%；渐变 22% 对 52%；阴影 24% 对 48%；小号加字距全大写标签 16% 对 57%。另一些则是 skill 作者本人的品味，与当下画廊流行风相悖：等宽字体标签、序号编号和发丝栅格在获奖站点上其实*更*常见，恰恰因此，生成器才会去模仿它们，也恰恰因此，它们如今看起来像戏服。在本 skill 中，它们无例外地被禁。`references/tells.md` 保存着带日期的登记册。

去掉装饰物会腾出空间。绝不要再用另一个装饰物去填它。用尺度去填（把主元素放大），用完整内容去填，用为这个主题专门绘制的图片去填，或用一整片纯色色场去填。有意的空置，每页至多一次。

## 手艺法则

简版。数字除注明为内部风格外，均来自研究。

**字体**
- 页面上可见的工作由两三个字号完成：一个非常大，一个小，中间没有过渡。研究站点中标题与正文的字号比中位数为 4.3；最好的站点远超此数（最大字号：头部站点中位数 8.4vw，弱站点 5.0vw）。
- 展示字体：字距 -0.02 至 -0.05em，行高 0.85–1.05。正文字体：16–20px，行高 1.45–1.6，每行 45–75 字符。
- 一个页面五个字号是上限。一种字体家族是常态（研究站点的三分之一）；两种是极限。
- 默认左对齐。至多允许一个居中的时刻。

**空间**
- 一套栅格，一对外边距（16–32px），处处通用；大元素直接顶到边缘。整页的文字块共用两三条左基线。
- 不对称存在于栅格之内，绝不在外框上：两条外边距相等，偏离中心的标题要有栅格远端的元素来呼应。
- 分区之间的间距明显大于任何分区内部的间距：桌面端 120–240px（研究的中位数约 240）。
- 每个分区的构图都不同于相邻分区；任何一个都不是卡片栅格。

**色彩**
- 一个底色，一个墨色，一个强调色。强调色出现在动作上，或许再加一件事物。
- 正文用足墨色。用浅灰排版的页面读起来像没做完。
- 表面之间靠细小的色调台阶区分，绝不靠线条或阴影。
- 一个分区可以整块更换色场颜色。任何东西都不渐隐入任何东西。

**图像**
- 一张主导图片胜过六张小图。在得分最高的站点上，68% 的 hero 媒体至少覆盖首屏的一半。
- 相同的裁切比例、相同的处理手法、直角边，除非方向另有要求（研究站点中 73% 让媒体保持直角）。
- 没有图片，胜过占位符、图标或抽象形状。而一张为这个主题专门绘制、用它的颜色、用心画出来的图，又胜过"没有"。一张找到并署名的、它世界的真实图片，还要更好。
- 每一张找到的图片都下载进项目，在页面上署名，并列入报告。任何一张都不得冒充客户自有。
- 任何东西都绝不压在标题或陈述句上方（检查器会判不合格）。

**组件**
- 按钮：扁平，单一填充色，要么直角要么全圆角，一次定死（头部站点：52% 直角，23% 药丸；9–16px 的"柔和"圆角是弱站点的默认）。多数强 hero 根本没有按钮，或只有一个。
- 导航：字标、三到五个朴素链接、一个动作。导航栏不加任何装饰件。
- 页脚是一次设计好的收束，不是站点地图：多数强站点会让名字以全宽回归。

## 特殊情况

**已有品牌或设计系统。** 传入 `--keep palette,type`，把品牌的颜色与字体映射到各个角色上，只从抽牌中取构图。内部规则依然生效；如果品牌本身要求某个被禁的手法（它的 logo 带渐变、它的强调色是紫罗兰），保留品牌素材，在报告中说明，并向检查器传入 `--allow <rule>`，只豁免那一条规则。

**对既有页面或应用界面的重设计、改样式或评审。**

1. **记录改造前的状态。** 原样运行项目，把它检查到专属文件夹中（`inspect.mjs <url> --out .taste-skill/before`，应用界面加 `--app`），并对源码跑 lint。读代码：框架、样式方案（Tailwind v3 或 v4、CSS modules、styled-components、纯 CSS）、组件，以及必须幸存的东西：路由、表单、数据、行为、品牌自有素材。
2. **评审到此为止。** 按照 `references/critique.md` 评析改造前截图，连同检查器的度量列出发现，并点名最能推动页面的三处修改。
3. **保住技术栈、内容与已经奏效的部分。** 不做框架或样式库迁移；添加任何东西之前先查依赖文件。改样式（restyle）保留版式，从抽到的方向中取字体、配色与组件（品牌固定的东西用 `--keep` 锁定）；重设计（redesign）抽一个完整方向，在既有组件内部按其蓝图重建各分区。无论哪种，都从执行流程的第 2 步开始，使用页面的真实内容。
4. **工作顺序，以最小风险换最大效果：** 字体（字族与字号阶）、配色（一个底色、一个墨色、一个强调色）、外框（外边距、分区节奏、首屏标题与各分区标题）、状态（hover、focus、加载中、空态、错误态），最后把套路组件（图标卡片、药丸徽章、渐变色块、卡片栅格）替换为抽到的蓝图。
5. **拿出证据。** 再次检查并输出到 `.taste-skill/after`，在每个宽度下对比前后，把之前可用的每个链接、表单和菜单都点一遍，并排报告前后的度量结果。

**单个组件或单个分区，而非整页。** 跳过抽牌，除非没有任何方向可循。贴合周边设计，应用内部规则与法则，结果仍然要过检查器。

**没有收银台，没有表单后端。** 简报给出真实去向时，主按钮就指向那里。否则它打开一封主题与正文都写好的邮件（`mailto:`，自动填入访客的选择）；如果是商店，它指向 `#checkout`，并在报告中说明上线前必须接线。绝不伪造支付表单。

**没有 Chrome 或 Node 22。** 运行 `lint.mjs`（Node 18+），用手头任何浏览器工具截图，并对截图做评析。在报告中说明检查器未能运行。

**没有网络。** 如果 `assets.mjs` 连不上任何来源，就改用绘制的图片，并在报告中说明开放图库无法检索。
