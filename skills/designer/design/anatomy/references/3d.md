# 3D：图里会转动的部件

可选的 3D 模式（"转组"，turning groups）让图形中的部分部件以刚体方式运动：会旋转的表盘或转台、会屈曲的手指、脱落翻滚的碎块。这些部件每一帧都由 kit 自己的规则重新投影、重新着色，并按由分离平面求解出的顺序绘制。其余一切仍是普通的静态 kit 图素。未启用此模式的图形不受任何影响。

**Status: beta.** 引擎已在 `examples/turning-dial` 和一个测试图形（仅凭本文档搭出的台扇）上得到验证，尚未在生产图形上验证。一次只转一个主体，让杂物保持静态，并在添加部件之前用第 15 节的预算衡量你的图形。

## 1. 何时值得给图形上 3D

只有当运动本身就是要表达的内容时才用：表盘随转动读数、转台从各个角度展示物体、轮组、抓握或断裂的手。绝不作为装饰。只需要某个部件滑动或指针摆动的图形保持 2D：`translateAlong` 和重绘指针更便宜也更精确。

## 2. 模型

- **组。** 组是一个带位姿的刚性框架。种类：`turn`（绕穿过 `pivot` 的竖直轴旋转，任意角度）、`slide`（沿某方向平移，`0…travel`）、`hinge`（绕过某点的任意轴旋转，限定在 `range` 内，以度计）和 `free`（任意旋转加平移，由图形每帧设定）。组可嵌套：位姿相对于父组。
- **静止态。** 每个构造器都以**静止时的世界坐标**为输入（所有组值为 0，所有自由组为 `null`）。引擎减去每组的原点，因此记录器（`A.recorder`）、kit 与引擎共享同一个世界。
- **动态层。** 动态层是舞台中的一个 `<svg class="iso-svg iso-live" data-live="name">`。动态层与静态层按 `T.stack([...])` 给出的顺序堆叠：例如 `back svg → [dial live] → back canvas → [hand live] → front canvas → front svg`。
- **恒等式。** 绕竖直轴把一组旋转 θ，与 kit 以方位角 `a − θ` 绘制完全等价，因为 kit 的光源锁定在相机上。因此转组的每一帧就是 kit 在 P′(θ) 处自己的画面，整体平移；P′(θ) 处的 kit 构建器是保真度基准，且所有 kit 屏幕空间审计在 P′(θ) 处原样运行。铰链与自由组则改为矩阵合成（正确，略慢）。

## 3. 最小页面

`examples/turning-dial/` 是参考场景：一个带滚花、刻度和数字的表盘，第二个转组（窗口下的刻度盘），一个铰链（骑在滚花上的棘爪），一只约 80 个部件、带材质的手，一根会抬起的三铰链手指，一个作为自由组脱落的六角舱，以及 WebGL LED、光池与火花。`examples/turning-dial/stress.mjs` 是性能场景（杂乱车间中转台上的一只细节密集的手）；它未通过审计，所以请从 `build.mjs` 取用编写模式。

`build.mjs`，删减到骨架：
```js
import * as k from "../../kit/iso-kit.mjs";
import * as A from "../../kit/audit.mjs";
import { turning } from "../../kit/turn-build.mjs";
import * as TA from "../../kit/turn-audit.mjs";
import { turnScript, glScript } from "../../scripts/inline-kit.mjs";

export const P = k.fitProjection(points, W, H, { pad: 22, azimuth: 40, elevation: 31 });
export const R = A.recorder(P);
export const T = turning(P, { recorder: R });
const dial = T.group("dial", { turn: { pivot: [0, 0] } });
const lift = T.group("f2.mcp", { parent: dial, hinge: { point: C1, axis: w, range: [-22, 0] } });
const hand = T.layer("hand");
T.stack(["back", "hand", "front"]);
export const follow = (values) => ({ ...values, "f2.mcp": -22 * (values.lift ?? 0) });
export const poses = () => Array.from({ length: 720 }, (_, i) => follow({ dial: i * 0.5, lift: (i % 90) / 90 }));

T.round({ name: "dial.body", group: dial, layer: hand, F: VERT(0, 0), s0: 10, s1: 14.4, r: 50, material: "steel", details: { ribs: { s0: 10.9, s1: 13.7, count: 150, seams: true, tone: "lo" } } });
T.prism({ name: "hand.palm", group: dial, layer: hand, plan: PALM, z: 19.4, h: 8, bevel: 0.9, material: "gold" });
T.tube({ name: "cable.red", group: dial, layer: hand, route, r: 0.7, hue: "red", material: "rubber", gaps });
// … static kit art: R.put({ name, layer: "back", svg, shapes }) as usual …

const out = T.build({ statics: R.items, poses, verify: argv.includes("--verify") });
A.settle(R, P);
if (argv.includes("--audit")) {
  A.auditOrExit(R, P);
  TA.orbitOrExit(T, R, P, { sweep: { at: (x) => follow({ dial: x }), from: 0, to: 360, frame: 0.3 }, clips: [{ name: "tap", at: (t) => follow({ dial: 40 + 12 * t, lift: tapAt(t) }), from: 0, to: 4, frame: 1 / 60 }] });
}
const stage = `<div class="iso-stage iso-turn" tabindex="0" role="slider" …>${backSvg}${out.layerSvg("hand", { width: W, height: H })}${frontSvg}</div>`;
const page = k.pageHtml({ title, theme, body: k.plateHtml({ …, body: `<style>${out.css}</style>${stage}` }), script: turnScript() + LIVE });
```
`live.js`：
```js
const controller = TURN.mount(stage, DATA.turn, { follow, onHold: () => (touring = false), onFrame: () => paint() });
function tick(now) {
  …
  controller.set({ dial: angle, lift });
  frame = visible && moving ? requestAnimationFrame(tick) : 0;
}
```
循环由图形自己拥有（`motion.md`）；controller 绝不运行自己的 `requestAnimationFrame`。`out.css` 就是 `TURN_CSS`（表盘面带规则、材质、色相导管和 `.iso-turn` 堆叠）：只引入一次。

**在 React 或 Next.js 中**（`references/react.md`）：把 `turn.mjs`、`turn-build.mjs` 和 `turn-audit.mjs` 复制到 kit 旁边并改写 import（`./iso-kit.mjs` → `./kit`，依此类推），`TURN_CSS` 作为只引入一次的 `turn.css`。几何模块（服务端）运行 `turning(…)` 和 `T.build(…)`，返回舞台标记（每个动态层一个 `out.layerSvg(name, { width, height })`，按堆叠顺序放在静态 SVG 与 canvas 之间），并把 `out.data` 放进图形数据。客户端挂载调用 `TURN.mount(stageElement, data.turn, { follow, onHold, onFrame })`，用自己的循环驱动 `controller.set(...)`；在 effect 的 cleanup 中返回 `controller.destroy`。verify 构建可把 `out.verify` 放进数据，由挂载逻辑赋值 `window.__isoVerify`，供 `turn-check --order` 使用。

## 4. 编写 API

### 场景
| 调用 | 作用 |
|---|---|
| `turning(P, { recorder, scale = 1 })` | 构建器 `T`。传入 kit 记录器，让每个动态形状也被记录，供 kit 审计使用。 |
| `T.group(name, { parent?, turn: { pivot: [x, y] } })` | 绕穿过 `pivot` 的竖直轴旋转，值以度计。 |
| `T.group(name, { parent?, slide: { direction, travel } })` | 平移，值为 `0…travel` 世界单位。 |
| `T.group(name, { parent?, hinge: { point, axis, range: [lo, hi] } })` | 绕穿过 `point` 的 `axis` 旋转，值以度计，限定在 `range` 内。 |
| `T.group(name, { parent?, free: { origin } })` | 自由刚体（第 7 节）。值为 `{ R: [9] \| q: [x, y, z, w] \| axis, angle, t: [3], world? }`，静止时为 `null`。 |
| `T.layer(name)`, `T.stack([…])` | 动态层，以及动态层与静态层名称的完整堆叠，从后到前。 |
| `T.build({ statics, poses, verify = false, strict = true })` | 求解每一对部件、证明每个静态项所在层、打包页面数据。`poses` 是图形可达的状态集（列表或返回一个状态的函数）：每段运动剪辑都要采样。任何一对部件没有分离平面、任何静态项无法证明、任何非凸部件，都会抛出可读的错误。`strict: false` 保留互锁对（让植入的故障能到达审计）。 |

`T.build` 返回 `out = { svg, data, css, report, layerSvg(name, { width, height }), verify }`。`out.data` 交给页面（`DATA.turn`）。`out.report` 含 `parts`、`layers`（每层：`planar`、`framed`、`dynamic`、`skip` 计数）、`tight`、`margins`、`proofs`、`seconds`。

### 构造器
每个构造器的公共选项：`{ name, group, layer, tone = "hi", crease = "faint", lit = false, material, owner, details = {} }`。

| 构造器 | 部件 |
|---|---|
| `T.prism({ plan, z, h, steps, bevel })` | 一块直立的 kit 平板（kit 的 `extrude` 规则）。 |
| `T.prism({ F, polygon, s0, s1, round = 0, steps = 4, bevel = 0 })` | 框架 `F = { o, a, u, v }` 中的凸多边形，沿 `F.a` 从 `s0` 挤出至 `s1`，任意轴向（`prismOf` 规则）。 |
| `T.round({ F, s0, s1, r \| [r0, r1], ends = ["flat", "flat"], fixed })` | 圆柱或圆台；每端为 `"flat"`、`"dome"`（半径必须与侧面相等：即一个胶囊体）或 `"open"`。一端 dome 一端 flat 即半胶囊，长度任意，甚至可以短于半径（电机罐上的鼻锥）。直立组中的竖直 round 自动成为 `fixed` 图形（`fixed: false` 可阻止）。 |
| `T.lathe({ F, profile, slope, radius })` | 一般凸平滑体（r(s) 凹）。代价高；优先用 round。 |
| `T.ball({ c, r, flats: [{ n, d }] })` | 球体；每个平切面满足 n·(p − c) ≤ d，并把其边界画成一个帽，因此 `n` 是该平切面的外法向。没有平切面时它是 `fixed` 图形，且不接受 `details`。它是绘制代价最高的种类（第 15 节）。 |
| `T.tube({ route, r, chunk = 6, turn = 20, gaps, breaks, caps, rings, hue, material, bundle, owner, touch })` | kit `tubePieces` 语义的分段版本；`hue` 取 `"red" \| "green" \| "blue"`；记录 `R.route`。route 从安装面到安装面。每端的端口、密封套或夹箍是独立部件，`owner` 设为导管名，其沿 route 的跨度记入 `gaps`。从端口外表面起始的 route 在 kit 审计中过不了 `terminals`（见下）。 |
| `T.fixed({ svg, anchor, shapes, hull, F })` | 任何在组运动下画面不变的 kit 标记，用 `translate` 移动。 |
| `T.plane({ part, o, u, v, svg, fade = [0.04, 0.3], normal })` | 部件某平面内的线或文本标记（刻度、数字、标签牌），用一个矩阵放置，按朝向淡出。 |
| `T.billboard({ part, at, normal, svg, fade })` | 投影点处的屏幕对齐标记（着色器辉光的 SVG 后备），按朝向淡出。`svg` 以 viewBox 像素为单位、以投影点为中心，不是世界单位：世界尺寸要乘以 `G.scaleOf(P)`（`<circle r="${(1.1 * G.scaleOf(P)).toFixed(2)}"/>` 填满半径 1.1 的透镜）。 |
| `T.split(part, { n, d })` | 被平面切成两半的部件（prism：沿轴或横轴穿过它的任意平面；round：横切）。切口边不描边。用它打破真正的循环。 |

### 细节（在部件自身框架内：`s` 沿轴向，`x` 与 `y` 沿 `u` 与 `v`）
每个构造器有自己的框架，接受自己的细节种类。其余一律忽略，且不警告。

| 构造器 | 框架 `[s, x, y]` | 接受 |
|---|---|---|
| `T.round`, `T.lathe` | `F`：`s` 沿 `F.a`，`x` 沿 `F.u`，`y` 沿 `F.v` | `seams`, `ribs`, `bolts`, `dots`, `rings`, `rules` |
| `T.prism({ F, polygon })` | `F` | `dots`, `seams`, `bevel` |
| `T.prism({ plan, z, h })` | 世界坐标：`s` 即 z，`x` 与 `y` 即世界 x 与 y | `dots`, `seams`（z 值）, `bevel` |
| `T.ball` 带平切面 | 原点 `c`，`a` 取第一个平切面的 `n`，`u` 与 `v` 来自 `G.frameAlong(c, n)`。平切面在 `s = d`，远极在 `s = −r` | `bolts`, `dots`, `rings`, `rules` |
| `T.ball` 无平切面 | 无：一个 fixed 图形 | 无 |
| `T.fixed({ F })` | `F`（无 `F`：无细节） | `bolts`, `dots`, `rings`, `rules` |

带穹顶的转体 `T.ball({ c, r: 4.5, flats: [{ n: [-1, 0, 0], d: 0 }] })`（平切面朝 −x，穹顶朝 +x）上的中心圆点应放在 `at: [-4.5, 0, 0], normal: [1, 0, 0]`：`s = −r` 是极点。`[4.5, 0, 0]` 会落在平切面后 4.5 处，钻进转体所安装的物体内部。棱柱面上的圆环或刻度线请用 `T.plane`。
```js
details: {
  seams: [s…],                                              // rings on rounds, ring seams on prisms
  ribs: { s0, s1, count, phase, twist, fade: [0.1, 0.55], seams: true, tone },   // knurl rows on rounds
  bolts: [{ s, r, count, phase, size: 0.5, tone: "mid", fade: [0.04, 0.42] }],   // bolt circles
  dots: [{ at: [s, x, y], normal, size, tone }],
  rings: [{ at: [s, x, y], normal, r, tone }],              // become planes
  rules: [{ points: [[s, x, y]…], tone, free }],            // become planes
  bevel: 0.4…1.6,                                           // prism cap bevel (faded slots)
}
```
每种细节都随朝向淡出：圆点与螺栓按 `smoothstep(0.04, 0.42, n·V)`，rib 逐条淡出，bevel 线逐条边淡出，平面随组透明度淡出。任何纹理都不会以全强度戛然而止。

### 运行时（`kit/turn.mjs`，经 `turnScript()` 内联）
| 调用 | 作用 |
|---|---|
| `TURN.mount(stage, data, { onHold, onFrame, follow })` | 绑定 `stage` 中的每个动态层，渲染静止位姿，安装 `window.__isoTurn`。`follow(values)` 在每次 `set` 时把图形值映射为组值（一个输入驱动多个联动组）。`onFrame(controller)` 在每次渲染后运行（在此画着色器）。工具调用钩子时运行 `onHold()`。 |
| `controller.set(values \| θ, { detail })` | 设置组值（数字作用于第一个转组），同步渲染，返回统计。`detail`（0…1）缩放淡出线、rib 与圆点（第 15 节）。 |
| `controller.angleAt(clientX, clientY, z, group)` | 把指针换算成在高度 `z` 平面上绕该组 pivot 的连续展开角（拖动表盘）。 |
| `controller.pose(name)` | 该组的世界位姿 `{ R, t }`。 |
| `controller.detach(name)` | 让自由组在世界坐标系中延续当前位姿的 `{ world: true, R, t }` 值（无跳变）。 |
| `controller.anchor(group, restPoint, restDir?)` | 组的某个静止世界点（及方向）现在的位置：`{ world, screen, direction }`。用于火花源、火焰根部、LED 位置。 |
| `controller.cover(names, options)`, `order(layer)`, `orderIndex(layer)`, `events()`, `stats()`, `frames()`, `cams()`, `scene()`, `values`, `destroy()` | 遮罩（第 12 节）、绘制顺序、顺序变化事件、`{ ms, writes, moved, forced, refined, unseparated, emitted }`。 |
| `TURN.cover(controller, names \| [names, names…], { polygons = 6, edges = 10, pad = 0.3, layers })` | 为 `coverOf` 提供 `{ uCoverEdge, uCoverCount, dropped, parts }`。 |
| `TURN.poseUniforms(controller, group, prefix = "uGroup")` | 返回 `{ prefixX, prefixY, prefixZ, prefixT }`，使 `toGroup(p)` 得到该组的**静止世界**坐标。 |
| `TURN.materials`, `TURN.materialCss()` | 材质名称；单独的材质 CSS（已包含在 `TURN_CSS` 中）。 |
| `TURN.exact(on)` | 路径坐标不取整（6 位小数）地写出，而不是取整到 0.01 px。环绕审计为 continuity 行打开它；页面从不需要。 |
| `TURN.rotation(axis, degrees)`, `TURN.quat(q)`, `TURN.compose(A, B)` | 以数组表示的 3×3 旋转，用于自由位姿。 |
| `TURN.floorOf(scene, group, R)` | 组的部件在旋转 `R` 下（相对其原点）的最低 z：用于把部件平稳落地。 |
| `window.__isoTurn` | `{ controller, set, get, order, events, stats, layers }`；每次调用都会暂停图形（`onHold`）。`set` 接受数字或值对象。 |

## 5. 部件种类与保持其真实性的规则

这些是硬性规则；没有它们，构建和审计都会失败。
- **只用凸部件。** 阶梯表盘是分层圆盘；缺口轮是轮毂圆盘加轮缘扇形段；U 形支架是三个棱柱；手的外壳是板片。`T.prism` 检查自己的多边形，`T.lathe` 检查自己的轮廓。
- **接触要么齐平，要么相切，要么轮缘落在平切面上。** 球面上的轮缘无法分离：给球一个平切面（`T.ball({ flats })`），把轮缘落在上面。嵌入宿主的垫块不允许出现在动态层（`separation` 以 `interlock A × B −0.6` 失败）。
- **关节。** 两个连杆保持至少 0.2 的间距，关节由子组上的铰接圆盘衔接：与铰链轴同轴，并与父组的连杆接触（齐平或相切）。与自身铰链同轴的圆盘（或任何在自己的平面内转动的平面）在铰链下不变，因此永不碰撞，且正是 kit 审计所需的接触。子组中没有任何东西接触父组时，`rigid` 会把子组的每个部件报为 `support loose`。在关节相遇的连杆共用一个半径；穹顶中心与关节保持相同距离，使间隙在任意角度都成立（半径 r 的两个穹顶，中心距关节 c，只要 cos(β/2) ≥ r/c 就不会相碰）。叉架上的耳轴：
  ```js
  T.round({ name: "yaw.arm+", group: yaw, layer, F: VERT(0, 11.7), s0: 40, s1: 61, r: 1 });
  T.round({ name: "head.can", group: tilt, layer, F: frameOf([0, 0, 56], [1, 0, 0], [0, 0, 1]), s0: -12, s1: 8, r: 9 });
  T.round({ name: "head.trunnion+", group: tilt, layer, F: frameOf([0, 9, 56], [0, 1, 0], [0, 0, 1]), s0: 0, s1: 1.7, r: 4.5 });
  ```
  `tilt` 绕过 `[0, 0, 56]` 的 y 轴转动。罐体到达 y = 9，臂从 y = 10.7 开始，因此连杆间距 1.7。耳轴从 9 延伸到 10.7：它坐在罐体上，端面与臂相切。若把它截止到 10.5，与臂留 0.2 间隙，整个头部的 `rigid` 就会失败。
- **没有动态线跨过两个运动组。** 跨过屈曲关节的电缆或软管拆成两段 route，各自止于关节两侧的夹箍或端口；或在铰链轴处穿过旋转接头（banjo）。必须从静止地面够到转动部件的电缆沿轴上行，穿过轮毂处的滑环（第 11 节）。
- **导管要么近乎水平地弯，要么弯在接头件里。** 在与水平面倾角 θ 的平面内、朝向观察者的半径 R 弯管，在屏幕上是一个椭圆，最紧处半径为 R·sin²(e − θ)（世界单位；像素乘 `G.scaleOf(P)`）。`folds` 会判定屏幕上转角超过 90°、弯曲半径小于 2r 的弯管失败，`self` 判定小于 r 的失败。所以弯管需要 **R ≥ 2r / sin²(e − θmax)**，θmax 是平面自身倾角加上它所骑的每个铰链的俯仰范围（转组会把倾角扫过每个方位角，最坏情形总会转出来）。e = 30° 时：

  | θmax | 0° | 5° | 8° | 10° | 12° | 15° | 20° |
  |---|---|---|---|---|---|---|---|
  | R ≥ | 8r | 11r | 14r | 17r | 21r | 30r | 66r |

  8r 在水平面上就是界限本身，没有余量：取 10r。约 15° 以上没有实际可用的半径，所以要在接头件内弯（夹持块、banjo、弯头球、接线盒），或把线走直。弯管用 `G.fillet(points, R)` 画，绝不用依赖视角的圆角。审计的 `folds` 与 `self` 在每个角度、每个位姿下运行。
- **导管绝不指向视线方向。** e = 30° 时，导管的切线仰角在任何位姿下都不得落在 15°–45° 与 −45°–−15° 之间（`endon`）：在铰链链上还要检查连杆的俯仰范围（一根在屈曲 30° 的连杆上的电缆会失败）。
- **lathe 是唯一带有小残余台阶的种类**（≤ 2.5 tone·px²，出现在色带改变拓扑之处）。动态部件优先用 round、穹顶和带平切面的球。

## 6. 材质

部件的材质是构造器上的一个选项（`material: "gold"`）。色调仍与 kit 完全一样来自朝向；材质重映射色阶（四种明暗、顶面、纸面、外轮廓与线条色、圆点与管体、亮带与暗带），各自有一套亮色与暗色版本。

| 材质 | 外观 |
|---|---|
| `gold` | 香槟金阳极氧化铝：暖浅色顶面，青铜色阴影，深青铜外轮廓。 |
| `chrome` | 亮抛光钢：远端一条浅带，紧邻亮带与白色高光的是一条深反射带（n·L 0.2–0.42）。有意非单调：色带随朝向移动，绝不跳变。 |
| `steel` | 缎面钢，单调而冷。 |
| `gunmetal` | 带浅色圆点的深蓝灰金属。 |
| `rubber` | 带柔光的黑色橡胶与电缆护套。配合 `hue`，导管变成彩色护套（色相混入橡胶色阶）。 |
| `brass`, `copper` | 用于接头件、端口、阀门的暖色金属。 |

静态部件用与普通 class 相同的族：把 kit 标记包进 `<g data-mat="brass">…</g>`（示例中的刻度楔块）。规则放在 `TURN_CSS` 里；只有静态图的页面可以引入 `TURN.materialCss()`。浅色页面里的深色底板会选用暗色版本（`.iso[data-theme="dark"] [data-mat]` 排在最后）。

在浅色页面上，材质图形远比 kit 灰阶有力：地面（台面、底座、板件）保持 kit 色调，材质用在主体上，让它读作被打光、完工的实物。

## 7. 自由组：会脱落的部件

`T.group("pod", { parent: dial, free: { origin } })` 创建一个刚体，其位姿由图形每帧设定。静止时（`null`）它恰好停在构建时的位置，随附在原处：父组带着它。要让它脱落，开始设定相对父组的位姿即可：不会出现单帧突变，因为第一个值就是恒等。
- **落在转台上**：父组保持为转台组，碎块落地后随台转动。把飞行轨迹算成时间的纯函数（示例中的 `breakAt(t)`：绕质心的空翻、抛物线轨迹、用 `TURN.floorOf` 求出的平稳落地、衰减的滑动与偏航）。纯函数可以被构建和审计采样，也能倒放。
- **落出台外到工作台**：用 `controller.detach(name)` 切换到世界坐标，它返回延续当前位姿的 `{ world: true, R, t }`，再从那里积分。
- **顺序**：自由组的部件在运行时与本层每个部件配对（先按屏幕包围盒，再按每个相对位姿缓存的 GJK 平面）；组内配对是平面的。自由部件之间理论上可能出现循环；审计对剪辑采样并报告它们。
- **证明**：把剪辑交给构建，放进 `poses()`（脱落过程在若干转角下的每一帧），并给审计同样的剪辑（`clips`）。审计在每个剪辑帧摆放每个形状，检查与动态和静态部件的间隙（`posed`）、顺序、循环与连续性。

## 8. 铰链链：手与手指

每个连杆是一个铰链组，其父组是上一个连杆（`T.group("f0.j1", { parent: f0j0, hinge: { point: J1, axis: w, range } })`）。手腕是承载手掌的铰链；拇指根部是承载拇指链的铰链（竖直轴）。链条由一个图形值经 `follow` 驱动（`lift` → 三个角度）。
- 不同连杆上的部件对尽量在构建时求解：若一对部件在 `poses()` 扫过的体积上，在其共同祖先的框架中存在余量 ≥ 0.1 的平面，它就成为 **framed** 平面（运行时无需 GJK）。只有近关节的对保持动态（GJK，热启动，两组保持相对位姿期间缓存）。所以 `poses()` 必须覆盖运动：若手势超出采样范围，审计的 `unseparated` 行会点名该对（"framed plane: … add it to poses()"）。
- 保持范围符合物理且小：三连杆手指每关节 ±5° 已经读得出手的运动；每关节 20° 需要重新证明每条 route 和每个接触。
- **铰接连杆上的 route 带着连杆的俯仰范围。** 第 5 节的 `endon` 规则和弯管界限用的都是线能达到的倾角，而不是静止倾角：±12° 铰链上一个 R = 8.6r（在平面的 8r 规则之内）的水平 90° 弯，`folds` 和 `self` 都会失败，因为俯仰到 12° 时它需要 21r。让线直行进入接线盒，或把弯移到父组。

## 9. 画家序及其正确性

屏幕上可能重叠的每一对部件都确定一个关系：固定在共享组内的平面（planar）、固定在共同祖先框架内的平面（framed）、每帧一个 GJK 平面（dynamic，彼此相对运动的不同的组），或跳过（同一 route 相邻的分段）。在该框架内当 n·V > 0 时，B 在 A 前。顺序是以上一帧顺序为键的稳定 Kahn 排序；出现僵局时，丢弃屏幕精确包围盒分离（或在 0.1 px 内相触）的部件之间的边；剩下的僵局是一次强制抉择，被计数，并被审计判定为致命。

正确性：两个投影重叠的不相交凸体必然同时被某条视线穿过，而分离平面恰好穿过该视线一次。无闪烁：平面的关系只在平面侧对视线时翻转，此时两个投影落在一条线的两侧：交换它们不改变任何像素。侧对视线的关系（|n·V| < 1e-7）不产生边。

## 10. 着色与淡出

- 平面（棱柱侧面、端盖、球平切面）经过平滑阶梯使用 kit 的阈值（直立棱柱用 `EB`，其余用 `LB`）：面在阈值 ±0.035 之外保持 kit 色调，在 ±0.035 之内则每带 64 步交叉淡变（`data-q`，0…256）。这一细步让 chrome 的高对比色带保持平滑。
- **continuity 行测的是未取整的几何。** 页面把路径坐标取整到 0.01 px 写出，最多移动边 0.005 px，远低于设备像素。在取整路径上测量时，长边的取整台阶永不缩小，因此减半测试曾把大面积平面（示例中的手掌、台扇高 21 个单位的棱柱臂）误读成并不存在的跳变。所以 `orbit` 为 continuity 行把运行时切到精确坐标（`TURN.exact(true)`），测完再切回；转组上的大面积平面没有问题。
- 曲面始终用解析的等照度带（`labelledArcs`），绝不用分面。胶囊穹顶是嵌套的包络；带平切面的球是被裁切的帽。色带以零宽度诞生。
- 淡出线槽位存放 rib 与 bevel：alpha 量化到 1/32，槽数取构建的环绕扫描显示该组所需的数量。
- `lit: true` 使用 lit token；有材质时用材质的 lit 集。

## 11. 静态层与转台周围的杂乱车间

每个静态项都带 `layer`（`R.put({ …, layer: "back" })`），构建在所有可达状态上证明它与每个动态层的恒定关系，按第一条成立的规则：**水平平面**（项完全在层的 z 范围之下或之上）、**圆柱规则**（项沿视线的地面方向完全在转组扫掠圆柱之后或之前）、屏幕上**从不重叠**，或**扫掠包络平面**。否则：`static S interleaves live layer Λ: split S at z = …, or move it`。

密集车间的编写规则（`examples/turning-dial/stress.mjs` 证明了 450 个关系：工作台、转台底座、电源柜、工具架、电缆卷盘、托盘、扳手、三条台面电缆）：
- **杂物放在扫掠圆柱之外或转台平面之下。** 高物（电源柜、架子、灯）沿视线的地面方向（cos a, sin a）放在半径 R（动态层离轴的伸展范围）的圆柱之后或之前。在旁边、既不在后也不在前的物品必须矮。
- **低于转台最低动态 z 的任何东西都在动态层之后，即使它坐在台面靠前的位置。** 它应放进动态层之下的层（`back`），而不是 `front`：构建会这么说。
- **必须够到转动部件的电缆**沿台面走到静止底座，在底座内部上行，穿过轮毂处的滑环或旋转接头到达转动部件。静态段画到底座上的一个端口，动态电缆从转盘上的接线端子开始。任何 route 都不跨静止地面和转组。
- 静态电缆平躺在台面上（弯在台面平面内，R ≥ 8r），因此永不折弯，并终止在端口、卷盘或标记 `free` 的自由端上。搁在台面上的电缆（中心在台面顶 + r）会碰到台面，kit 的 `clearance` 检查会失败（`close stand.feed × stand.bench clearance 0.00 < 0.40`），除非 route 自己声明：`R.route(name, route, r, { owner: name, limp: true, touch: ["stand.bench"] })`。
- `stress.mjs` 是性能与分层证明场景，不是通过审计的场景：它的台面电缆没有 `touch`，它的手连杆松弛，kit 审计不通过。编写模式请照抄 `build.mjs`。

## 12. 跟随转动与各组的着色器

`kit/gl.mjs` 新增（均为可选加入；旧 fragment 看不到任何新东西）：
- `GLSL_TURN`：`uGroupX/Y/Z/T`、`toGroup(p)`、`toWorld(g)`、`dirToGroup(d)`、`dirToWorld(d)`，以及遮罩 `uCoverEdge[60]`、`uCoverCount[6]`、`coverOf(vb, soft)`。
- `glslPose(Name, prefix = "uName")`：为任意组提供同样的四个函数（`toDial`、`fromDial`、`dirToDial`、`dirFromDial`），让一个着色器可以跟随多个组。
- `glLayer` 把长度超过 4 的数组按声明的类型发送到 `vec2`/`vec3`/`vec4` uniform 数组（float 数组不变）。

着色器如何跟随运动：
1. **运动部件上的内容**（指尖上的 LED、断裂管线端口的火焰、管口喷出的油）：每帧用 `controller.anchor(group, restPoint, restDir)` 取锚点，把 `world`、`screen` 与 `direction` 作为 uniform 传入。画在**前景 canvas**（动态层之上），并用绘制顺序在其后的部件遮挡它：`const c = TURN.cover(controller, [partName]); layer.draw({ ...c, … })` 以及 `ink *= 1. - coverOf(vb, .7 * px)`。每个动态部件都是凸的，其包络就是精确轮廓；遮罩外扩 0.3 vb，使墨停在遮挡物的描边上，绝不进入其中。多个目标共享六边形遮罩：`TURN.cover(controller, [["hand.f2.p3"], ["hand.pod.socket"]])`。
2. **固定在转动表面上的内容**（转台上汇聚的油、表盘上被光照出的纹理）：传入 `TURN.poseUniforms(controller, "dial", "uDial")`，在静止世界坐标下求值：`vec3 q = toDial(onFloor(vb, FACE_Z));` 油池随表盘转动。
3. **世界空间中的内容**（升起的烟、离开源之后的火花、转台之外汇聚在台面的油）：绝不触碰组变换。粒子出生时从锚点的世界位置发射，在世界空间中积分（示例中的火花）：转动不会拖着它们走。
4. **背景 canvas**（光落在被上方部件覆盖的表面上）：把 canvas 放在两个动态层之间。示例把表盘拆成独立的动态层 `dial`，位于 `hand` 之下，于是 LED 的光池落在表盘面上，手直接盖住它，完全不需要遮罩。

`webgl.md` 的每条规则仍然成立：包络、在任何边界之前归零的窗口、浅色主题墨水（饱和主体、浅色核心、着色地面，墨只随光增长）、抖动、canvas 边缘为 0、SVG 后备（`T.billboard` 放在所属部件内，隐藏于 `[data-gl]` 之下，用 `(1 − u)/(1 − u·α)` 交接）。遮罩块用 70 个 uniform 向量：读取 `MAX_FRAGMENT_UNIFORM_VECTORS`，把 SVG 后备保持在 128 以下。`GLSL_TURN` 已定义 `toWorld`：不要再把它前置到自行定义了这一函数的 fragment 里。

## 13. 环绕审计

`node build.mjs --audit` 先跑 kit 审计，再跑 `TA.orbitOrExit(T, R, P, options)`，后者每项检查打印一行，最后以 `turn audit passed` 或 `turn audit failed: n problems` 结束（退出码 1）。只有完整运行才以 `turn audit passed` 结束：带 `only` 的运行以 `turn audit partial: no problems in what ran (n lines skipped by only)` 结束，快速运行以 `turn audit quick: no problems in what ran (quick run, undersampled: the full run is the proof)` 结束。

选项：`sweep: { at(x), from, to, frame }`（转角）、`clips: [{ name, at(t), from, to, frame }]`（手势、脱落：60 fps 逐帧）、`poses`（额外状态）、`crowd: [[route, part]…]`（豁免 `crowding` 的对，前提是你已看过）、`cover`、`fittings: [[route, from, to]]`（接头件内的段，豁免 `endon`）、`quick`（约 1/10 状态，用于迭代）、`only: ["order", "rigid", "swept", "posed", "routes", "coverage", "continuity", "depth"]`（未知名字会抛错）、`log`。示例接受 `--quick`、`--only=a,b` 和 `--verbose`。`only` 运行这些行：`order` → `unseparated`、`cycles`、`forced`、`swaps`；`routes` → `folds`、`self`、`crowding`、`endon`；`depth` → `depth`、`layers`；其余各运行自己的行。`separation` 始终运行。未运行的行打印 `skipped`。

**耗时与迭代方法。** 环绕审计很慢，耗时随部件数 × 状态数增长。在 28 部件的台扇上测量（一个转组、一个铰链、一个剪辑）：`--quick` 85 秒，完整 17 分钟。示例场景需数分钟；完整运行按每个部件约 30–40 秒预算。这超出 10 分钟的 shell 超时，所以：
1. 用 `--quick --only=…` 只跑你正在修的行来迭代。
2. 最终运行之前先单独跑一次 `--quick`。它欠采样：二分候选只查 100 个，而完整运行查 800 个，漏掉了完整运行发现的 20 处 `continuity` 失败。
3. 最终完整运行放后台（`node build.mjs --audit > audit.txt 2>&1 &`），结束后读取。只有该次运行的 `turn audit passed` 算数。

| 行 | 失败情形 | 修法 |
|---|---|---|
| `separation` | 同组内一对部件没有平面（余量 < −0.08） | 拆分、加平切面，或改齐平接触 |
| `unseparated` | 跨组一对部件在其包围盒重叠时互相穿入；某个状态破坏了 framed 平面 | 修接触或修运动；把运动加进 `poses()` |
| `cycles` | 某状态下重叠部件间出现循环；打印部件、状态范围和分离平面（余量最大的循环边） | 用 `T.split` 在该平面切分该部件 |
| `forced` | 运行时不得不强制抉择 | 同 cycles |
| `swaps` | 两个重叠部件在重叠超过 0.25 px² 时互换顺序（构建为齐平的对是 0.5 px²，余量小于 0.05：接触平面侧对的瞬间，真实重叠是一条线，画出的曲线留下约 0.1 px 宽的细缝） | 先看：`drive.mjs page.html '[["orbit", "swap.png", θ−0.3, θ+0.2, 0.1, null, 6, [x, y, w, h]]]'`（θ 取自该行；围绕该对的区域，以底板的 CSS 像素计，放大 6 倍）。一步之内出现或消失的东西是绘图 bug，不是顺序 bug。2026-10-06 之前的引擎把一端 `"dome"` 且短于半径的 round 在其平端之后画出一个楔形，当该端侧对时会消失：复制当前 `turn.mjs`。两侧顺序（`__isoTurn.order`）都正常下的干净互换是平面选错：连同部件对与 θ 一起上报 |
| `layers` | 静态项在某个动态部件的错误一侧（射线投射） | 移动或拆分（第 11 节） |
| `rigid` | kit 间隙、terminals、支撑、静止时的实体间隙 | 同 kit 审计。铰链组每个部件都 `support loose`：组内没有东西接触父组（铰接圆盘，第 5 节）。`terminal … from X`：route 从端口表面起步，而不是从安装面（`T.tube` 行，第 4 节）。`clearance … × stand.bench`：台面电缆没有 `touch`（第 11 节） |
| `swept` | 静态形状在转组的扫掠包络之内 | 把它移出圆柱 |
| `posed` | 不同组的形状（以及动态 × 静态的运动）在任一采样状态互相穿过 | 运动或几何 |
| `folds`, `self`, `endon` | 动态 route 在每个角度和每个位姿状态 | 第 5 节（弯管半径要加上俯仰范围，第 8 节） |
| `crowding` | 动态 route 的端点或弯管在某个角度落在细长实体的轮廓上（杆、立柱、轴颈） | 与转动杆平行的线无论偏移多少，总会在某个角度穿过杆的外轮廓，无法从设计上消除。看它点名的角度（`["turn", θ]` 与一张 4× 截图），若读作两个独立部件，把该对列入 `crowd: [["cable.a", "yaw.stem"]]`，或把线走进杆内部。不平行的线：从杆的侧面横向接近 |
| `coverage` | 部件记录的形状覆盖其绘制 < 60% | 记录真实形状 |
| `depth` | 射线投射判据与引擎顺序不一致 | 上报 |
| `continuity` | 每 0.05°：色调步 > 1/16 带、新生 > 2 px²、圆点 α 步 > 0.01、淡出 α 步 > 1/32 + 0.005、轮廓移动超过 1.5·ω·Δθ + 0.05 px；以及减半测试 | 戛然而止的细节：让它淡出。轮廓或面边界一步跳变的部件：用 0.1° 的环绕图找出角度；在普通 kit 基元上这是引擎 bug，连同部件与 θ 上报。`--quick` 欠采样：只有完整运行算数 |

减半测试以 ½、¼、⅛ 尺度重发每个候选台阶，使用精确坐标，以 4× 光栅化各帧（8 条子扫描线上抖动采样），测量改变归属的像素并按色调加权。平滑的变化随台阶减半；跳变不会。当某台阶在每次减半后保持在 60% 以上、且在 ⅛ 时仍 ≥ 2 tone·px²，它就是一次不连续；测量在 4× 进行，再在 16× 复测：4× 失败的台阶只有在 16× 也失败时才算失败。若改在页面的取整路径上测量，每条长边都保有约其长度 × 0.01 px 且永不缩小的下限；切到精确坐标之前，正是这个下限把大面积平面误报。每一行都有一个会令它失败的植入故障（构建会话中的 `3d/engine/plants.mjs`：下沉的垫块、三根倾斜短棍的风车、竖直平面内的纤维弯管、30° 的导管、停止的 rib 行）。

## 14. 浏览器检查

```sh
node examples/turning-dial/build.mjs --light --verify           # writes turning-dial-verify-light.html
node scripts/turn-check.mjs examples/turning-dial/build.mjs --fidelity
node scripts/turn-check.mjs page-verify.html --order --step 1
node scripts/turn-check.mjs page-verify.html --order --states clip.json
node scripts/turn-check.mjs page.html --pops --no-webgl --step 1 --out shots/pops
node scripts/turn-check.mjs page.html --lines                    # and the dark page
node scripts/turn-check.mjs page.html --perf --width 1440
node scripts/turn-check.mjs page.html --perf --width 390 --throttle 4
node scripts/turn-bench.mjs examples/turning-dial/build.mjs
node scripts/drive.mjs page.html '[["turn", 37], ["shot", "a.png"], ["orbit", "orbit.png", 0, 345, 15]]'
```
- `--fidelity`（Node）：prism 对照 `k.extrude`/`G.prismOf`（外轮廓、顶面与各面均 ≤ 0.06 px），round 与 lathe 对照 `G.lathe(…, smooth)`（对照以 10× 绘制的 kit，外轮廓 ≤ 0.05 px，色带 ≤ 0.5 px；该行还会打印对照 kit 自身路径的外轮廓，那些路径取整到 0.1 px，因此那里的 0.08–0.13 px 属预期，不判罚），tube 对照 `tubePieces`（0.05 px），均在 P′(θ) 处。对照组：故意画偏 2° 的一个 prism 必须失败。
- `--order`：把记录的形状放进 WebGL z-buffer，与 DOM 画家的填充对照，2×；动态对若有 4 个以上内部像素则失败。对照组：把每个动态层反过来必须给出 ≥ 1000 px。静态 × 动态的不匹配会被列出（静态记录形状常是替身，例如用一块平板代表带窗的板件）。`--part name` 打印某部件在两张图中的足迹。`--step` 只扫掠**第一个转组**，其余组保持静止：铰链、slide 或剪辑需要 `--states`。
- `--pops`：一阶差分（θ → θ + 0.02°，两次腐蚀）与二阶差分（0.1°，|2b − a − c| > 56，或在平坦像素上 > 6，一次腐蚀；6 px 的核心即失败）。对照组：把最大的部件隐藏一帧。`--out dir` 保存首个核心的帧。使用 `--states` 时，相邻条目被当作相邻帧，只跑一阶差分，所以列表必须是**以约 0.02° 步长的一条连续路径**：529 个互不相关的 yaw × tilt 位姿给出 404 个假失败；0.02° 步长的 1201 个状态 tilt 扫掠给出 0。
- `--states file.json`：一列值对象，取代角度。从构建模块写出，它导出 `follow` 和剪辑函数：
  ```js
  import { writeFileSync } from "node:fs";
  import { follow, nodAt } from "./build.mjs";
  const at = (t) => follow({ yaw: 20 + 30 * t, tilt: nodAt(t) });
  writeFileSync("clip.json", JSON.stringify(Array.from({ length: 241 }, (_, i) => at(i / 60))));
  writeFileSync("tilt-path.json", JSON.stringify(Array.from({ length: 1201 }, (_, i) => follow({ yaw: 30, tilt: -12 + i * 0.02 }))));
  ```
  `clip.json`（剪辑的每个 60 fps 帧）用于 `--order`；`tilt-path.json`（以 0.02° 扫掠的一个铰链）用于 `--pops`。`--pops` 每个铰链跑一条路径，选在铰链部件重叠最大的转角处。

## 15. 性能

由 `turn-bench`（Node CPU）与 `turn-check --perf`（浏览器，1.1° 步长 240 帧）测量。

**一个部件值多少钱。** `turn-bench` 按种类打印每个部件的 Node 耗时。以 prism 单位计（一个动态 prism 在构建机上约每帧 0.03–0.04 ms）：

| 种类 | 代价 | 种类 | 代价 |
|---|---|---|---|
| `fixed`（竖直 round、普通球） | 0.5 | `round` | 2.5–4 |
| `prism` | 1 | `ball` 带平切面 | 8–10 |
| tube 分段 | 2–3 | `lathe` | 约 25 |

图形的重量是总和。**小型图形**重量约 50 以内（几十个部件，多为 prism 和 fixed 图形）；**密集**图形约 230 以内。台扇（28 部件：6 prism、7 fixed、5 个 tube 分段、8 round、2 个带平切面的球）重约 65，测得每帧 1.6–1.9 ms Node CPU，1440 下浏览器任务 6.0 ms，因此超出了小型图形线，主要因为那两个球。转盘表盘（88 部件、42 round、一个 lathe）重约 225，测得 6.4–7.2 ms。带平切面的球是带轮缘落点的穹顶端部的正确部件（第 5 节），但代价相当于九个 prism；普通球或竖直 round 是 fixed 图形，几乎免费。耗时因机器和负载而异：在同一次运行内比较种类，并测量你自己的图形。

| 指标 | 小型图形预算（重量 ≤ 50） | 密集图形预算（重量 ≤ 230） |
|---|---|---|
| 每帧 Node CPU | ≤ 2 ms | ≤ 7 ms |
| 1440、DPR 2 下的浏览器主线程任务 | ≤ 6 ms | ≤ 13 ms（60 fps） |
| 390、DPR 3、4× CPU 降速下的主线程 | ≤ 16 ms | ≤ 33 ms（30 fps） |
| `data.turn` JSON | | ≤ 250 KB |

杠杆，按顺序：
1. 每个竖轴回转部件和每个普通球都用 `fixed`（自动）。
2. 面上的每一组线或文本都用 plane；直立棱柱顶面是一个矩阵。
3. 小部件按设备像素采样：小于 30 px 的部件，其圆环、端盖与穹顶取 12–16 个采样，绝不用大部件的最低值。
4. **framed 平面与相对位姿缓存**（自动）：组保持相对位姿时（纯转台转动），跨组对零开销；构建采样过其运动的对是 framed 平面。
5. **自适应半帧率**（图形的循环）：维护 `controller.set(...)` 耗时的指数移动平均；超过 14 ms 时隔帧渲染动态层（基于时间的运动不变），低于 9 ms 时恢复每帧（`stress.mjs` 的循环）。
6. **按速度调整细节**（可选加入）：`controller.set(values, { detail })`，`detail = settle(1 − smoothstep(120, 240, |ω|°/s), 0.25 s)`：淡出线、rib 与圆点随之缩放，低于 0.01 时跳过。外轮廓与色调绝不降级。

把图形保持在预算内的编写规则：每个运动组约 150–250 个动态部件；小细节用 `details`（圆点、圆环、螺栓）而不是部件；静态杂物用静态图；每个独立运动区域一个动态层；tube 按 6 分段，在弯管允许下分段越少越好。示例与压力场景的实测数字在该 Skill 的构建笔记里；本机上 380 部件的屈曲手借助半帧率杠杆是 1440 下 30 fps 的图形，不是 60 fps。

## 16. 已知限制

- 竖直转轴走方位角捷径；其他旋转用矩阵合成。
- 只有凸部件。凹体拆成凸块；球平切面取代轮缘落球面的关节。
- 动态导管遵守折弯与端向规则：没有扫掠管轮廓，因此转弯要么近乎水平要么在接头件内进行，且没有 route 跨两个运动组。
- 无自动拆分：循环是一次带建议平面的审计失败。
- 平面在评分 ±0.035 内交叉淡变（约 8° 的转角）。
- lathe 在色带改变拓扑之处保留小残余台阶。
- 自由组在运行时与整层配对；几十个碎块在运动期间持续付出 GJK。
- 手机：预算瞄准 30 fps 而非 60，只有预算内的图形能达到。380 部件的压力场景（`examples/turning-dial/stress.mjs`）在一台高负载机器上、带半帧率杠杆时，1440 下测得约 20 fps，390 加 4× CPU 降速测得 13–15 fps。没有 canvas 绘制器。
