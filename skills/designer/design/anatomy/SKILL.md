# Anatomy

本 Skill 生成的图形如同工作台上的一台小型仪器：带支脚的厚重底座、带刻度尺的导轨、装在轴套上的滑座、滚花旋钮、螺旋弹簧、指针会动的百分表、化作小点的螺丝。读者之所以能理解概念，是因为他们认得这台机器。图中显示的每一个数字，都来自驱动其部件运动的同一个模型。

本 Skill 随附八个完整示例。开始之前，先打开与任务最接近的一个。每个无框架示例都用 `node examples/<name>/build.mjs` 构建，它会在脚本旁边生成一个独立的 HTML 页面；加 `--light` 可切换浅色主题。

- `examples/dial-indicator/` 是最小的示例：支架上的一个百分表，总共约 300 行。
- `examples/desk-computer/` 是无框架 SVG：一台可以敲键盘的桌面电脑。敲入的一行字显示在与机箱正面同一平面内绘制的 CRT 屏幕上，关机时画面塌缩成一条线和一个点。它约有 85 个实体和 850 条路径。
- `examples/arcade-cabinet/` 是一台拆掉侧板的立式街机机柜，是一个 Hero 级示例，约 240 个实体和 15 条线缆。一枚 25 美分硬币飞入投币口，以圆盘在 30° 斜面上滚动所能达到的速度滚下投币滑道，碰动投币开关的金属线后落入钱箱；开关的脉冲沿电缆一段一段地传到主板，CRT 预热、自检，然后在倾斜显示器的平面内运行 attract mode（吸引演示）。摇杆倾斜并压合面板下方的微动开关。它演示了：如何放置相机让剖视图的机构始终留在画面内；如何把凹形板沿任意轴画成棱柱；如何在页面中用与构建脚本相同的模块重建运动部件；以及如何在 settle 定序后的预留槽位里绘制活动的硬币与线缆。`node build.mjs --audit` 证明几何正确。
- `examples/raptor-engine/` 是悬挂在试车台上的火箭发动机。它的圆形部件来自 `kit/lathe.mjs`，管路与线束来自 `kit/tube.mjs`。它可拆解为 11 个组件，带错列排布的弹簧和逐帧深度重排。每个部件都记录其真实形状，`node build.mjs --audit`（`kit/audit.mjs`）在静止、拆开状态以及爆炸图的每个回放帧中证明：没有任何东西穿过任何东西、每个端点都落在真实安装座上、没有任何弯头收窄成尖角、折叠或落到另一条线上、没有曲面轮廓的斜率出现抖动，且每处重叠都按深度顺序绘制。WebGL 羽流、激波、水花与蒸汽渲染在前后两层 SVG 之间。它是密集管路、平滑着色与淡出效果的参考。
- `examples/ripple-tank/` 是一架装在高腿上、架在纸屏上方的教学波动水槽，从上方 44° 俯视。两个 WebGL 图层（纸面上的灯光、阴影与焦散，以及水面的反射与玻璃）注册对齐到等距平面，由一个纯粹的色散与光学模型（`model.mjs`）驱动；频率变化从振子出发，经一张历史纹理向外传播。
- `examples/test-rig/` 是来自真实站点的正式成品图（React/Next）：弹簧支承滑座上的一枚玻璃按钮、导轨上一个会按压并回拉的指形探针，以及读出倾斜量的百分表。它有 53 个实体、约 470 条路径。
- `examples/spot-plate/` 是同一站点的另一张正式成品图：点滴板上的六对玻璃液滴，每对都由同一个距离场绘制，因此间距小于 `merge` 的一对会融成一块玻璃。一排扇形展开的塞尺设定 `merge`，每个间隙一片塞尺。它是形状相互形变融合、以及单一控件驱动多个部件的参考。
- `examples/turning-dial/` 是可选的 3D 模式：一个在真实 3D 中转动的密码拨盘，上面有一只小型机械手。它约有 90 个金属材质的活动部件、第二个 turn 组、一个铰链、一根带三个铰链且会抬起的手指，以及一个作为自由体崩脱的小端罩。WebGL LED、它的光斑和火花跟随运动部件。它旁边的 `stress.mjs` 是杂乱车间中一只约 380 个部件的密集机械手，用于测量性能。

test-rig 是图形绘制本身的质量标杆。Raptor 是着色器工作的标杆：WebGL 效果必须达到它的标准——世界空间、无跳变、无缝渲染。

## 唯一重要的思想

**物件即解释。** 不要画方框、箭头和标签。去发明一件真实、做工精良的实物，它的运转本身就是概念。以下是此前一些图形的对应关系：

| 概念 | 物件 |
|---|---|
| 一个 GPU 上下文服务多个画布 | 一台龙门绘图仪：一个打印头巡视 16 个井位 |
| 一个在无变化时跳过工作的缓存键 | 一把弹子锁：所有弹子都对上时，锁芯转动，无需重绘任何东西 |
| 七个每 texel 字节数不同的渲染目标 | 一个七斗柜，每斗的深度对应其字节数 |
| 可分离模糊（49 × 49 次采样 vs 49 + 49） | 导轨上两把梳子旁的一枚钉床印章 |
| 一个既按压又倾斜的弹簧 | 一台带弹簧、探针和百分表的测试台 |
| 一个高度轮廓 | 紧贴边缘按压的轮廓（取形）规 |
| 依赖朝向的光照 | 一间小型摄影棚：转台四周的主灯与补光灯 |

这种做法有两种常见的失败，都在实践中见过：

- **太抽象。** 叠放的板子、悬空的厚块或贴了标签的方框，让人看不出任何东西。
- **太平淡。** 一大块板加几条线，没有体积、没有部件、无可发现之物。

两者的解法相同：一台由许多细小、精确、各有用途的部件组成的、一眼可辨认的机器。

**每件作品都必须高度精细。** 无论概念或需求多小，这条对每个图形都成立：即使是一个快速解释图，也要是一台稠密、真实的机器，绝不能只是几块板。随尺寸（工作流第 1 步）变化的是你推进的深度：Figure 级要对主体和机构做 4× 扫描，Hero 或 Epic 级则要对整幅图做 4× 扫描。
- **研读实物。** 按真实物件的建造方式来构建：每一颗螺丝、每道接缝、每个倒角、每个轴套、每块铭牌、每根带接头的线缆、每条带刻度的标尺，以及固定部件的部件。
- **两种观看。** 在 1× 下它读起来是一台清晰完整的机器；在 4× 下每个区域仍有真实的东西可发现。光秃的面或空荡的角落是未完成的工作，而不是留白。
- **有目的，绝非噪点。** 细节来自属于机构的部件。每个部件都坐落在另一部件之上、终止于某条边，且以淡出收尾而非戛然而止。
- **最后检查。** 完成前放大到 4×（Figure 级看主体和机构，Hero 或 Epic 级看整幅图），凡是区域显得空平之处，补上缺失的真实部件。

## 工作流

按此顺序工作。在任何几何构建之前，先写出概念和部件清单。大部分质量在那里就已注定。

1. **动手前先定档位。** 在做任何其他工作之前先报出档位；当下面的档位要求给出估时时，向用户大致说明需要多长时间。
   - **Figure**：单个机构，40–80 个部件，SVG 至多带一个 WebGL 图层。报出档位后直接构建，无需再询问。不要向用户报时间，因为 Figure 通常远不到一小时就能完成。就下面的进度检查而言，预算上限为一小时。
   - **Hero**：一个稠密物件、多个 WebGL 图层或一个 3D 主体，80–150 个部件。约 2–4 小时。说明所需时间，然后开始构建，除非用户要的是快速小图。
   - **Epic**：一整辆车、建筑或带众多运动系统的厂区，或对多个主体启用 3D 模式。6 小时以上。不要直接开工。给出估时，提出一个保留概念核心的 Hero 版本，并列出完整版会多做什么。只有用户明确选择 Epic 时才构建。
   - 无论档位大小，第一小时内就要有一个能在浏览器打开的可用页面，然后在此基础上深化。开始时和每一步都运行 `date`；当某一步的耗时超过其估时份额的两倍时，告诉用户进展到哪、还剩什么。
2. **真实优先。** 收集被解释对象的真实数字和行为：尺寸、数量、阈值、曲线。读数、运动和说明文字都必须真实。如果可以，把模型写成一个小型纯模块（如 test-rig 示例中的 `rig.ts`），并由它驱动一切。
3. **发明物件。** 挑一台机构能与概念一一对应的机器、工具、仪器或家具。用一句话说清什么在动、这个运动意味着什么。绝不要照抄参考图：借鉴它的质感，而不是它的物件。
4. **部件清单。** 写出至少 40 个部件（Figure 40–80 个，Hero 80–150 个，Epic 更多），分组：底座（板、支脚、凹槽、角部螺丝、铭牌、标尺条）、结构（立柱、导轨、框架杆、限位块）、机构（滑座、轴套、弹簧、柱塞、指针）、控制件（滚花旋钮、指拧螺钉、表冠）以及主体本身——它是唯一被点亮的部分。每个部件都坐落在另一部件上。`references/craft.md` 提供带配方的部件词汇表。
5. **规划世界。** 使用约等于实物 1 px 的世界单位：x、y 在地面上，z 向上。平面布局用圆角矩形 `{x, y, w, d, r}` 和圆形来画。选相机：方位角默认 45°，需要展示长边时用 35–60°，仰角 30°（想看进某个开口内部时更高，如 ripple-tank 的 44°）。然后用 `fitProjection(points, width, height, { pad, azimuth })` 适配取景。
6. **几何只构建一次。** 用 kit 在几何模块中预计算每条静态路径：`slabOf`、`cylinder`、`extrude`、`planOutline`、`topTicks`、`knurl`、`coil`、`radialTicks` 等。任意轴向上的圆形部件（钟形罩、法兰、阀门、执行器）来自 `kit/lathe.mjs`，管路和线缆来自 `kit/tube.mjs`。运动部件在静止位置一次性构建，用 `translateAlong` 移动。只有形状会改变的部件才逐帧重建。
7. **从后往前、自下而上地绘制。** 用 `depthOf` 排序重复部件。把任何包裹另一部件的东西拆成后半和前半：围绕杆的弹簧、围绕滑座的框架杆。运动部件绘制在它物理上所处的槽位。参见 `references/craft.md` 的 “Painter's order”（画家排序）一节。一旦图形中有管路、线缆和圆形部件，就别再靠眼睛调 key：把每件物品放入 `A.recorder(P, { order, spring })` 时记录其形状，让 `A.settle(R, P)` 在任意两件物品重叠处测量真实深度并设定 key，最后以 `A.auditOrExit(R, P)` 结束构建。画管路之前先布线路：两端为真实端口，支腿沿结构走，交叉选在直线段，套环处为管子留缺口（`references/craft.md` 第 8 节）。记录所画内容的真实形状：用替身形状让审计静默通过本身就是 bug，审计也会把替身判为失败。从密封套（gland）中滑出的杆应是 `G.rodOut` 生成的一整根杆，并用 `A.slide` 记录。
8. **加框。** 把图形放进卡片：左上角 `Fig n`，右上角短标题，左下角交互提示，右下角实时读数。图例（legend keys）和真实的说明文字放在卡片下方；除最多一个微小的蚀刻标签外，图形内不出现文字。
9. **让它活起来。** 使用从容的基于时间的运动：指数跟随或真实弹簧。无人触碰时，空闲导览循环播放。图形响应指针与键盘，离开屏幕时停止，在 reduced motion（减少动态）下保持静止。在 ref 上写属性，不要逐帧重新渲染。参见 `references/motion.md`。
10. **像评审一样验证。** 收图的人会放大找毛病，所以你要先放大。逐一查看自己生成的每张 PNG。
   - 用 `scripts/capture.mjs` 截取桌面、手机（宽 390）、悬停以及运动的多个瞬间；序列、拆开姿态和 `--no-webgl` 回退用 `scripts/drive.mjs`。
   - **把审计清零。** 有管路、线缆或圆形部件时，`node build.mjs --audit` 必须以 `audit passed` 结束，每一项失败计数为 0：静止、拆开与飞行途中的间隙、端接、松散端头、折叠、自重叠、拥挤（对细长实体同样检查）、替身形状、支撑、抖动、鞍座与深度顺序。修几何层面的互锁问题，绝不要用 key 偏置来修。
   - **把线条检查清零。** 审计看不到线条标记。`node scripts/lines.mjs page.html --out shots/lines.png`（在 `-light` 页面上、以及用 `drive.mjs` 的 `["lines"]` 动作在每个静止姿态下）必须输出 `line ends: 0`：每条接缝、刻线、棱筋、刻度和指针都终止于描边、圆点或轮廓上。查看圈出失败处的 PNG。
   - **两个主题下每个接合处的 4× 特写**（也要构建 `--light` 版本），组装态与拆开态都要：每个法兰、三通、弯头、卡箍、阀门、波纹管、箍带、鞍座、球接头和交叉点，每个曲面体（不得有色调阶梯），每个纹理终止处（终止于边上或渐隐），带接缝的平整箱面，每根带纹理软管的分块接缝处，每根滑动杆的静止与满行程位置，以及每个含文字或着色器内容的窗口。
   - **着色器：** 用 `["slow", 0.05]` 放慢速度，截取覆盖每个过渡的联络表（contact sheet）；不得有任何跳变、不得有颜色突变、边缘读数为 0。浅色主题下，还要在每个过渡中逐帧记录墨量（ink），它必须随光照单调变化；并在 8–16× 放大裁剪墨量与描边相交处（`references/verify.md` 的 “Light-theme shaders” 一节）。
   - 把你的 PNG 放到示例旁边自问：它是否一眼看上去就是真实物件，富含有体积的小部件，且每条线都终止在某物上？在 1× 下是否高度精细、在 4× 下仍有可看之处，且没有光秃的面或空荡的角落？迭代直到答案是肯定的。检查清单：`references/verify.md`。

## 组件（Setup）

kit 位于 `kit/` 目录：

| 文件 | 用途 |
|---|---|
| `kit/iso-kit.ts` | 完整核心集于一个文件：相机、实体、部件库、SVG 字符串渲染器、卡片与页面构建器，以及 CSS（`ISO_CSS`）。复制到 TypeScript 项目中使用。 |
| `kit/iso-kit.mjs` | 同一核心编译为纯 ESM，供 Node 脚本使用。直接 import 即可。 |
| `kit/iso.css` | 展开写出的 `ISO_CSS`。import 一次，并在包装元素或 `<body>` 上放 `class="iso"`（浅色主题再加 `data-theme="light"`）。 |
| `kit/react/draw.tsx` | 服务端安全的 React 组件：`Solid`、`Line`、`Wire`、`Dots`、`FaceText`、`IsoFigure`、`Plate`。 |
| `kit/react/live.tsx` | `"use client"` 钩子：`useReadout`、`useLoop`、`useEased`、`useInView`、`useStillness`，外加 `spring` 和 `follow`。 |
| `kit/lathe.mjs` | 任意轴向的圆形部件：`frameAlong`、`lathe`（轮廓带平滑节点时自动开启平滑着色）、`solidOf`、`disc`、`ringBand`、`sphereOf`、`saddleOf`、`bandsOf`（把一个曲面体切成可深度排序、共享同一表面的条带，轮廓由 `sidesOf` 生成）、曲面上的可见弧线、棱筋与螺栓圆（`ribsOf` 与 `dotsOf` 接受 `fade`，`ribsOf` 接受 `seams`）、用于从密封套滑出的杆的 `rodOut`，以及用于管路倒圆的 `fillet`。 |
| `kit/tube.mjs` | `tubePieces` 把 3D 管或线缆切成可深度排序的分块（带 `breaks`、套环与卡箍下的 `gaps`、椭圆端盖，以及让编织、波纹或包覆跟随横截面穿过每个接缝的 `rings`），`tubeSvg` 绘制其中一个分块；`crossingsOf` 找出线路穿过卡箍的位置，`runsOf` 找出实际绘制的走线段。它的 `.tb-*` 填充色在 `ISO_CSS` 中。 |
| `kit/audit.mjs` | 证明几何正确。`recorder(P, { order, spring })` 在各辅助函数绘制时收集物品、形状（回转体、板、棱柱、箱体、球、管、被宿主切割的垫块）与线路；`settle(R, P)` 对每一对重叠物品做射线投射以测得真实深度——静止、拆开与回放的爆炸帧中都要——并设定画家排序的 key（`overlapsOf`、`orderKeys`）；`auditOrExit(R, P)` 是 `--audit` 钩子，运行全部检查（`clearances`、`solidClearances`、`terminals`、`looseEnds`、`supports`、`folds`、`selfOverlaps`、以细长实体为线的 `crowding`、针对替身形状的 `coverage`、`wobble`、`seats`、`depthOrder`），任何问题都以非零码退出。`A.slide` 记录从密封套滑出的杆。见 `references/kit.md` 第 12 节。 |
| `kit/gl.mjs` | 图形内部着色器用的 WebGL 图层：`GLSL_ISO`（GLSL 中的相机，含 `rayOf` 与 `pixelOf`）、`glCamera(P)`、`glLayer(...)`，以及 JS 包络 `smooth`、`burst` 和 `settle`。对 3D 图形，`GLSL_TURN` 与 `glslPose(name)` 把世界坐标点带入运动组，并用 `coverOf` 遮罩前层画布。 |
| `kit/turn.mjs`、`kit/turn-build.mjs`、`kit/turn-audit.mjs` | 可选的 3D 模式。`turn-build.mjs` 提供 `turning(P, { recorder })`：分组（turn、slide、hinge、free）、活动图层、带材质的凸部件，以及 `T.build`。`turn.mjs` 是运行时：`TURN.mount`、控制器、`TURN.cover`、`TURN.poseUniforms` 与 `TURN_CSS`。`turn-audit.mjs` 提供 `orbitOrExit`，即覆盖每个转角与每个动作片段的环绕审计。见 `references/3d.md`。 |
| `scripts/capture.mjs` | 无头 Chrome 截图、特写与控制台检查，开启 WebGL。用 `node` 运行。 |
| `scripts/drive.mjs` | 带脚本的无头 Chrome（含 WebGL）：移动、点击、按键、慢动作、wait-until、eval、截图，以及能捕捉跳变的联络表；支持 `--no-webgl` 和 `--preload`。 |
| `scripts/lines.mjs` | 在无头 Chrome 中对构建出的页面做线端检查：每条纹理线必须终止于描边、圆点或轮廓。用 `--out` 把失败处圈出来；有任何失败即以 1 退出。 |
| `scripts/inline-kit.mjs` | `kitScript()`、`glScript()` 和 `turnScript()` 把 kit、WebGL 图层和 3D 运行时作为源码返回，供内联进独立页面。 |
| `scripts/turn-check.mjs`、`scripts/turn-bench.mjs` | 3D 图形：与 kit 构建器的保真度对比、z-buffer 顺序检查、像素跳变、24 个角度下的线端检查与浏览器中的帧计时；以及按部件类型统计的 Node CPU 耗时。 |
| `scripts/print.mjs`、`scripts/print-sheet.mjs` | 可打印页面：把已构建页面的各姿态冻结为矢量静帧，并排成三种格式（poster、drawing、detailed）的 A4 或 Letter PDF。见 `references/print.md`。 |

按项目选择合适的路径：

- **独立 HTML、静态 SVG、博客文章或任何非 React 站点。** 写一个类似 `examples/dial-indicator/build.mjs` 的 Node 构建脚本。它 import `kit/iso-kit.mjs`，用 `solidSvg`、`lineSvg`、`dotsSvg`、`wireSvg` 和 `faceTextSvg` 组装字符串，用 `figureSvg` 和 `plateHtml` 包裹，再以 `pageHtml({ script: kitScript() + live })` 写出页面；带着色器时用 `kitScript() + glScript() + live`。若只要一个单独的 `.svg` 文件，用 `figureSvg({ standalone: "dark" | "light" })`，它会内嵌样式。
- **React 或 Next.js。** 把 `kit/` 复制进项目（例如 `components/iso/`）。几何放在纯 `.ts` 模块里，静态画面在服务端组件中用 `draw.tsx` 组件构建，再把它作为元素 props 传给唯一一个 `"use client"` 活动组件，由它驱动运动。`references/react.md` 讲解了这一拆分方式以及大页面会踩到的一个陷阱。

## 工艺规则（简版）

以下是区分精工图形与普通图表的规则。`references/craft.md` 给出完整的推理与配方。

- **实体，而非线框。** 每个部件都填充纸面色并按序绘制，前面的东西遮挡后面的东西。不要有透视可见的边，也不要虚线隐藏线。
- **让 kit 来着色。** `extrude` 按朝向返回四个侧面色调外加更亮的顶面。任何有高度的东西都保留它，`flat` 只用于地面和厚度小于 1 单位的镶嵌件。
- **色调层级。** 底座和支脚用 `lo`，结构用 `mid`，主体用 `hi`。有且仅有一个强调件用 `lit`（深色主题为白、浅色主题为黑）：它是读者应该注视的部件。凹槽用 `faint`，次刻度 `lo`，主刻度 `mid`，零位标记 `hi`。只有当颜色本身是主题时才用彩色，例如红、绿、蓝通道。
- **细小精确的细节，绝不是噪点。** 倒角用 0.4–1.6，凹槽距边内缩 3–5，螺丝画成 0.4–0.55 的圆点、板角处带一圈，旋钮上加滚花，标尺刻度每 4–5 单位一个、每第 5 个为主刻度，铭牌带三条刻线。每个细节都隶属于某个部件。
- **线条有归处。** 每条线都终止于某物：一个面、另一条线或一个端点圆点。连接器是端点圆点落在物体上的 `Wire`。没有引出线、气泡标注、尺寸箭头或悬在空中的标签。
- **任何管或线缆都不穿过任何东西。** 无论静止、拆开还是爆炸图的任何一帧，都不穿过另一根管、线缆或实体。除线路自身连接点外，与所有东西保持约 1.5 个半径的间隙；让线路沿结构旁边走，而不是横穿主体正面；凡法兰、箍带、波纹管、卡箍或阀门包住管子的地方，都给管子留缺口。部件相接的方式是平齐、相切或边缘落在表面上，绝不陷入：法兰的背面落在其端口上（端口为曲面时落在鞍座垫 `G.saddleOf` 上），支管从球形三通引出，而每个端头——拆开状态也一样——都收束于法兰、管接头、连接器外壳或端点圆点。
- **每个交叉都按真实深度顺序绘制。** 屏幕上两件物品重叠时，较近者画在上面，由 `A.settle` 和审计证明，而不是靠眼睛调。线路在直线段交叉，且深度上彼此相距足够远：落在另一条线轮廓上的弯头、端头或卡箍会被读成接头（杆、拉杆、立柱或导轨都算线：管子的最后一段腿在屏幕上绝不沿着这样一条线走）；先指向观察者再转向的一条腿会收窄成 V 形（这类端口要经弯头球引出）；线路绝不在屏幕上折返。无法排序的一对要做互锁处理，修法是切断或改为相切接触，绝不能用 key 偏置。
- **曲面平滑着色，绝不做成分段阶梯。** 把曲面节点标记为平滑（`[s, r, 1]`），`lathe` 会用一条同时画出轮廓的单调曲线为其着色；比管接头更大的任何曲面体都要用 `smooth: { slope }` 给出解析轮廓，长曲体用 `G.bandsOf` 切分，球体用 `G.sphereOf`。色调条带渐细至无，而不是止于一条直线切边；接缝藏在轮廓之下（`inner`）。
- **纹理要么终止于真实边缘，要么渐隐。** 棱筋、螺栓圆、刻线、接缝和凹槽绝不在表面（无论平面还是曲面）中央停住：`ribsOf` 和 `dotsOf` 接受 `fade`（渐隐的棱筋用 `fadedSvg` 绘制），棱筋排终于其接缝（`ribsOf(…, { seams: true })`），箱体上的接缝或焊缝包住它的角（`k.sideSeam`，同板的 `inner`），一个面上的线从一个边画到另一个边，通风格栅是闭合的槽，刻度悬挂在标尺条的边缘上，必须停住的单线用 `fadeLineSvg` 渐隐收尾，特征朝上的一排（环顶面上的孔）要四面可见（`all: true`）。管子上的纹理（编织、波纹、包覆）跟随其横截面并穿过每个分块接缝：`tubePieces(…, { rings })`，绝不是沿中心线的虚线描边。管子的高光与阴影要延续到端盖上，并穿过每个分块接缝。只有代表印刷文字的刻线、表针的尾部与指针的尖端可以停在光面上，并标记为 `free`。
- **着色器绝不跳变或被硬切。** 每个 uniform 都乘在一条带起振（attack）与衰减（decay）的包络上；相位变化是由物理量驱动的交叉淡化；每一项都在任何边界或画布边缘之前归零；效果存在于世界空间中，使用图形自己的相机（见下文）。
- **面上的东西要贴合面。** 机器显示的文字在最宽字符串下也要装进其窗口并被裁剪到窗口内；透过开口看到的内容既被开口裁剪、也被其自身平面裁剪，且要画出凹槽内壁。
- **体积。** 给物件真实厚度，让它们站在别的物件上，并在底座下方以及任何被抬起的物件下方加一圈柔和光晕。
- **构图。** 图形居中并占据卡片约 55–65%。一组图形保持一致的缩放，并确保在 390 px 宽度下仍能读懂。

## 图形内部的 WebGL

着色器只用于线条画不出来的东西：火焰与尾气、水与焦散、真实的灯光、辉光、蒸汽。部件保持为 SVG。核心规则来自第一张带着色器的图形——它的相位间颜色变化看起来像硬切而非交叉淡化：

- **三层结构。** 后层 SVG 承载效果覆盖之下的内容，画布承载效果本身（`pointer-events: none`），前层 SVG 承载覆盖效果的内容。当部件或效果两侧都涉及时，将其拆分。
- **世界空间，同一相机。** 每个着色器点都用 `onFloor`、`onWallX` 和 `onWallY` 构建，或对像素射线 `rayOf(vb) + t·towardViewer()` 做步进。所有尺寸都用世界单位乘以 `uK`。凡位于某平面上的东西都与该平面的 SVG 线条精确对位。
- **没有跳变。** 每个 uniform 都遵循一条带起振与衰减的包络（事件用 kit 的 `burst`，量级用 `settle`）。相位变化是交叉淡化，颜色随物理量连续变化，淡出只会更暗。
- **没有硬性截断。** 每一项都在任何 `if`、边界或画布边缘之前归零，也在任何 cell noise 的胞格边缘之前归零。
- **透过开口观看时双重遮罩。** 窗口或凹槽之后的内容既在其自身平面内被遮罩，也被正面平面上的开口遮罩，两者相乘（`references/webgl.md` 第 5 节）。
- **混合。** 使用 `tonemap()` 与抖动（dither）。深色主题下，只加光的画布用预乘输出配 `mix-blend-mode: screen`；还需要压暗的画布（如 ripple-tank 的水）保持普通混合。
- **浅色主题是正式交付物，其着色器为纸面而设计。** 使用普通预乘 alpha，绝不用 screen。先写下纸张应显示的颜色，再解出墨量。辉光是一个饱和主体加浅色核心、彩色边缘和一个 alpha 下限，绝不是把深色主题的颜色压暗——那正是造成 Raptor “红色墨烟” 的原因。
  - 被光照到的表面带一点色调偏染，容纳光的腔体用更深的物理底色（烟灰、耐火材料、水体深度）。
  - 热体遵循与回退方案共用的一张黑体墨量对照表。
  - 墨量只随光增长：对最终墨量做一次整体淡出，绝不逐项淡出。
  - 墨量终止于每条描边的内侧边缘。
  - 逐帧测量墨量。`references/webgl.md` 第 8 节有配方以及评审者发现的错误。
- **克制。** 设备像素比封顶 1.5，只在效果激活且在屏内时渲染。reduced motion 下只给一帧静帧，且没有 WebGL 时 SVG 也必须依然可读。

写任何着色器之前，先读 `references/webgl.md`。

## 3D：可转动的图形（beta）

3D 是和 WebGL 一样的可选能力。当“部件在深度方向运动”本身就是概念时使用它：转动的拨盘或转台、屈伸的手指、崩落坠下的部件。图形的其余部分保持静态 kit 画面。

它仍处于 beta：引擎只在其示例和一个测试图形上得到验证，尚未在正式成品图上验证。一次只转动一个主体，并保持其周围的杂物为静态。小图形可跑 60 fps；在一台负载很重的机器上，一个 380 个部件的密集屈伸手在 1440 下实测约 20 fps，在手机配置（390 px、4× CPU 降速）下为 13–15 fps。

- **活动部件就是 kit 自己的画面。** 每一帧，凸的 kit 图元（棱柱、回转体、穹顶、带平面的球、车削件、管件）都按 kit 的规则重新投影、重新着色。转动 θ 角就是 kit 以方位角 `a − θ` 绘制。
- **顺序来自分离平面。** 同组配对用在组内固定的平面，不同连杆上的配对用在其公共坐标系内固定的平面，其余配对每帧求解。审计证明任何角度、任何动作片段帧内都不存在循环。
- **接触方式为平齐、相切或边缘落在平面上。** 关节是子组上与父组连杆相触的同轴铰节盘，否则审计会把整个子组判为松动。没有活动线跨越两个运动组：线缆借助两侧的线夹跨过关节，或通过轮毂处的滑环到达转台。
- **活动管在近水平面内或接头件内部弯曲，且绝不指向视线方向。** 弯曲需要 R ≥ 2r / sin²(e − θmax)，其中 θmax 包含其所经过的每个铰链的俯仰范围：平放时界限为 8r，±12° 铰链上为 21r。每条线路都从安装面走到安装面，其端口记入 `gaps`。这一点在任何角度、任何姿态下都成立。
- **材质重新映射色调坡。** 金、铬、钢、炮铜、橡胶、黄铜与铜各有一套浅色与深色配置；色调仍由朝向决定。
- **自由组的断裂没有跳变。** 同轴部件是带旋转纹理的固定画面。
- **着色器跟随运动。** 用 `controller.anchor` 或 `toGroup` 把它们锚定到组，用 `coverOf` 遮挡前层画布，并让世界空间效果（烟雾、坠落的火花、台面上的油）留在组空间之外。
- **用 `--audit` 验证**（输出 `turn audit passed`）和 `scripts/turn-check.mjs`（`--fidelity`、`--order`、`--pops`、`--lines`、`--perf`）。用 `--quick --only=…` 迭代。只有完整运行才能证明图形合格，30 个部件需要 15–20 分钟，所以放到后台运行。

先读 `references/3d.md`。

## 可打印页面（A4）

当用户想要纸面版本（讲义、海报、PDF、A4 或 Letter 页）时，从完成的图形直接打印，而不是重新绘制。在构建脚本旁写一个 `sheet.mjs`：把要捕捉的姿态写成 `drive.mjs` 动作，把部件写成对活动 SVG 的 CSS 选择器，把文字写全——每一个字都必须与模型相符。然后运行 `node scripts/print.mjs sheet.mjs --format all --png` 并逐页查看。

- **poster**（默认）：一页，名称大字排版、问题、大数字、带编号图钉的图形，以及每个部件配一行文字。
- **drawing**：一页，工程图纸，含部件清单、规格、一个局部放大插图，以及一条步骤条，其中工作部件被点亮。
- **detailed**：2–4 页，随机器规模伸缩：带图钉与圆形特写的总览；“How it works”（工作原理）页，每步一张大的点亮静帧（每页六张，最后一个位置放“为什么”）；复杂图形另有“Assemblies”（组件）页，最多四张部件组的大特写（规格中的 `assemblies`）。简单图形保持 2 页；`maxPages` 为其上限。

用户未选择时，三种格式都提供。当页面展示的图形已有对应 PDF 时，把 `kit/pdf-button.mjs` 的 `pdfButton(href)` 放进 plate 主体内，在卡片上加上指向它的链接（见 `examples/push-button/build.mjs`）；先打印，再重建页面。`examples/raptor-engine/sheet.mjs` 与 `examples/arcade-cabinet/sheet.mjs` 是参考实现。先读 `references/print.md`。
