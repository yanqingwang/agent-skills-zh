# Visualize：方向 comp 与资产生产

在以 comp 为先导的构建中，当图像生成可用（Harness 原生工具或 `impeccable context` 报告的 API 回退）时，从 [new-work.md](new-work.md) 加载本文件。以代码为先导的契约在设计上就跳过本文件，这不是漂移；此时不要加载它。PRODUCT.md 是前提；DESIGN.md 只在已确立的世界里才是前提，因为新的或替换的世界要到收尾时才写出它。为这个界面打出的 MODE RULES 块 concept-seed（COMPS）连同本文件一起管辖这些 comp，冲突时以 MODE RULES 为准；本会话没有 roll 时，读 new-work.md 点名的该模式的文件。New-work 已经解决了视觉世界；本文件不得重开它。一次已经把三张可视化卡片呈给用户的界面级结构轮（new-work.md，已确立世界）已经履行了本轮：被锁定卡片的 comp 就是已批准的 comp，所以记录该批准并从 After approval 一节继续；不要生成任何新东西。

一次探测（probe）测试构图、叙事、层级、密度、焦点时刻、签名的使用，以及图像要求。它不是第二场身份工作坊。保持世界的调色板、字体方向、材质语言、组件性格、图像立场与动效语法固定：已确立世界用 DESIGN.md 的，新世界用所选方向的。

## 生成三个构图选项

comp 轮在构建的阶段状态内运行：`impeccable build-phase start --direction <seed reference>` 已经运行（所选卡片有 decision comp 时带 `--decision-comp <path>`），且其 `comps` 阶段在第一个 comp 生成之前处于开启；在此之前的 comp 位于状态之外，从那个时点恢复的会话没有阶段可循。`impeccable generate-image` 在 start 运行之前拒绝写入 `.impeccable/mocks/` 之下；Harness 原生图像工具受同样的顺序约束。

渲染三张彼此不同、高保真的北极星 comp，对应请求的界面，保存在 `.impeccable/mocks/` 之下以跨会话存活。所选卡片有 decision comp 时，它就是选项一：留在 `.impeccable/mocks/decision/` 下的原路径，闸门经 `--decision-comp` 把它计入，绝不再生成；渲染另外两张。comp 采用界面自己的视口：native 应用或移动优先界面用设备尺寸的竖版，其余用桌面横版；把手机屏幕 comp 成横版，在用它构建任何东西之前就歪曲了构图。comp 是构建线程自己的工作，绝不委托：写提示词的线程持有方向的全部上下文，并且在构建开始时已看过每张 comp。用工作区相对路径打开每张图片；沙盒化的查看器拒绝绝对路径，而项目根下的一切都有相对路径。comp 基于真实内容以及已经与用户一起发展出的界面概念。在已确立世界上，每张 comp 都锚定真实身份：截取一张有代表性的现有页面的屏幕截图（已播种但尚无页面的世界，用其 DESIGN.md 在 `Reference image:` 下点名的图片），并把它作为参考图传入（Harness 图像工具的 input image，或 `impeccable generate-image --ref`）；提示词以新界面的结构领衔，参考图承载调色板、字体与组件性格，因为光靠 DESIGN.md 的文字会漂移，而像素参照不会。说明参考图贡献什么、不允许什么：chrome、调色板、字体与组件性格可以带过来；参考页面自己的内容不行，逐字搬来一条横幅、hero 或卡片是参考图在泄露，不是忠实。三就是三：一张 comp 招来橡皮图章；三张之间的跨度才呈现值得构建的构图。所选卡片的 decision comp 是三张中的第一张：它已经在这一纪律下以全保真渲染了这个方向，所以再生成两张，变动第一张固定下来的东西，从方向的文字描述出发，而不是把第一张 comp 当作输入图片（参考图会锚死布局，三张 comp 会塌缩成一个构图）。第二、三张如何与第一张不同，由模式在其 COMPS 规则中决定。一个把第一张简化为更整齐版本的变体，没有为本轮增加任何选择。三张一起送审。只有没有任何 decision comp 就抵达的一轮（降级的 roll、identity 模式页面、未走决策轮就钉死方向）才在此处渲染全部三张。

- 一条 comp 提示词要短，150 到 300 词，只携带图像模型无法知道的东西。模型画出提示词点名的东西，而提示词钉死的内容模型就不再自行决定，所以一条事无巨细的提示词只会换来一张模板。以界面开头：它是什么样的屏幕（桌面 web 应用、文档页、落地页、处于设备视口的 native 应用屏幕），属于哪个产品、写出名字，边到边渲染，文字清晰可读，周围没有浏览器窗口、设备或桌面。然后用平实的语言写产品与访客的任务，配上回答它的真实内容：名称、带单位的数字、offer 或状态、任何主张以其诚实的确定性表述、按名字写出的下一步动作。然后写本张 comp 的主导者、它的产品概念（summary-led、timeline-led、offer-led、reference-led），以及屏幕按阅读顺序容纳的部分，每部分一个短语。然后一行写框架：产品的标志与名称、它的导航、它的实用控件，以及远缘，让 comp 是一块完成的屏幕，绝不是一个碎片；没有导航的页面要写明没有，而不是发明一个。尺寸、位置、颜色、组件样式一律不写，除非用户钉死了某种颜色、字体或品牌元素：那是内容，要写。对每次渲染自检：如果它能当海报挂起来，或读起来像一张带点文字的照片，它就不是 comp；重新生成。
- 观感来自世界，有图可依时来自图片。已确立世界有上面的截图参照：它承载观感，所以提示词只用一句话写参考图贡献什么，不再多说任何风格内容。目录世界有卡片图片：把它的 board 与 hero 作为参考图附上（NEXT 行点名了它们；`impeccable generate-image --ref <board> --ref <hero>`，或 Harness 图像工具的 input images），并写一句话：参考是风格灵感，要适配成真实可用的产品，其布局与内容不可照抄。连风格也一并描述会覆盖图片。没有卡片图片的方向，用两到四句具体的视觉法则承载观感：底色与主色各做什么、字体的声音，以及让它可被认出的那一个签名。任何路径都不在主要的几种颜色之外列举颜色，也不逐个描述组件。
- 主体必须在画里。接受一次渲染之前，指向主体：只描绘世界、不含主体的渲染，无论氛围多么忠实都是失败，而这次删除通常乘着一份排除清单混进来。带着主体的内容重新生成。
- 把 comp 当作要交付的屏幕来评判：访客的任务必须能仅凭图片读出来。不带图注，从渲染里说出界面的模式；读不出模式的渲染是没有界面的艺术指导。以访客的任务作为提示词的主干重新生成。
- 投入是深度，不是铺满各区域的表演。世界通过一个主导动作加上支撑它的材质、字体与间距进入；其余区域在那个材质中保持安静，内容保持真实阅读字号。第二个元素在同等尺度上与主角竞争，就是 comp 在喊叫：重新生成，保留最强的动作，压低其余。忙乱是更响，不是更大胆。
- 用户入围了多个概念时，把三张分散到它们上面。
- 已投入一个方向时，变化一张图片能解决的结构性不确定：屏幕由什么领衔、拓扑、序列、密度、层级、焦点构图，或交互框架。
- 展示足够超出开场一刻的内容，证明这个概念能治理整个界面。
- 不要生成调色板产物，不要提新的氛围问题，不要引入另一种字体声音，不要发明新母题。已投入的世界支撑不了概念时，回到概念入围名单，而不是改世界。

每张 comp 都是一次方向测试，不是一张截图规格书。核心 UI 文字、响应式行为、无障碍、语义与交互状态仍是实现层面的责任。

## 一个批准点

三张一起呈现在决策页上（`impeccable serve-question`，每张 comp 一个选项，comp 作为其 hero），或在 Harness 中呈现，但仅当它内联渲染图片时；纯文本界面不算展示。问什么应当延续、什么与世界不符，以及所选概念应当批准、合并、修改还是拒绝。然后停下等待。结构化的模拟用户算作在场，收到同样的问题。

用户批准一个方向或明确委托选择之前，不要开始写代码。他们委托时，用任务简报、PRODUCT.md 与 DESIGN.md（新世界用所选方向）来选，并说明依据。批准精炼任务概念；它不修改 DESIGN.md。

本批准点没有替代物，也没有跳过条件。结构化提问工具出错时，回退到决策页；两者都失败之后，才可把选择视为已委托，而一次委托的选择按与批准完全相同的方式记录，并在你的第一次回复（不是最后一次）中披露。finish 审查者把没有记录批准的 comp 轮 comp 当作实质性 finding；`.impeccable/mocks/decision/` 下的 decision comp 是方向轮的手牌，不是 comp 轮的产出，其自身不隐含任何批准。

批准之后，把选择记录到工具能找到的地方：已批准 comp 的路径写进界面简报，其提示词 sidecar（图片完整文件名加 `.json`：`a.png` 得到 `a.png.json`）加上 `"approved": true`（每张经 `impeccable generate-image` 生成的 comp 都有一个；原生工具没生成时就创建一个）。sidecar 随 mocks 文件夹一起走，所以批准能跨会话、跨从未见过简报的机器存活，而 `impeccable build-phase advance` 正是读它来关闭 comps 阶段的。总结构图与 comp 中不得被字面化的部分，回到 new-work.md，从已批准的概念记录方向契约，然后开始构建。

## 批准之后：comp 变成规格

已批准的 comp 是翻译成语义化、响应式、无障碍代码的北极星，绝不是重新构图的许可：保留调色板与氛围却重画拓扑，是第二次艺术指导。不要把核心 UI 文字或控件栅格化。批准后不要未经询问就替换另一种视觉驱动器。

comp 展示的东西是被测量的，不是被记住的。new-work.md 第 6 节把构建作为阶段来运行（`impeccable build-phase`）：spec 阶段把 comp 转成区域盒与采样调色板（`impeccable comp-spec`），每个区域的媒介由像素是什么决定，绝不由什么感觉可构建决定：图形、产品物件、机械、任何含透视、明暗或绘画功底的插画，以及任何按名可指的纹理（编织布、纸纹、织物、皮革、拉丝金属），都是 `plate` / `image` / `texture` 区域并以位图交付；文字、控件、chrome、元素可数的图示、扁平形状系统，以及一切必须动、缩放或响应的东西，都是语义的。给一个雕塑感的面板表面写"CSS"，或给一个撕边写多顶点 `clip-path`，是对已批准设计的无声删除；检测器的 organic-clip-path 与 buried-raster 规则以及 hero 闸门的区域评分会抓住它。砍掉一个图像原生的区域是用户在批准点做出的范围决策，绝不是批准之后的静默扁平化。生成的图像是材料，不是主张：证据规则约束的是作为真实呈现的断言、规格、推荐语与照片，从不约束渲染保真度。

## Plates 与出处

每个位图区域的 plate 在 plates 阶段、任何页面代码之前产出，由随附的资产生产者或在当前线程中完成（用 `impeccable comp-spec --crop <id>`，并把 `impeccable comp-spec --plate-prompt <id>` 保存为提示词文件；把裁切与提示词交给 Harness 图像工具，或用 `impeccable generate-image --ref <crop.png> --prompt-file <prompt.txt> --out <plate.png> --size <WxH> --quality high`）。孤立的抠图，在 plate-prompt 与 API 生成命令中都加 `--background transparent`；用原生 PNG alpha，保留白色颜料与透明缝隙。满幅图像用 `--background opaque`。先创建输出目录，并在浅色与深色底上检查 alpha。生成上下文是资产的一部分：用任何工具生成任何图片之后，运行 `.claude/skills/impeccable/scripts/impeccable embed-prompt <image> --prompt "<prompt>"`，用工具收到的精确字符串（`impeccable generate-image` 自己就会做），让意图活在文件内部；`--read` 找回它，`--scan <dir>` 列出仍缺一个的位图。内嵌提示词加上 spec 中该区域的行，就是这张位图的**出处（provenance）**，产物引用的每张位图都携带它；有来源、素材库或既有的位图则内嵌其来源。之后在修复批次或审查者重建中创建或替换的位图，以同样的方式生产；一次修复放弃的位图在同一批次中删除。

用 `impeccable context` 启动时报告的转换器转换图片（IMAGE_TOOLS 行）；只在它什么都没报告时探测，每次会话至多一次，绝不逐图探测。
