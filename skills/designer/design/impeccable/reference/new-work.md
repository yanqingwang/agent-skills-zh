# 新的视觉工作

新的界面或替换视觉识别时使用本流程。PRODUCT.md 持有产品事实。DESIGN.md 持有持久的视觉决策。界面简报（surface brief）保存属于单一路由或产物的策略。PRODUCT.md 缺失时先完成 [init.md](init.md)；DESIGN.md 缺失不需要回退到 init。

选定设计稿（comp）的区域映射，命令序列与 schema 参见 [region-map.md](region-map.md)。

## 1. 判断哪些已经成立

阅读 DESIGN.md、代表性代码、tokens、组件与素材。

- **重设计：** 保留产品事实、内容、功能、约束和明确的品牌承诺；替换旧视觉世界，而不是打磨它。旧外观是"主体是什么"的证据，不是"它该变成什么"的权威。
- **已确立的世界：** 继承它。DESIGN.md 缺失并不能抹掉代码里已经存在的完整识别体系；把这套体系记录下来，而不是发明一个替代品。
- **不完整的品牌：** 保留已确认的素材和可识别的特征，然后与用户一起为这个界面扩展系统。
- **预设世界（seeded world）：** DESIGN.md 的 frontmatter 标注了一个目录 `world:`（由 `impeccable world <id>` 写入）而代码尚未承载它。用户已经选定了这个世界，所以它就是已确立的世界，即使启动报告说没有视觉权威也一样：绝不掷骰、重选或发明替代品。它的文字与颜色是方向，不是成品 tokens；首次构建负责落地它们，之后由 `document` 记录真实系统。全新界面按下方已确立世界的路径走；还没有页面可截图时，DESIGN.md 里该世界的 `Reference image:` 行就是设计稿的锚点。代码先行的构建没有设计稿，写代码前先看那张图：把它下载到工作区 `.impeccable/reference/` 下（绝不放 `.impeccable/mocks/`，那里的每张图都算设计稿），并打开相对路径，因为只能读文件或在沙箱里运行的查看者拿不到 URL。它是这个世界的唯一一张图。
- **没有视觉权威：** 与用户一起创造一个新世界。

已确立界面内部的区块、组件、功能或状态继承该界面。绝不把局部新增变成一次新的识别体系练习。

## 2. 问清会改变工作的问题

实现之前，能用结构化提问工具就用它拿到用户的回答。问两三个相关的问题；精确的请求只需要一次简短确认。跳过已定事实，但不跳过确认：DESIGN.md 定的是视觉世界，不是这个界面的目的或概念。

- **说服（Persuade）：** 谁必须行动，他们应当相信什么，哪些真实证据、内容或素材能赢得这种相信。
- **操作（Operate）：** 任务、信息、重要状态、频率、约束。
- **阅读（Read）：** 读者的问题、源材料、结构、导览路径。
- **体验（Experience）：** 什么引导，探索如何展开，哪种交互或过渡重要。

各模式下都要问：成功是什么样子，什么必须保持不动，什么会让精致的结果显得不对。绝不要问 CSS 数值或现成的审美选项。在新建或替换世界时这里只有产品问题：concept-seed 运行前不要提出自己的外观方案，因为问题里点名的方向就是回答会确认的那个。

## 3. 选择合适的发明量

### 扩展现有界面

继承它的世界与构图。只解决新的目的、内容、层级、状态、交互，以及这次新增如何接入周边体验。不做概念锦标赛；除非用户批准持久的系统级变更，否则不改 DESIGN.md。

### 在已确立世界内创建完整界面

视觉系统保持不变。从内容、任务和用户行为出发，推导五到七个实质不同的结构，按共鸣度排序。对于真正开放性的整页、整屏或流程，运行：

`.claude/skills/impeccable/scripts/impeccable concept-seed --scope surface --mode <mode>`

脚本从你的结构里发三张牌；骰子决定哪三个送到用户面前，打破排名惯性，同时用户保有真实选择。在决策页上以同等显著度的完整卡片呈现它们，被发到的主打结构放在 kicker THE ROLL 之下，附 steer 与 re-roll；用户锁定一张。每张卡声明 `kind`：被发到的主打结构为 `assigned`，其余被发到的结构为 `dealt`，赢得席位的挑战者为 `challenger` 并带 `catalogId`（即 SOURCE ID）。surface 范围不放标准款卡片（canon card）也不放精选卡片（pick card）：世界已定，每张卡可视化的都是构图，不是识别体系。有图像生成且构建路径为设计稿先行（PRESENTATION 块为本界面打印的路径；见下方构建路径段）时，每张卡声明一张 `comp`，位于 `.impeccable/mocks/decision/` 下，在页面服务之后按阅读顺序生成，遵循 [visualize.md](visualize.md) 的设计稿纪律和 concept-seed 为本界面打印的 MODE RULES 块。每张设计稿锚定已确立的识别体系：把一个代表性现有页面的截图（预设世界还没有页面时，用 DESIGN.md 在 `Reference image:` 下点名的图片）作为参考图（Harness 图像工具的输入图，或 `impeccable generate-image --ref`），配一条 visualize.md 形态的短提示词；用散文转述设计系统会漂移，像素级参考不会。没有图像生成，或代码先行的轮次，每张卡携带第一视口的 HTML 草图，声明为其 `html`，页面按骨架绘制；PRESENTATION 块会写明其形态，没有的卡回退到 `wireframe` 示意（`impeccable serve-question --schema`）。锁定卡片即批准，并确定构建路径：锁定的设计稿按设计稿先行构建、该稿即已批准稿，直接清偿 [visualize.md](visualize.md) 的三选一轮，无需第二个批准点；锁定的草图或线框按代码先行构建，其抱负由方向契约承载，锁定的草图就是构建要对齐的构图。局部扩展或精确指定的窄请求绝不要跑这个脚本；直接塑形即可。

### 创建或替换视觉世界

1. 用一句话说出产品的独特机制、受众的真实场景、它的文化归属，以及这第一个界面必须证明什么。记下这个品类总在交付的页面及其可预料的反面；两者都是惯性套路，排除在七个候选之外。简报自己描绘的画面、产品名、有题名的产物、统领性隐喻，都会把其字面读法加进套路：最多花一个候选在其上，其余从受众世界的其他地方推导。
2. 从那个文化世界列出七个受众烂熟于心的具体视觉系统、器物、场所或仪式，每个配一行它为何有共鸣、能承载机制，再配一行它的样子（底色与主色、字体声部、让它可被认出的那一个签名），按共鸣度排序。受众的世界包括其图形与屏幕传统，不只物理物件：他们日常阅读的记谱法、出版物、识别程序、数据图形和界面。在 Operate 或 Read 界面上，七个候选仍来自该世界的任何角落（其图形传统、场所、仪式与器物），绝不来自受众操作的工具与仪表：交给工作屏幕的终端、示波器或控制面板，回来只会变成那件工具的戏服。可命名的抽象系统（某一流派的海报、某套文档标准）与任何器物一样是具体候选。在 Persuade 或 Experience 界面上，受众操作的工具与仪表计入套路：最多花一个候选在其上。还要问这个东西作为实体物件会是什么样、它的世界在 Web 之前是什么样。近似重复的算一个。七个里超过三个同属一个材质族，说明推导停在了主体最显眼的器物上；往下挖，直到清单横跨至少三个族。
3. 把这些素材变成完整的设计方向：每一个都把一个可复用的视觉世界接到一个具体的首个界面体验上。
4. 运行 `.claude/skills/impeccable/scripts/impeccable concept-seed --scope direction --mode <mode>` 并照它打印的做。不许替代，不许跳过：在新建或替换世界时，这个脚本运行并被确认其指派之前就写产物代码，无论 Harness、模型或时间压力如何都是违约；掷骰正是防止每次运行都收敛到品类默认值的东西。唯一例外是用户或简报完整钉死（pin）的方向，其世界与首个界面体验都用可引用的文字点明：步骤 1 到 3 无从推导，指派也无可约束，因此不掷骰、不出决策页；只有简报文件携带的钉死项才向用户确认，让收尾审查可以佐证，并在第 5 节记录该钉死项。差一点都要掷骰：留了一个维度开放的钉死项、你从残缺简报补完的方向、或只有简报的画面或隐喻，那是步骤 1 的套路素材。脚本指派要构建的方向，并发牌目录挑战者。判定前先把每个挑战者融合：挑战者供给形式与其系统语法，产品供给一切事实，冲突时清晰度胜出。融合后的挑战者与被指派方向只在两条轴上较量：受众认同与产品清晰。败给扎实的有根素材是正当结果；胜过单薄或工具单一文化的清单才是要点。给每个挑战者一个判定，且在任何借鉴之前定下：wins（两条轴都胜过被指派方向；成为构建候选）、competitive（守住一条轴；保留为完整备选）或 declined（两条都输）。declined 的挑战者没有被浪费：点出其系统里被指派方向缺少的那一条纪律，在呈现之前把被指派方向提升到与之相当。捐献转移的是抱负与系统纪律（一套色板的彻底投入、一个网格的密度勇气、一种形式的结构诚实），绝不是挑战者的衣服。组件级处理，比如按钮的阴影或一款展示字体，是衣服不是纪律；搬来的母题是戏服注记，不是提升，且一个世界拥有一整页。把每条提升写进呈现的方向里，单独成行，注明捐献者；没人读得出来的提升等于没发生。
5. 呈现一个方向，全面投入，并且已被它击败的那手牌提升过，提升以具名行的形式可见：世界、首视口、访客路径、签名交互、跨界面延展、诚实风险。按判定分流每个挑战者：获胜与 competitive 的挑战者是完整备选，带各自的 QUALITY BAR 卡片和一行理由；declined 的挑战者降级呈现，紧凑而安静，各带其判定以及方向从它那里保留下来的东西，绝不占全尺寸，也绝不悄悄丢弃，请求时仍可选用。判定为用户提供信息，绝不替用户做决定；降级行就是这手牌判断力的证明。一手牌最多容纳三张全尺寸挑战者卡：掷骰发得更多时，最强的三张加入，其余在重发池等待，用一行注明；把挑战者踢出一手牌本身需要点明一条产品事实上的失格，并披露。手牌大小跟随判定，绝不跟随用户点名的数字：权衡后全尺寸卡少于所求数量时，如实交付这手牌，用一行说明为何更小，并提供重发以发出可能赢得全尺寸席位的候选。declined 的挑战者绝不会被提拔来凑数；被提拔的卡与 competitive 卡外观完全相同，提拔会不留痕迹。常设出口（standing exit）在用户看过并拒绝之后不计入所求数量；它作为安静之门继续在场。当你自己排序最高的有根候选不是被指派方向时，为它加一张卡，kicker 为 IMPECCABLE'S PICK，解剖结构与每张卡相同，若属实则配一行诚实风险点出其熟悉感：最强的有根方向往往是本品类大多数运行的落点，用户亲自决定这笔取舍正是展示它的意义。熟悉且有效是正当目的地，不是勇气的失败；精选卡与常设出口在两个深度上服务它。精选卡只放一张，绝不两张，绝不是排名清单：把你的候选排成阵容等于把选择交回给品味函数，并招来最安全的那张。精选卡绝不占主打位；骰子指派你的首选候选时没有精选卡，被指派的卡会注明它登顶你的清单。附上 re-roll 与可选的一行 steer，三种档位：plain（换一手新牌，同样跨度）、safer（你剩下的常规有根候选加标准款，对阵点名竞品）、bolder（只用外来形式，全力投入）。档位是用户在熟悉-大胆轴上的引导，绝不由你预选；回答携带档位时，用 `--register <value>` 重跑 seed 并进入下一个 `--reroll` 轮，照它打印的做。方向轮进行中用户说"bolder"或"safer"，指的就是这些档位，绝不是 bolder 或 harden 命令。两条通道共享此结构，只在丰富度上有别：决策页上是卡片与展板，结构化工具里是名字与一句话，其选项列表携带被指派方向、精选、获胜与 competitive 挑战者，常设出口放在最后；declined 挑战者折入被指派选项的描述，作为其保留行，提升因此也能在文本通道存活。

常设出口（standing exit）：每个方向轮都提供一个安静、永久的备选，即品类标准，按正规打法出牌。它是用户的门，不是你的：绝不推荐它，绝不用它去权衡掷骰结果，绝不让它软化被发到的方向；制衡约束的是未被选择的默认项，不是被选中的那个。用户选了它（canon 动作、safer 档 steer、或用平实言语求熟悉或竞品式的路径）时，惯例成为承诺：问一次它应与哪两三个产品并列，把那些产品的工艺水准定成标尺，全保真地执行 canon，不带讽刺也不夹带怪癖。把常设偏好作为品牌承诺记入 PRODUCT.md。重发会淘汰已展示的每个方向，有根候选与挑战者一视同仁；连续两次重发后，问缺的是什么质量。自己主动重发只在点明的事实理由下进行，即被指派方向承载不了产品的事实或任务；品味从来不是理由。用户可以随意重发，而用户或简报钉死的方向永远压过掷骰。钉死点明的是外观本身，用用户的话，或用户使之具约束力的品牌承诺；简报引用的参考产品定的是工艺标尺，不是世界，而对开放式 steer 的、只是复述简报的回答什么也钉不住。碰撞逐字段解决：保留每一条用户或简报钉死的约束。简报留白的维度里，指派仍通过其拓扑、控件、状态词汇与仪式约束；当只有其材质与钉死的视觉方向或 PRODUCT.md 品牌承诺冲突时，翻译那层材质表达，并在呈现的方向里注明这次翻译。外观不匹配不构成重发理由。把决策可视化呈现：写一个选项 payload，被指派方向领衔，包含其提升行；有精选卡时带上；被发到的挑战者作为备选，带各自 QUALITY BAR 卡片、判定与保留行；re-roll 连同其 safer 与 bolder 档；steer；canon 启用；`buildPath` 携带记录的默认值，只要有图像生成就带 `toggle: true`（细节见下方构建路径段）。没有挑战者的退化掷骰仍用决策页，作为单张纯文本卡加 re-roll。每个选项声明自己的身份：`kind` 为 `assigned`、`pick`、`challenger`、`grounded`（你自己的另一个有根方向，比如 safer 一手牌阵容里的每张卡，数量不限），或 `dealt`（surface 轮发到的、主打之外的结构），每个挑战者携带 `catalogId`，即 concept-seed 为其世界打印的 SOURCE ID，绝不是卡片自己的 id；`--start` 和 `--update` 拒绝缺少它们的 direction 或 surface payload，页面据其报告选择。每张卡同一解剖结构：论点、色板、材质、首视口、诚实风险，以及挑战者的理由行（`--schema` 打印确切形状）；页面由这些字段渲染身份，自行把 declined 挑战者降级到其所在行，挑战者的目录图只作为标注了出处的灵感随行，绝不是构建的承诺。也要撰写 `canonCard`：品类标准作为一张诚实卡片，同一解剖结构；页面让它居于从属，制衡仍然约束你。运行 `.claude/skills/impeccable/scripts/impeccable serve-question --start --payload <file>`（先 `--schema` 看 payload 形状）。脚本守护进程化，打印页面 URL 和一个 key，然后退出；为用户打开该 URL，先用应用内浏览器，再用系统打开器，最后展示 URL。用 `--wait --key <key>` 收集选择，退出码 3 时重复；ANSWER 以 JSON 打印。ANSWER 为 `{"optionId":"reroll"}` 时保持服务器存活、页面停在等待新牌：用相同 `--scope` 和 `--mode` 加 `--from <seed-key> --reroll <n>`（首次重发为 1，向上计数）重跑 concept-seed，构建下一个 payload，用 `--update --key <same key> --payload <file>` 交付，然后回到该 key 的 `--wait`。绝不在此时 `--start` 第二个服务器或退回聊天：两种做法都会把已打开的标签页晾在一手永远不会到来的牌上。退出码 4 表示页面未作答就关闭：用结构化提问工具再呈现一次，那里也没有回答时，按被指派方向无人值守继续并声明假设。能让 shell 在后台阻塞的 Harness 可以不带 `--start` 运行脚本，让它自动打开并阻塞。无法持有阻塞式 `--wait` 的 Harness（分离长时命令且不返回其输出，或回收后台子进程）改用结构化工具、不启动页面，并在第一条回复里披露这次替换，标签页绝不会被晾着不答。把仍在运行的命令作为可轮询会话交还的 shell 算持有等待：轮询该会话直到退出，仅在它已退出且无回答时才重跑 `--wait`。绝不预测其他任何回退：运行脚本，只有启动时退出码 2，或启动前的等待检查，才把决策改道到结构化工具；那两个是回退路径，不是可以重试的错误。concept-seed 用这个流程收尾每次掷骰，以浓缩形式写进 PRESENTATION 块，其中注明记录的构建路径。

有图像生成时，每张卡还声明一张 `comp` 路径，位于 `.impeccable/mocks/decision/` 下，canon 卡也一样。Harness 给 shell 上沙箱时，用它提供的沙箱最少的命令路径启动页面：沙箱 shell 绑不了展板的端口，第一次失败会让每个会话都付出一次重试。先服务页面，再产出设计稿；页面按槽位微光等待，用户可能在图落地之前就作答。写第一张决策稿提示词之前就加载 [visualize.md](visualize.md)，不要等到设计稿轮：每张卡的图是该方向在其设计稿纪律与 concept-seed 打印的 MODE RULES 块之下的全保真北极星稿，先写提示词后读规则会漏掉那里的每一条：请求的界面作为真实页面，其首视口及其下方小节的开头，同每张稿一样受 visualize.md 规则约束，即模板骨架无论被哪个世界上色都仍是模板（你自己的精选也算：世界皮肤下的安全布局仍是模板），提示词用 visualize.md 的形态、短，用真实产品名与真实内容，不发明商业性声明，用该卡自己的色板、字体性格与材质世界，贯彻到底。一旦某轮声明了尚未生成的设计稿，`impeccable serve-question --start`（以及 `--update`，以及翻转到 comp）会打印一行 `NEXT read <path>/visualize.md`；届时先读那个文件，再写第一条提示词。`--wait` 对已落地但没有提示词伴生文件（sidecar）的决策稿打印 `COMP SIDECAR MISSING`（伴生文件名为图片完整文件名加 `.json`：`a.png` 对应 `a.png.json`）；继续之前先补齐缺失的伴生文件。`COMP STALE` 点名某文件是上一轮留在这一手牌槽位上的；在原位重新生成。生成在任何保真度下耗时相同，因此未完成的草稿按草稿质量支付设计稿的成本；卡与卡之间的公平是各自语法下的同等保真、同一界面、同一侧面，绝不是共享的未完成。画幅取界面自己的比例：原生应用或移动优先的界面用竖版设备视口，桌面 Web 用横版；决策页两者都适配，横版构图的手机屏是一帧破画，不是中性默认。按阅读顺序产出：被指派卡、然后精选、然后全尺寸手牌、然后 canon，每个文件完成即写入其提示词伴生文件，这样重发的开销前置到最先被读的卡上；declined 挑战者没有设计稿，其目录缩略图就是它的脸。有并行子代理时，每张卡派一个代理：每次派生都是随包的素材生产者（asset producer），携带单稿包（single-comp packet）、该卡字段、NEXT 行点名时其世界的卡片图、PRODUCT.md、共享画幅、指向 visualize.md 的路径作为其设计稿纪律、逐字复制的 MODE RULES 块 COMPS 节（子代理看不到掷骰输出）、以及该卡声明的路径，同时在飞不超过四个。代理返回时仍为空的槽位就地重新生成；用户作答时仍为空的槽位干脆放弃。除此之外不欠任何监督。没有并行子代理时，服务页面后在主线程生成，顺序相同，进度交给 Harness 自己的生成展示；对回答的等待跟随最后一个文件。被选卡的设计稿不因被选而消耗：设计稿先行时，它作为构图选项一进入设计稿轮；代码先行时，它在收尾审查回归为批评参照，即图像敢于而构建未敢的部分。未被选的设计稿留在 `.impeccable/mocks/decision/` 作为该轮花掉的一手牌；它们不携带批准，也不暗示批准。没有图像生成时，卡片用色板色块与事实承载身份，那样的页面是完整的，不是缩水版；页面此时也会自行把每个挑战者的目录图降级为带标注的缩略图，因为显著度必须编码判定，而不是编码哪张卡碰巧有图。

执行契约（构建路径），无论设计稿先行还是代码先行，都绝不在轮内询问；页面的开关处理例外。Operate 或 Read 界面无论项目记录什么都是代码先行：工作屏幕与文档，建出来比画出来更好。Persuade 或 Experience 界面取记录的默认值：从 `.impeccable/config.json`（`buildPath`）读取，单机与团队提交值不同时，gitignore 的 `.impeccable/config.local.json` 优先；两者都没有时，只要有图像生成，默认就是设计稿先行。concept-seed 的 PRESENTATION 块为手头界面打印该路径；照那行做。撰写每个 direction 与 surface payload 时都写 `buildPath: { "value": <default>, "toggle": true }`；页面渲染一个页脚开关并在旁边写明取舍，ANSWER 返回 `buildPath` 和 `buildPathFlipped`。翻转值只约束该会话，永不回写，只有一个例外，也是该偏好在轮内唯一值得问的一次问题（有机会的项目 init 会提前记录）：当 `buildPathFlipped` 在一个完全没有记录 `buildPath` 的项目的 Persuade 或 Experience 界面上返回 true，轮次关闭后问一次是否将其保留为常设默认；Operate 或 Read 界面上的翻转只是一轮的选择，绝不提供记录。两种回答都写 `.impeccable/config.json`；回答选定的是值，绝不是要不要记录。是（Yes）写入翻转后的值；"不，仅这一次"写入他们翻转离开的值，即他们用拒绝刚刚确认的常设默认。在翻转上问，绝不在未动的默认上问：留着开关没动的用户什么也没告诉你。被拒绝的提议什么都不写下，下一次会话会再次提出。用户用言语要求更改常设默认时，直接更新文件，不再问。**设计稿先行**：被选卡的设计稿就是法律，尚不存在时先于构建生成，收尾审查以它为基准审计构建；桌上放最大胆的构图，预期会有修复轮，设计稿不可选，不许静默跳过。**代码先行**：本页没有设计稿，也不为此道歉；用户从每张卡的 HTML 草图中选择，被选中的就是构建对齐、收尾审查审计的构图；QUALITY BAR 展板仍然校准完成度，抱负移入书面契约，即 FIRST VIEWPORT 块加具名的签名交互与动效语法，收尾审查者在行为中审计这些承诺；代码先行不是投入的折扣。代码先行的轮次仍把每张卡的设计稿路径声明为翻转储备：用户在轮中把开关翻到 comp 时，`--wait` 以 BUILD PATH FLIPPED 返回一次，页面让槽位微光等待；届时把每张未决卡的设计稿生成到其声明路径，主打卡优先，然后再次等待。翻回去不花钱，已渲染的设计稿在收尾审查作为批评参照随行。没有图像生成就没有开关也没有选择：代码先行是唯一路径，用一行陈述而不是询问。结构化工具回退同样没有开关：按 PRESENTATION 块为该界面打印的路径构建，不问构建路径。旧的两卡执行契约轮已退役；`followup: true` 仍是经 `--update` 在同一张桌上交付任何后续轮的通用机制。

目录世界是能运转的系统，不是情绪参考。一个世界胜出时，把它的色板与材质、字体与构图、拓扑、控件与状态、响应式规则带进产品，带多远以界面的模式允许为限。本身就是界面语言的源头能把语法带多远，由模式决定，写在 MODE RULES 块里。选择落定的那一刻就打开你要构建的世界的 QUALITY BAR 展板与 hero，哪怕你先前看过的是另一张卡；ANSWER 行点出被选卡的图片（Harness 只读文件或在沙箱中运行时，把图下载进工作区并打开相对路径；沙箱查看者拒绝工作区外的绝对路径）。它们设定构建必须达到的工艺水准，是一张已渲染参考的完成度、投入度与美术方向，绝不是构图；你的界面服务于这个产品。

掷骰可能落到的每个方向都必须已经可行：它可视化的每条关系与声明都为真，有真实的色板与组件族，有带一个产品专属体验的独特构图，能在现有素材、工具与性能预算内以整界面尺度运作。在真实性问题上的失败者，掷骰之前就换掉，绝不靠掷骰来救。真约束的是声明，不是演示：绿地工作里，概念需要的任何示意素材都以全保真撰写，访客可能误以为真的地方标注"合成"，并把需要换成真实素材的清单交给用户。不可发明的是商业与事实声明：价格、客户、基准、端点、产品并不具备的能力。以演示数据尚不存在为由拒绝大胆方向，是穿着诚实外衣的怯懦反射。

开场必须做什么、世界能延伸到页面多深，取决于界面的模式。`concept-seed --mode <mode>` 以 MODE RULES 块打印该模式的规则，分 DIRECTIONS 与 COMPS；它们治理该界面的每个方向、卡片与设计稿，与共享指引冲突时以它们为准。会话没跑过 concept-seed 就走到了方向或设计稿（完整钉死的方向，见步骤 4），则改读模式文件：Persuade 与 Experience 读 [mode-persuade.md](mode-persuade.md)，或 [mode-operate.md](mode-operate.md)、[mode-read.md](mode-read.md)。

## 4. 投入这个世界

选颜色之前先选色彩策略：克制（从中性色调出世界色再加一个强调色；常见于人们操作或阅读的屏幕，模式规则在这些屏幕上仍要求颜色承担实际职责）、投入（一个饱和色承载界面 30-60%）、完整色板（3-4 个具名角色），或浸染（界面就是颜色本身）。Persuade 与 Experience 界面获准使用更大胆的策略；简报允许就采用。颜色以页面尺度投入：成片拥有整个区域的色域，不是撒在中性底色上的强调点。深色还是浅色从来不是默认：写一句物理场景（谁在用，在哪里，什么光线下），让它逼出答案。

像从主体世界里挑器物那样挑字体，用该模式的声部。系统字体栈与主力 UI 字体足以服务 Operate 与 Read 界面；Persuade 与 Experience 界面想要有立场的字体，而下面这些训练数据默认值意味着你停止了寻找：Fraunces、Playfair Display、Cormorant、Lora、Crimson、Newsreader、Syne、Space Grotesk、Space Mono、IBM Plex、Inter-as-display、DM Sans、DM Serif、Outfit、Plus Jakarta Sans、Instrument Sans。仍要选用其中一款字体，需要一个其他任何字体都无法满足的理由，主体联想从来不是那个理由：书要衬线、书店要手写体、科技要等宽，正是这份清单要打破的联想。

校准：无论主体是什么，AI 生成的界面都聚在几种面孔上：暖奶油底、高对比衬线展示体，配陶土红或信号红强调色；近黑底配一个霓虹强调色和发光边缘；大报排印的发丝线、斜体展示衬线、小号加字距的等宽标签；平涂饱和墨色配黑框、硬投影和厚重的压缩展示体。简报点名要求时，这些全都正当。简报把审美留白时，落进其中一种意味着自查失败：如果有人能仅凭品类、或凭品类加规避项猜出你的审美，就返工，直到两个答案都不明显。能量不是信任的敌人：简报的负面约束（不要游戏化、不要炒作）排除的是那些手法，不是热情，描述产品行为的形容词（安静的支持、沉稳的辅导）不支配界面的能量。书卷气、温暖或面向儿童的主体不会软化校准：书布、线、夹克、环衬与书架上的小物横跨整个饱和色谱，奶油纸只是这个世界最小的一角；书类主体落在奶油加衬线上，是默认值穿着主体的衣服。简报钉死的世界钉住的是世界，不是它最柔软的呈现：被钉死世界的完整材质范围仍在牌桌上，呈现结果与其他任何模型为该世界出货的东西一样，失败在执行而非选择环节。

你的已测呈现先验：温暖、书卷、家庭、面向儿童的主体会呈现为奶油底、带斜体强调的衬线展示体和灯光，即使被指派方向从未要求。把第一版色板当作已经花掉的。写代码之前重读自己的 OWN-WORLD 块：当它对简报未钉死的 Persuade 界面说出 cream、paper、parchment、ivory 或 lamplight，呈现即告失败，先从该世界的饱和材质重新做起。同一主体在其他模型上呈现为书布、线、夹克与环衬色；主体本身没有任何东西要求你的默认值。

## 5. 记录决策

写代码之前，把选定的方向作为仅开发用契约记录在相关界面简报的 `## Direction contract` 下。方向契约属于持久的路由或产物策略，因此即使没有其他界面策略需要持久化，也要创建或更新简报。用六个短块，大约 150 词；不要花工具调用去数字数。THESIS：这个界面拥有的唯一想法，以及它拒绝的品类默认排布。OWN-WORLD：色板与组件语言，具体到抽掉全部内容仍可辨认。STORY：访客理解什么、相信什么、做什么。FIRST VIEWPORT：确切构图，什么在哪里、什么尺度，主行动落在何处。FORM：选定的形式、它在你的有序清单上的位置，以及 concept-seed 打印的 SEED REFERENCE（`seed:` 加 16 位十六进制），绝不是原始 seed key：简报一经提交，在这台机器上凡是命令需要 key 之处都由该参照代行。掷骰打印 SEED REFERENCE unavailable 时，写 `seed: none (unavailable)`，此外什么都不写。完整钉死的方向跳过了掷骰时，把 `seed: none (pinned)` 写在清单位置与参照两个位置上，后接钉死它的被引原话。最后再写一行 FINISH：本次运行的退出条件，逐字为"unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance"。界面简报是后续代理在编辑与会话间重载的提醒：FINISH 行未清偿却看上去完整的页面不是完成，是在终点线前被丢弃。某个块读起来像情绪，说明方向还没定；收尾审查以本契约为基准审计渲染。

绝不把方向契约复制进实现源码或任何浏览器交付物。这包括 HTML 或框架注释、隐藏 DOM、`<template>` 元素、`data-*` 属性、渲染出的 JSX 或 TSX 输出、序列化的 props 或 state、React Server Component 负载、客户端 bundle、metadata 或 JSON-LD、仅无障碍可见文本，以及随产物一起服务的文件。编译器或优化器移除开发元数据，不构成安全边界。审查者与文档撰写者从界面简报获得契约。

新建或替换世界时，DESIGN.md 在收尾时写入，依据已建成的世界，由随包文档撰写者（documenter）执行（第 7 节）；构建前写成的规则手册会被用来对抗现实，而不是描述现实，还会给设计系统检测器一个不稳定靶子。新世界交付时没有 DESIGN.md 仍是不完整的运行。普通扩展不改写 DESIGN.md。

更新界面简报前先读现有简报：

`.claude/skills/impeccable/scripts/impeccable surface-brief read <primary-target>`

`.claude/skills/impeccable/scripts/impeccable surface-brief write <primary-target> <body-file> [related-target ...]`

写完后再读一遍简报，构建之前核实六个契约块和 seed 参照（掷骰打印 unavailable 时为 `seed: none (unavailable)`；完整钉死的方向跳过掷骰时为 `seed: none (pinned)`）都在。

简报保持小：范围与访客模式；受众、工作、行动/任务、证据/内容与约束；选定方向与难忘瞬间；未决决策。不要把全局产品事实或 DESIGN.md tokens 复制进去。

设计稿先行的构建，只要有任何图像生成可用（Harness 原生工具或 `impeccable context` 报告的 API 回退），锁定的方向就在构建之前被可视化，绝不跳过：加载 [visualize.md](visualize.md) 并遵循它，三个构图选项交用户批准，即被选卡的决策稿加两个变体。这一步已被证明能产出最具构图性与抱负的作品。在 surface 范围结构轮中锁定的设计稿已经清偿了本轮（见上文"在已确立世界内创建完整界面"）。代码先行的构建按契约跳过设计稿轮，绝不因漂移跳过：它本要承载的抱负活在方向契约的 FIRST VIEWPORT 块与具名签名交互里，收尾审查者在行为中审计这些承诺。

`shape` 场景下，把选定方向交回 [shape.md](shape.md)，在持久化或实现之前停下。

## 6. 全力投入地构建

构建被指派的方向，而不是它的安全化解读。形式供给结构、阅读顺序、组件惯例与原生动效；产品供给一切事实。每个原子都投入：nav、按钮、输入框和链接都以形式的词汇重建，投入的形式里出现一个现成组件就是失手。首次构建就全力投入落地；后续各轮的存在是为了让投入的东西清晰有效，绝不是稀释它。无人值守的工作里，安全呈现就是已知风险。

### 设计稿先行：设计稿是量测过的契约

已批准的设计稿存在时，它是空间契约，不是情绪板：只有用户能以明示言语降级其权威。模型会系统性地相信自己对该图的 HTML、CSS、SVG 复刻成功了，实际并没有，所以构建以磁盘上的状态机运行，其关卡量测屏幕与设计稿的差距，而不是让你凭记忆。启动一次，让它告诉你下一步：

`.claude/skills/impeccable/scripts/impeccable build-phase start --direction <seed reference, or none when it was unavailable or a direction pinned whole skipped the roll> --artifact <entry file>`，在选定方向后立刻运行；被选卡有决策稿时加 `--decision-comp <path>`（CHOSEN COMP 点名的路径），让 comps 关卡把它算作选项一；surface 轮已锁定设计稿时用 `start --comp <approved comp> --artifact <entry file>`。start 不是选择 ping：那是掷骰的 TELEMETRY 行点名的 `concept-seed --kind` 重跑，掷骰打印了它就发送一次。

之后按顺序推进，每一步以 `.claude/skills/impeccable/scripts/impeccable build-phase advance` 关闭（下文每个动词都以 `.claude/skills/impeccable/scripts/impeccable <verb>` 运行；退出码 2 表示关卡失败并打印了原因；修复后再次推进；前置关卡未关时不为后续阶段写任何东西）：

0. **comps。** [visualize.md](visualize.md) 的设计稿轮：请求界面按其自身视口的三张构图稿，放 `.impeccable/mocks/` 下，各带提示词伴生文件，交到用户面前；被选者的伴生文件写入 `"approved": true`。关卡清点它们并读取批准；`start --comp` 跳过本阶段，因为它已经发生过。

设计稿先行路径是前沿档工作：它要求构建者持有量测过的布局、把图版放进各自的框、跨十几次尝试按数值读数行动。更小或更快的模型能产出可辨认的页面，然后在 hero 关卡卡死；手中的模型属于此类时，在方向轮之前说明并改走代码先行路径，否则就要预期运行止于 hero、读数未达标。

1. **spec。** 量测设计稿：`impeccable comp-spec --comp <comp> --grid` 在设计稿上叠加坐标网格；打开它，把每个显著区域按网格跨度记入 regions 文件（文本与控件区域只在保留下不少于该跨度 95% 对比像素时才收窄为一个墨迹簇；检查生成的裁剪，复合控件与多行文本尤其要查；`snap: false` 保留原跨度，显式 `box` 按所画采用）（画出来的东西用 kind `plate` / `image` / `texture`：每张插画、照片、图形、产品物件与材质纹理；代码绘制的东西用 `text` / `control` / `chrome`；每个区域带一条 `note`，说明设计稿在此处画了什么，图版提示词与关卡消息都会读它），然后运行 `impeccable comp-spec --comp <comp> --regions <file>`。spec 携带每个区域的框、采样色板与媒介；`impeccable comp-spec --print` 从此就是构建的参照。字体是量出来的，不是猜的：`impeccable font-match --measure <text region>` 从像素读出设计稿的 cap height、宽度类别与字重，`impeccable font-match --rank <region> --text "..."` 从 Google Fonts 目录的指纹索引（与裁剪形状最接近的字面）加你用 `--candidates` 传入的任何名字取候选，按该 cap height 和该区域的文字渲染并按指纹距离排序（其 `USE` 行就是 CSS）；没有可解析的浏览器时，它记录目录中最接近的字面并说明尺寸为估算，这仍是要依此构建的选择。不要为排序安装浏览器，也绝不手工把 `chosen` 字面写进 spec：关卡只接受 font-match 写入的内容。lead 文本区域量测并排序之前，spec 关卡拒绝关闭。代码 kind 之下描述绘画材质（图解、绘图、照片、纹理）的区域注记在 spec 处被拒：重新分类为 plate，或确认代码确实绘制时改写注记。脚本拒绝让设计稿墨迹保持未命名的 regions 文件：从未命名的东西永远不会被判缺失。它还拒绝大于设计稿四分之一的 `text` / `control` / `chrome` 区域：那是栏，不是元素。把其中的每个元素单独命名（`container: true` 只在它确实是不可分的单一元素时使用）。凡画出来的都是图版：超出图标预算的内联 SVG（图解、记号、带箭头的引线、对画面的"快速近似"）在 hero 处被拒；图标尺寸的 SVG（64px 以下、几条 path）没问题，页面在运行时由数据绘制的图表是 chart，不是插画。注解绘图的标注线与箭头归属那张绘图所在的图版，只把其标签设为文本。按独立变化的维度切分区域，[region-map.md](region-map.md) 有规定；带框视图是一个 frame 图版叠在其自身图像区域上。设计稿的裁剪永远不是图版（plates 关卡拒绝设计稿区域的重采样）；裁剪是图版据以生成的参照。图版区域的框必须连同边距容纳整幅画面：spec 量测画面与框边的接触并拒绝切穿画面的框（`bleed: true` 只在页面确实在该处裁切时使用），因为在此类框上以 `object-fit: cover` 放置的图版显示的是画面减去框丢失的那一侧。spec 之外的东西在页面上不存在：设计稿未画出的边框、细线、容器或 chrome 一概不加。只有三项让步：字体（可获得的最接近字面）、图标字形（足够接近即可，用户选了图标库则须精确；这只覆盖象形图，绝不覆盖控件的 chrome，所以 chevron、箭头、下拉框的边框与填充、按钮的形状都归设计稿）以及设计稿的真实缺陷如拼写错误。

产出素材之前检查提议的映射：`impeccable comp-spec --comp <comp> --regions <file> --inspect-map` 写出编号叠加层、精确裁剪、前景掩码预览和一份汇总报告，不改动 spec 或构建状态。边界与被排除像素一起检查；空参照需要修正几何。`parentId` 指向包裹它的 `container`；它绝不移除区域，也不批准素材。报告诊断的是几何，不是语义完整性。

2. **plates。** 每个栅格区域都作为图版交付：插画、照片或图形从其设计稿裁剪按素材分辨率重新生成、去掉 UI 文本，放其 `plate` 路径（孤立墨迹、图形或物件用原生透明 PNG，使其坐在页面自己的底色上；照片与纹理保持不透明）；纹理（纸、布、颗粒）是把设计稿区域的一块干净补片镜像平铺到所需尺寸，只在不存在干净补片时生成。`impeccable comp-spec --crop <id>` 写出参照；抠图把 `impeccable comp-spec --plate-prompt <id> --background transparent` 存为提示词文件，否则用 `--background opaque`。优先用带该裁剪与提示词的 Harness 原生图像工具，然后 `impeccable embed-prompt <plate> --prompt-file <prompt.txt>`。API 回退是 `impeccable generate-image --ref <crop.png> --prompt-file <prompt.txt> --out <plate.png> --size <WxH> --quality high --background transparent`（整幅素材用 `--background opaque`）；先建输出目录。核实真实 alpha、白色前景、细边与浅底深底上的镂空；不要对原生输出做色键抠图。plates 关卡按设计稿为素材打分；还要目检摆放与缩放。有并行子代理时，派随包素材生产者（`impeccable-asset-producer`；codex 中为 `impeccable_asset_producer`；Cursor 中为 `/impeccable-asset-producer`；GitHub Copilot 中说 "Use the impeccable-asset-producer agent"）携 spec 路径，让它全部产出；没有子代理时就在这里产出。设计稿的裁剪是参照，绝不是交付像素。已批准的设计稿是固定参照：绝不编辑它、不向它合成、不重新生成它，也绝不把它的裁剪直接拷作图版（裁剪只是你据以生成的参照）。关卡检查每张图版存在、尺寸至少为区域的 1.5 倍、且读起来是该区域。页面代码等这个关卡：图版尚未存在就写出的页面，是一个用 CSS 画素材的页面。单文件交付物不改变这一点：图版照样生成并内联为 data URI。`--force` 只为一种情况存在：用户以你在 `--reason` 里引用的原话降级设计稿权威；脚本拒绝其余一切理由。审查开启前先给图版打分：`build-phase advance` 报告只剩待审审查时，运行 [component-review.md](component-review.md) 的计划与素材审查，用户在其中检查图版以及哪些区域由代码绘制。他们接受之后被替换的图版需要新一轮。他们接受之前不写任何页面代码；未接受前 `build-phase advance` 拒绝推进。

3. **hero。** 先 `impeccable build-phase scaffold`：它把量测布局写成 CSS 自定义属性（`.impeccable/build/scaffold/layout.css`：`--r-<id>-x/y/w/h` 以设计稿百分比计，外加量测出的 cap height、font-size、family 与 weight），并写一个参照页（`hero-reference.html`），每个区域在其框内、每张图版已放置。把这些数字绑到你自己的语义结构上，每区域一个元素；参照页是位置检查，绝不是页面，重叠的框就是重叠的框。然后只构建第一视口，按设计稿自身尺寸，设计稿文字逐字照抄（用户批准的是带那些文字的设计稿；改写是 hero 通过之后的明示决策，绝不在其中悄悄进行），每个文本区域按量测 cap height 定尺寸并以其排名字面呈现（字体由项目本地提供：把该字体的文件放在页面旁边并用 `@font-face` 加载，绝不用 fonts.googleapis.com 这类托管字体样式表，也不用字体 data URI，因为首视口截屏只允许来自页面自身文件的字体，并把任何其他主机拒绝为外部依赖），图版优先：在任何文本或控件之前，把每张图版放到其 spec 框内（`object-fit: cover`、`<img>`、背景图，或以其命名的内联 data URI），截屏到 `.impeccable/review/hero-repro.png`，运行 `impeccable build-phase record hero` 一次，让图版区域在任何文本存在之前先读到匹配，然后从 spec 的色板与框把语义层铺上图版之上，推进。关卡先在源码未引用任何图版时拒绝，然后运行 `impeccable comp-diff`，写出 `.impeccable/review/diff/hero/`（并排、热力图、每区域一对裁剪、`report.json`；`raw-report.json` 保存未经解读的量测）。报告与裁剪标注采用关卡的判定；即使某区域被判为 drift，`gate.reasons` 也列出其余阻断项。图版被接受后，其文件、量测区域或设计稿变化时重新验证。关卡以总体 72% 且无未决硬否决通过（缺失区域、被推翻的图版或文本块、SVG 插画、被裁切的图版、任何分数下的凭空墨块）；过线之后，数值读数变为随通过一起打印的建议项，响应式之前的打磨轮就是修它们的地方：关卡还会对照设计稿读取每个文本区域的 cap height、行数、字重、墨色与位置，每条 chrome 带相对其细线的高度，以及设计稿平静处画面里的墨迹（kicker、多出的导航项、分隔线），并把每个偏差说成数字（"构建里 cap height 78px，设计稿 103px"）；这些数字就是要做的编辑。失败时，先按顺序打开它列出的区域裁剪再编辑：判为 `missing` 的区域需要它的素材，`contradicted` 需要从 spec 框重新推导结构，`drift` 是尺寸与间距编辑该去的地方；反复尝试不会清除未解决的阻断项。三次失败后，改为呈现 [component-review.md](component-review.md) 的首视口审查，而不是继续迭代。用户接受首视口后，只要截屏仍与之一致，总分数线、色板检查与每个数值读数都是建议项；缺失或未被引用的图版、SVG 插画、有机裁切、被裁切的图版、凭空墨迹与渲染在场失败仍然阻断。截屏偏离他们接受的东西时，恢复它：该审查已关闭，绝不会再被要求。这里是运行的抱负赢或输的地方，这里一次重试花几分钟，收尾时一次重建判定赔上整个运行。
4. **sections。** 在 spec 的系统内构建界面其余部分：同一套转角语言、线宽与色板，设计稿从未画出的东西一概没有。设计稿未覆盖的区域继承已记录的系统。
5. **motion。** 签名交互、揭示与动效，统一编排一次，而不是四处散落。
6. **responsive。** 其余视口，以及常用桌面宽度（1280 到 1600）下的第一视口，而不只是设计稿的精确尺寸：流式列，不要在窄一百像素就换行的固定像素网格，尺寸按视口比例而非 px 下限，设计稿首视口展示的东西没有被挤到首视口之下，已接受的首视口在桌面宽度下仍匹配。把 `desktop.png`（宽 1440，整页）和 `mobile.png`（宽 390）截到 `.impeccable/review/`；关卡把桌面首视口（宽 1440、设计稿纵横比；原生截屏渲染自己的）与设计稿比对，拒绝只在设计稿宽度下成立的首视口。失败时，按顺序打开它列出的裁剪：`displaced` 区域是在但被挤出首视口，通过调整其上方内容的尺寸把它恢复到首视口内，而不是只挪它自己。三次失败后关卡点名路线（首视口审查，或用户接受一次后的用户决定）；走那条路，而不是继续迭代或记录 `fix`。移动优先且做了设计稿的界面，设计稿是竖版构图；图版就是为那个画幅产的。

### 代码先行

没有设计稿，也不为此道歉：抱负活在方向契约的 FIRST VIEWPORT 块与具名签名交互里，收尾审查者在行为中审计这些承诺。被选的决策稿作为批评参照随行到收尾审查。

### 两条路径通用

- **首视口是论点，不是页眉。** 立刻演示机制，按该形式在现实中的尺度；不要把概念关进标准 hero 或卡片壳里。记忆测试：如果有人只看了一个视口就离开，一小时后他会描述什么？诚实的答案是种情绪，说明概念还没有投入。
- **证明，不要声称。** 展示主体在工作：界面运转中、机制被戏剧化、竞品无法复制粘贴的具体细节。演示数据是设计素材：以全保真撰写并标注合成；声明不可发明。
- **撰写素材，绝不用 chrome 顶替。** 伟大的界面活在精心制作的内容上：名字、条目、文案、封面、缩略图、纹理。绿地工作里，请求轮留下的每个空白都由你以生产保真度撰写；内容可撰写，声明可标注，没有哪个小节可省略。该有撰写素材的地方出现渐变、玻璃、通用图标贴片、多顶点 `clip-path` 多边形，就是穿着 chrome 的缺口；检测器标记后两者。
- **构建形式的 Web 杠杆。** 选定的世界点名了某项技术（canvas、WebGL、view transitions、生成式动效）时，构建技术本身，而不是它的静态模仿。
- **像工作室那样给滚动编节奏。** 在同一语法内变化密度、尺度、图像、动效与留白；密集段落挣来安静段落，页面以一个真实的收尾锚定结束。间距节奏全程统一，标题上方留白多于下方。
- **简报暗示需要真实图像时，用真实且经验证的图像。** 搜主体的实体物件，而不是品类；一张决定性的照片胜过五张平庸的。核实图库 URL 可解析。
- **把动效当素材撰写。** 给页面一次形式的原生动效，统一编排，而不是散落的悬停效果。昂贵的效果要设边界，内容默认可见。

保持语义、可访问性、性能、响应式、项目惯例与既有行为。

## 7. 检查与收尾

在一轮批量截屏里检查界面的目标尺寸：Web 上是桌面与移动；原生平台（`ios` / `android` / `adaptive`）上按 OS 的交付设备类，按平台参照的 Verifying the build 一节所述从模拟器或仿真器截取。Harness 报告了用户实际视口（应用内浏览器尺寸、具名分辨率）时，把该宽度加进集合：会破的宽度就是用户最先看到的宽度。凡交互之物，这一轮要驱动每个交互与可达状态（打开、关闭、悬停、聚焦、错误、空态、超长内容），并逐一检查重叠与裁切，不只是静置画面。以用户请求和方向契约为基准批评渲染，修实质性缺口，再用一轮最终确认；两轮是上限，修复在轮间批量做，而不是每个微调都挣一张截屏。上限约束检查，绝不关闭未关的 build-phase 关卡：关卡保持开启，直到通过或走了它点名的路线。设计稿先行的构建，运行 `.claude/skills/impeccable/scripts/impeccable comp-diff --comp <approved comp> --build .impeccable/review/desktop.png --spec .impeccable/build/spec.json --out-dir .impeccable/review/diff/final` 并把它的区域行与配对裁剪当作批评：并排视图是构建线程自己永远看不到的视角，被判 missing 或 contradicted 的区域就是要修的东西，无论凭记忆看页面多么顺眼。绝不凭一张整页缩略图判断保真度；它恰好藏起那些要紧的失败。Persuade 界面上，核实模式尽了职：首次访客应在几秒内知道这是什么、为什么重要、该做什么，用的都是形式自己的词汇。

截屏只有有效才是证据，发送前先验证。先让入场动效收尾或禁用：被动画时机藏起来的元素会被当成缺失元素，修成一个回归。整页截屏从文档顶部截起。设计稿对比按设计稿自身像素尺寸截。然后逐个打开每个文件一次，确认它展示的与文件名声称的一致：没有黑块或空白区，正确的文件名背后不是错误的小节，没有半加载状态。发出畸形截屏会赔上整轮；审查者以 `disposition: recapture` 回应，且其审过的任何东西都不作数。

第二轮检查之后，构建线程的打磨就结束了：这里不再有缺陷狩猎、微编辑脚本或重建（未关的 build-phase 关卡不是缺陷狩猎；按上文关闭）；剩下的经交接交付，新鲜上下文找得更准也更省。Web 上，该 Harness 不运行设计钩子时，在这里对变更目标运行一次 `.claude/skills/impeccable/scripts/impeccable detect --json`，修掉机械项，把其余发现交给审查者；跳过这一步的无钩子 Web 构建，会把钩子存在的意义所要捕捉的每个破绽都发布出去。原生平台完全跳过检测器：它读 HTML 与 CSS，对原生代码没有发言权，所以审查者的底线检查是唯一的 slop 关卡，输入包里要写明这一点。截屏存入 `.impeccable/review/`，每个被截视口一个文件（Web 上是 `desktop.png` 和 `mobile.png`，用户视口加入检查集合时再加 `user-<width>.png`；原生上每个设备类一个，如 `phone.png` 和 `tablet.png`，adaptive 上按 OS 加后缀），Harness 不创建该目录时创建它；传给审查者的路径就是它的 spec，你检查过的每个视口都在输入包中点名为必需，传入路径缺失时它就在该目录里找。

然后派生随包收尾审查者 `impeccable-finish-reviewer`（codex 中为 `impeccable_finish_reviewer`；Cursor 中为 `/impeccable-finish-reviewer`；GitHub Copilot 中说 "Use the impeccable-finish-reviewer agent"），携带原始请求、已确认的回答、产物路径、截屏路径、方向契约、既有钩子发现、QUALITY BAR 卡片与已批准设计稿路径（代码先行构建没有已批准设计稿；被选决策稿以批评参照身份占用该槽位，并如此注明）、设计稿先行构建的构建状态（`.impeccable/build/state.json`）、spec 与 diff 目录（`.impeccable/review/diff/hero/` 和 `.impeccable/review/diff/final/`，其并排、热力图、区域配对与 `report.json` 即保真度证据）、工艺底线参照路径，原生平台上还有平台参照路径 [ios.md](ios.md) / [android.md](android.md)，adaptive 则两者都要，外加一行说明未运行检测器，审查者按平台自身惯例而不是 Web 惯例判断。审查者没有浏览器；你未能传入的截屏就是它无法运行的检查。派生之前绝不读取随包代理的定义文件；Harness 在派生时加载它们，你只欠输入包。等待任何代理都用一次长超时，而不是短轮询循环，把等待花在下一个独立步骤上。核实返回携带五个契约节（recapture 返回携带一节，即其 recapture 清单）；返回为空或来回摇摆时，用相同输入重派一次。该审查绝不在构建线程内运行，也绝不继承它：全新派生审查者，不带分叉的会话历史（codex 中 `fork_turns: 0`）；继承你转写文本的审查者会继承你的框架、你的乐观和你的抽象，它所需的一切都在上述输入里。只有完全没有子代理能力的 Harness，才在彻底退出构建上下文后以全新的线程内一轮替代，按 [degraded/finish-reviewer.md](degraded/finish-reviewer.md) 运行；替代的或失败后更换的审查在收尾时用一行披露，绝不沉默。

按处置词行动；恰好四个。**recapture**：证据失败，不是构建失败。按捕获有效性规则重摄返回点名的部分，然后对新证据运行完整审查。在无效证据上进行的审查约束不了任何东西，其后的判定 pass 绝不可有。**rebuild**：保真度整体失败，不是局部失败。跳过修复批，立即执行重建：重新推导点名的区域，产出点名的素材，把结果送回做新的完整审查，绝不是判定 pass；重建整体替换区域，整个矩阵要在重摄之上重跑。告诉用户正在发生什么，而不是请求修复失败的许可。只在第二次 rebuild 指令、两个判定都摆在桌上、或重建会丢弃用户已批准内容时才咨询用户。**ship**：无所欠；按其范围报告判定并继续到文档撰写者。**fix**：一批内应用实质性修复，重建一次，对同样文件重摄同样视口。设计稿先行的构建，该批保持关卡通过：有阶段开启时，批后重跑 `.claude/skills/impeccable/scripts/impeccable build-phase advance`。全部关闭后，最后的 `finish --disposition ship`（只在审查者的 ship 判定上记录）复核页面，页面不再成立时重开 responsive。重摄量测的是位置、加载与溢出；它量不出修复是否达到了发现所指向的质量，所以把重摄截屏送回同一位审查者，由其判定每条实质性修复是 resolved、partial 还是 unresolved（经 Harness 的代理续谈；没有时，从 [degraded/finish-reviewer.md](degraded/finish-reviewer.md) 的 Verdict Pass 全新评分）。判为 partial 或 unresolved 的修复再来一批、重摄与判定。两轮是无人值守运行的预算；有人值守会话的上限属于用户，所以第二个判定仍列有未决项时，把表格摆到用户面前，让他们在按现状发布与出资再一轮之间选择。谁来决定都要在某一轮毫无进展时立即停下，且审查者的发现是你工作的唯一清单，绝不自行重开狩猎。不要再运行第二次检测器。

重建轮与修复轮共用一条素材规则：任一轮创建或替换的栅格仍是 [visualize.md](visualize.md) Produce 一节下的素材工作，像每个构建栅格一样保留其 **provenance**，该轮放弃的栅格在同一批中删除。任一轮的结果送回审查或判定之前，对产物栅格的交付目录运行 `.claude/skills/impeccable/scripts/impeccable embed-prompt --scan <asset-dir...>`，对其报告的每个文件补上所缺内容以清除：产出的栅格补确切的生成提示词，采购的、图库的或既有的补来源。扫描只读；删除只留给该轮放弃的栅格，绝不用于扫描点名的文件。

按审查者自己的处置词、按其实际范围报告最终判定。判定 pass 只对列出的修复评分，别无其他："审查者把三条修复都评为 resolved"是它支持的陈述，"没有实质问题残留"不是。还有未决实质性发现的表格绝不被宣布为通过，绝不软化，也绝不在只评了修复清单时装扮成整界面的批准。用户以反证回应 ship 时，他们自己的截屏、与设计稿的具名不符，该证据压过你做的每次捕获：把他们的素材放进输入包，派一位全新审查者做新的完整审查。就地打补丁并自我认证，正是被拒页面发布两次的方式。

最后一次修复之后，新建或替换世界、或经批准的系统变更在写入边界已有 DESIGN.md 时，收集 [document.md](document.md) 要求的选择：把现有文件展示给用户。用 AskUserQuestion 工具提问，继续之前等待回答。提供刷新、覆盖或合并。预设世界的首次构建不问：种子的存在就是等着被构建落地成的系统替换，所以选择是刷新，保留 frontmatter 的 `world:` 行和 sidecar 里的 `seededFrom` 键。然后派生随包文档撰写者 `impeccable-documenter`（codex 中为 `impeccable_documenter`），携带项目根、产物路径、方向契约、PRODUCT.md、[document.md](document.md)、写入边界与该选择；文档撰写者不能提问，没有该选择绝不覆盖既有 DESIGN.md。没有子代理时，写入之前加载 [degraded/documenter.md](degraded/documenter.md) 和 [document.md](document.md)。核实结果：新世界、预设世界的首次构建与经批准的系统变更要求带 tokens 的 DESIGN.md **加** `.impeccable/design.json`，不只是散文。普通扩展把成品构建与现行系统比对，保留其文件，报告核查过的证据；既有漂移未经要求不修。后续编辑之后复查。审查与文档都完成才叫完成。

设计稿先行的构建，最终回复之前用 `.claude/skills/impeccable/scripts/impeccable build-phase finish --disposition <ship|fix|rebuild|recapture>` 记录最终审查处置。被拒绝的 `ship` 是未完成的构建；连同判定报告未决阶段。最后被捕获关卡之后的任何编辑，包括 `ship` 之后的钩子发现修复，都会使该捕获作废：停止前再跑一次 `finish --disposition ship`，它按关卡复核当前文件并点名所需的任何重摄。绝不用记录 `fix` 来在有未关关卡时结束运行：走关卡点名的路线；用户让它开着时，把该阶段报告为开启。
