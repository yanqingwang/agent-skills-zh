## 样本量基础

### 必需输入

1. **基线转化率**：你当前的转化率
2. **最小可检测效应（MDE）**：值得检测的最小变化
3. **统计显著性水平**：通常 α = 0.05（5%）
4. **统计功效**：通常 80%（β = 0.20）

### 各参数含义

**基线转化率**：如果页面转化率是 5%，那就是你的基线。

**MDE（最小可检测效应）**：你在意检测的最小提升幅度。设定依据：
- 业务影响（5% 的提升有意义吗？）
- 实现成本（值得花这个力气吗？）
- 现实预期（过去的测试表现如何？）

**显著性水平（α = 0.05）**：就计划中的测试及其假设而言，它把错误拒绝真零假设的长期概率限制在 5%。它不是"观测到的差异由偶然造成"的概率。反复不加调整地查看结果、或做多重比较，都不会保持这一错误率。参见 [ASA 的解读指南](https://www.amstat.org/asa/files/pdfs/p-valuestatement.pdf)。

**统计功效（80%）**：意思是如果存在大小为 MDE 的真实效应，你有 80% 的概率检测到它。

## 时长计算器

### 公式

```
Duration (days) = (Sample per variant × Number of variants) / (Daily traffic × % exposed)

For unequal allocation, calculate each arm separately:
Days per arm = Required sample for that arm / (Daily eligible traffic × Exposure fraction × Arm allocation fraction)
Total collection time = longest arm duration
```

曝光比例与分配比例使用小数（50% = 0.5）。符合条件的随机化单元的计数方式要与样本量计算保持一致；重复的页面浏览不是新增参与者。均衡公式假设各臂样本量需求相同、分配比例相同。

### 示例

**场景 1：高流量页面**
- 需要：每变体 10,000（2 个变体 = 共 20,000）
- 日流量：5,000 访客
- 100% 暴露于测试
- 时长：20,000 / 5,000 = **4 天**

**场景 2：中等流量页面**
- 需要：每变体 30,000（共 60,000）
- 日流量：2,000 访客
- 100% 暴露
- 时长：60,000 / 2,000 = **30 天**

**场景 3：低流量且部分曝光**
- 需要：每变体 15,000（共 30,000）
- 日流量：500 访客
- 50% 暴露于测试
- 有效日流量：250
- 时长：30,000 / 250 = **120 天**（太长了！）

### 最短时长规则

即使样本量充足，测试至少也要跑满：
- **1 个完整周**：捕捉星期几带来的差异
- **2 个业务周期**：B2B 场景（工作日与周末模式不同）
- **覆盖发薪日**：电商场景（月初/月末）

### 最长时长指南

测试不要超过 4-8 周：
- 新奇效应会消退
- 外部因素会介入
- 占用其他测试的机会成本

## 多变体调整

变体多于 2 个（A/B/n 测试）时，需要更多样本：

| 变体数 | 倍数 |
|----------|------------|
| 2 (A/B) | 1x |
| 3 (A/B/C) | ~1.5x |
| 4 (A/B/C/D) | ~2x |
| 5+ | 考虑减少变体 |

**为什么？** 比较次数越多，假阳性概率越高。你在做这些比较：
- A vs B
- A vs C
- B vs C（有时）

使用 Bonferroni 校正，或用能自动处理此事的工具。

## 常见样本量错误

### 1. 功效不足的测试
**问题**：样本不足以检测出现实中会出现的效应
**解法**：把 MDE 定得现实些，去争取更多流量，或者干脆别测

### 2. 功效过剩的测试
**问题**：已经出现显著性了还在等样本量
**解法**：这其实没问题：你承诺过样本量，就要兑现

### 3. 基线率用错
**问题**：计算时用了错误的转化率
**解法**：用具体指标和具体页面，不要用全站平均值

### 4. 忽略细分
**问题**：按全量流量计算，然后却去分析细分
**解法**：如果计划做细分分析，就按最小细分来算样本量

### 5. 同时测太多东西
**问题**：把流量切得太碎
**解法**：狠心排优先级，减少并发测试数量

## 样本量要求过高时怎么办

拿不到足够流量时的选项：

1. **提高 MDE**：只接受检测更大的效应（20%+ 提升）
2. **降低置信水平**：用 90% 而不是 95%（有风险，记录在案）
3. **减少变体**：只测最有希望的变体
4. **合并流量**：跨多个相似页面测试
5. **测上游**：在漏斗更上游、流量更大的位置测试
6. **不测了**：改用定性数据做决策
7. **拉长测试**：接受更长时长（数周/数月）

## 序贯检验

如果你必须在达到样本量之前查看结果：

### 是什么？
对多次查看数据做调整的统计方法。

### 何时使用
- 高风险变更
- 需要尽早停掉差的变体
- 时间敏感的决策

### 支持它的工具
- Optimizely (Stats Accelerator)
- VWO (SmartStats)
- PostHog（贝叶斯方法）

### 代价
- 更灵活，可以提前停止
- 样本量要求略高
- 分析更复杂

## 快速决策框架

### 这个测试能跑吗？

```
Daily eligible traffic (randomization units): _____
Fraction exposed to the experiment: _____
Number of arms (including control): _____
Allocation fraction for each arm: _____
Baseline conversion rate: _____
MDE I care about: _____

Sample needed per variant: _____ (from tables above)
Balanced allocation: Days = Sample per arm × Number of arms / (Daily eligible traffic × Exposure fraction)
Unequal allocation: Days = max across arms of [Sample required for arm / (Daily eligible traffic × Exposure fraction × Arm allocation)]
Round collection time up, then apply the minimum-duration rules above.

If days > 60: Consider alternatives
If days > 30: Acceptable for high-impact tests
If days < 14: Likely feasible
If days < 7: Easy to run, consider running longer anyway
```

**时长核对（示意）：** 每臂需要 2,000 名参与者、每天有 1,000 名符合条件参与者时，两臂按 50/50 分配且全量曝光需要 4 天，而不是 2 天。曝光率 50% 时需要 8 天。全量曝光且按 90/10 分配时，较小的那臂需要 20 天才能凑满 2,000。这些只是数据收集的估算；仍要遵守计划好的业务周期和分析停止规则。
