# 竞品拆解（Competitive Teardown）

**层级（Tier）：** POWERFUL  
**类别：** 产品团队（Product Team）  
**领域：** 竞争情报、产品战略、市场分析

---

## 何时使用

- 产品战略或路线图会议召开之前
- 竞品发布重大功能或调整定价时
- 季度竞品回顾
- 销售演示之前需要作战手册（battle cards）数据时
- 进入新的细分市场时

---

## 拆解工作流程

按顺序执行以下步骤，产出一份完整的拆解报告：

1. **确定竞品** — 列出 2–4 个待分析的竞品。确认哪一个是主要关注对象。
2. **收集数据** — 依据 `references/data-collection-guide.md`，为每个竞品从至少 3 个来源收集原始信号（官网、评论、招聘岗位、SEO、社交媒体）。  
   _校验检查点：在继续之前，确认你已拿到每个竞品的定价数据、至少 20 条评论以及招聘岗位数量。_
3. **按评分标准打分** — 对每个竞品及你自己的产品应用下方的 12 维度评分标准，产出数值化的记分卡。  
   _校验检查点：每个维度都应有分数，且至少附一条支撑性证据说明。_
4. **生成产出物** — 使用 `references/analysis-templates.md` 中的模板（功能矩阵、定价分析、SWOT、定位图、UX 审计）填写内容。
5. **制定行动计划** — 将发现转化为行动项模板（速赢 / 中期 / 战略）。
6. **为利益相关者打包** — 汇编利益相关者演示文稿，使用步骤 3–5 的产出物。

## 数据采集指南

> 每个来源的完整可执行脚本见 `references/data-collection-guide.md`。以下是需要采集内容的摘要。

### 1. 网站分析

需要采集的关键内容：
- 定价档位（pricing tiers）与价格点
- 各档位的功能列表
- 主 CTA 与信息传达（messaging）
- 客户案例 / 客户 logo（可指示 ICP，理想客户画像）
- 集成生态 logo
- 信任信号（认证、合规徽章）

### 2. 应用商店评论

评论情绪分类：
- **好评** → 用户喜爱的点（应捍卫 / 强化的地方）
- **功能请求** → 未被满足的需求（机会缺口）
- **Bug** → 质量信号
- **UX 抱怨** → 你可以借此击败对手的摩擦点

**应用商店查询示例（iTunes Search API）：**
```
GET https://itunes.apple.com/search?term=<competitor_name>&entity=software&limit=1
# Extract trackId, then:
GET https://itunes.apple.com/rss/customerreviews/id=<trackId>/sortBy=mostRecent/json?l=en&limit=50
```
解析 `entry[].content.label` 获取评论文本，解析 `entry[].im:rating.label` 获取星级评分。

### 3. 招聘岗位（团队规模与技术栈信号）

从招聘岗位可以读出的信号：
- **工程岗位数量** → 是在扩张还是在收缩整合
- **具体技术提及** → 技术栈（React/Vue、Postgres/Mongo、AWS/GCP）
- **销售/客户成功比** → 产品驱动（product-led）还是销售驱动（sales-led）的增长模式
- **数据/ML 岗位** → 即将上线的 AI 功能
- **合规岗位** → 监管合规方向的扩张

### 4. SEO 分析

需要采集的 SEO 信号：
- 前 20 个自然搜索关键词（意图：信息型 / 导航型 / 商业型）
- 域名权重（Domain Authority）/ 反向链接数量
- 博客发布节奏与主题
- 哪些页面有排名（产品页 vs. 博客 vs. 文档）

### 5. 社交媒体情绪

通过 Twitter/X API v2、Reddit 或 LinkedIn 采集近期提及。寻找反复出现的好评、抱怨和功能请求。API 查询示例见 `references/data-collection-guide.md`。

## 评分标准（12 个维度，1–5 分）

| # | 维度 | 1（弱） | 3（平均） | 5（同类最佳） |
|---|-----------|----------|-------------|-------------------|
| 1 | **功能** | 仅有核心功能，缺口多 | 覆盖扎实 | 全面 + 有独到之处 |
| 2 | **定价** | 晦涩 / 定价过高 | 市场价，清晰 | 透明、灵活、公平 |
| 3 | **UX** | 晦涩难用，摩擦大 | 功能可用 | 令人愉悦，摩擦极小 |
| 4 | **性能** | 缓慢，不可靠 | 尚可接受 | 快速，高可用性 |
| 5 | **文档** | 稀少，过时 | 覆盖尚可 | 全面，可检索 |
| 6 | **支持** | 仅邮件，响应慢 | 在线聊天 + 邮件 | 7×24 小时，响应出色 |
| 7 | **集成** | 0-5 个集成 | 6-25 个 | 26+ 或生态深入 |
| 8 | **安全** | 无任何提及 | 宣称有 SOC2 | SOC2 Type II、ISO 27001 |
| 9 | **可扩展性** | 无企业版 | 面向中型市场 | 企业级 |
| 10 | **品牌** | 平庸，缺乏记忆点 | 定位尚可 | 强势，有差异化 |
| 11 | **社区** | 无 | 论坛 / Slack | 活跃、有活力的社区 |
| 12 | **创新** | 近期无发布 | 按季度发布 | 发布频繁且有意义 |

**填写示例**（竞品：Acme Corp，维度 3 – UX）：

| 维度 | Acme Corp 评分 | 证据 |
|-----------|----------------|---------|
| UX | 2 | 应用商店评论提到"导航令人困惑"（38 次提及）；新手引导在达成 TTFV（首次价值时间）前需要 7 个步骤；无引导向导；注册即要求绑定信用卡（CC required）。 |

对每个竞品的所有 12 个维度应用此模式。

## 模板

> 完整模板 markdown 见 `references/analysis-templates.md`。以下为简版参考。

### 功能对比矩阵

行：核心功能、定价档位、平台能力（web、iOS、Android、API）。  
列：你的产品 + 最多 3 个竞品。  
每个单元格打 1–5 分，加总得出满分 60 的总分。  
**评分图例：** 5=同类最佳，4=强，3=平均，2=低于平均，1=弱/缺失

### 定价分析

按竞品采集：模式类型（按席位 / 按用量 / 一口价 / freemium 免费增值）、入门/中档/企业版价格点、免费试用时长。  
汇总：价格领先者、价值领先者、高端定位者、你自身的位置，以及 2–3 条定价机会要点。

### SWOT 分析

对每个竞品：每个象限 3–5 条要点（优势 Strengths、劣势 Weaknesses、我方的机会 Opportunities、我方的威胁 Threats）。每条要点都必须锚定到一个数据信号（评论原话、招聘岗位数量、定价页等）。

### 定位图

2x2 轴（例如：简单 ↔ 复杂 / 低价值 ↔ 高价值）。在此放置每个竞品与你的产品。气泡大小 = 市场份额或融资额。ASCII 版与可编辑版见 `references/analysis-templates.md`。

### UX 审计清单

新手引导：TTFV（分钟数）、达到激活的步骤数、是否强制绑卡（CC required）、引导向导质量。  
关键工作流：步骤、摩擦点、对比评分（我方 vs. 对方）。  
移动端：iOS/Android 评分、功能对等性、最主要的抱怨与好评。  
导航：全局搜索、键盘快捷键、应用内帮助。

### 行动项

| 周期 | 投入 | 示例 |
|---------|--------|---------|
| 速赢（0–4 周） | 低 | 添加评论徽章、发布对比落地页 |
| 中期（1–3 个月） | 中 | 推出免费档、改善新手引导 TTFV、补齐呼声最高的集成 |
| 战略（3–12 个月） | 高 | 进入新市场、构建 API v2、取得 SOC2 Type II 认证 |

### 利益相关者演示文稿（7 页）

1. **执行摘要** — 威胁等级（LOW/MEDIUM/HIGH/CRITICAL），最大优势，最大机会，建议行动
2. **市场定位** — 2x2 定位图
3. **功能记分卡** — 12 维度雷达图或表格，总分
4. **定价分析** — 对比表 + 关键洞察
5. **UX 亮点** — 对方做得更好的地方（3 条）vs. 我方胜出的地方（3 条）
6. **客户之声** — 排名前 3 的评论抱怨（引用原文或转述）
7. **我们的行动计划** — 速赢、中期、战略优先级；附录附原始数据
