# 回测专家（Backtest Expert）

系统化的交易策略回测方法，基于专业方法论，其核心是稳健性优先于乐观结果。

## 核心理念

**目标**：找到"最不容易崩溃"的策略，而不是纸面上"利润最高"的策略。

**原则**：增加摩擦，对假设做压力测试，看什么能存活下来。如果一个策略在悲观条件下依然站得住脚，它在实盘交易中就更可能有效。

## 何时使用本 Skill

在以下情况下使用本 Skill：
- 开发或验证系统化交易策略
- 评估某个交易想法是否足够稳健、可以进入实盘
- 排查回测结果为何可能有误导性
- 学习正确的回测方法论
- 避免常见陷阱（曲线拟合、前视偏差、幸存者偏差）
- 评估参数敏感性与市场状态依赖性
- 为滑点和执行成本设定符合现实的预期

## 前置条件

- Python 3.9+（用于评估脚本）
- 无需 API 密钥
- 无外部数据依赖——指标由用户提供

## 工作流程

### 1. 陈述假设

用一句话定义优势（edge）。

**示例**："财报日高开超过 3%、且在第一个小时内回踩至前一日收盘价的股票，存在均值回归机会。"

如果你无法清晰地表述优势所在，就不要进入测试阶段。

### 2. 以零主观裁量固化规则

以下各项都必须给出完全具体的定义：
- **入场**：确切条件、时机、价格类型
- **出场**：止损、止盈目标、基于时间的出场
- **仓位管理**：固定金额、组合百分比、波动率调整
- **过滤器**：市值、成交量、行业、波动率条件
- **标的池**：哪些标的符合资格

**关键**：不允许任何主观判断。每一个决策都必须基于规则且无歧义。

### 3. 运行初始回测

测试区间要求：
- **至少 5 年**（最好 10 年以上）
- **多种市场状态**（牛市、熊市、高/低波动率）
- **符合现实的成本**：佣金 + 保守滑点

检查初始结果以判断基本可行性。如果从根本上有问题，就迭代假设。

### 4. 对策略做压力测试

这里应该花费 80% 的测试时间。

**参数敏感性**：
- 在基线的 50%、75%、100%、125%、150% 处测试止损
- 在基线的 80%、90%、100%、110%、120% 处测试止盈目标
- 入场/出场时机变动 ±15-30 分钟
- 寻找表现稳定的"平台期"（plateau），而不是狭窄的尖峰

**执行摩擦**：
- 将滑点提高到典型估计的 1.5-2 倍
- 建模最差成交情况（以 ask+1 tick 买入，以 bid-1 tick 卖出）
- 加入现实的订单拒单场景
- 采用悲观的佣金结构进行测试

**时间稳健性**：
- 逐年分析表现
- 要求大多数年份具有正期望
- 确保策略不依赖 1-2 个异常时段
- 分别在不同市场状态下测试

**样本量**：
- 绝对最低：30 笔交易
- 推荐：100 笔以上
- 高置信度：200 笔以上

### 5. 样本外验证

**Walk-forward（滚动前推）分析**：
1. 在训练期优化（例如第 1-3 年）
2. 在验证期测试（第 4 年）
3. 向前滚动并重复
4. 比较样本内与样本外表现

**危险信号**：
- 样本外表现低于样本内的 50%
- 需要频繁重新优化参数
- 参数在不同时期之间剧烈变化

### 6. 评估结果

**需要回答的问题**：
- 优势在悲观假设下是否仍然存在？
- 表现在参数变动下是否稳定？
- 策略在多种市场状态下是否有效？
- 样本量是否足以提供统计置信度？
- 结果是否现实，而不是"好得不像真的"？

**决策标准**：
- ✅ **Deploy（部署）**：通过所有压力测试且表现可接受
- 🔄 **Refine（改进）**：核心逻辑可靠，但需要调整参数
- ❌ **Abandon（放弃）**：未通过压力测试，或依赖脆弱的假设

使用评估脚本进行结构化、定量化的评估：

```bash
python3 skills/backtest-expert/scripts/evaluate_backtest.py \
  --total-trades 150 \
  --win-rate 62 \
  --avg-win-pct 1.8 \
  --avg-loss-pct 1.2 \
  --max-drawdown-pct 15 \
  --years-tested 8 \
  --num-parameters 3 \
  --slippage-tested \
  --output-dir reports/
```

该脚本从 5 个维度评分（样本量、期望、风险管理、稳健性、执行现实性）。将机器可读的 `decision` 和 `blocking_reasons` 视为权威结果。0–100 分的 `quality_score` 仅作诊断用途：即使得分很高，也不能推翻以下任何一项——非正期望（交易笔数少于 30 笔时首先返回 `NOT_EVALUABLE`）、回撤（drawdown）达到或超过 50%、用户设定的更严格回撤上限、交易笔数不足、缺少滑点/摩擦验证、测试周期不足五年，或结果好得可疑（胜率超过 90% 且最大回撤低于 5%，原因为 `too_good`，此时需要先做前视偏差与数据审计才能采用）。`verdict` 是保守的 Deploy/Refine/Abandon 兼容字段，其结果永远不会优于基于得分的判定。使用 `--max-acceptable-drawdown-pct` 可以在 50% 硬性上限之下设置个人上限；等于个人上限的取值是允许的。无效输入将以退出码 1 结束且不生成报告。

## 关键测试原则

### 惩罚策略

处处增加摩擦：
- 佣金高于现实水平
- 滑点取典型值的 1.5-2 倍
- 最差成交情况
- 订单被拒
- 部分成交

**理由**：在悲观假设下存活下来的策略，在实盘交易中往往表现更好。

### 寻找平台，而不是尖峰

寻找表现稳定的参数区间，而不是制造表现尖峰的最优值。

**好**：止损在 1.5% 到 3.0% 之间任意取值，策略都能盈利
**坏**：策略只在止损恰好为 2.13% 时有效

稳定的表现意味着真实的优势；狭窄的最优区间暗示曲线拟合。

### 测试全部案例，而不是挑选样本

**错误做法**：研究手工挑选的、事后验证有效的"市场龙头"
**正确做法**：测试所有满足条件的股票，包括失败的案例

选择性举例会造成幸存者偏差，并高估策略质量。

### 将想法产生与验证分离

**直觉**：适用于产生假设
**验证**：必须完全由数据驱动

绝不要让对某个想法的执念影响对测试结果的解读。

## 常见失败模式

尽早识别这些模式以节省时间：

1. **参数敏感性**：只在确切的参数取值下有效
2. **依赖市场状态**：某些年份表现极好，其他年份表现极差
3. **滑点敏感性**：加入现实成本后无法盈利
4. **样本过小**：交易笔数太少，无法提供统计置信度
5. **前视偏差**："好得不像真的"的结果
6. **过度优化**：参数很多，样本外表现很差

详细示例与诊断框架见 `references/failed_tests.md`。

## 输出

- `reports/backtest_eval_<timestamp>.json` — 结构化评估结果，包含各维度得分、危险信号、`decision`、`blocking_reasons` 和 verdict
- `reports/backtest_eval_<timestamp>.md` — 人类可读的报告，包含维度表、关键指标和危险信号详情

关键 JSON 字段：

- `decision`：权威结果，取值为 `DEPLOY`、`REFINE`、`ABANDON`、`REJECT`、`RISK_LIMIT_EXCEEDED`、`VALIDATION_REQUIRED`、`NOT_EVALUABLE` 之一。门控优先级：`NOT_EVALUABLE`（交易笔数少于 30 笔或 profit factor（盈亏比）溢出），其次 `REJECT`，其次 `RISK_LIMIT_EXCEEDED`，其次 `VALIDATION_REQUIRED`（未做滑点测试、不足五年、或 `too_good`）。只有当没有任何门控拦截时，才由得分产生 `DEPLOY`/`REFINE`/`ABANDON`。
- `blocking_reasons`：所有被触发的门控的 ID（`profit_factor_overflow`、`small_sample`、`negative_expectancy`、`zero_expectancy`、`excessive_drawdown`、`risk_limit_exceeded`、`no_slippage_test`、`short_test_period`、`too_good`）；即使更高优先级的门控决定了 decision，所有原因仍会全部保留。
- `profit_factor`：可能为 `null`。`profit_factor_status` 说明原因：`FINITE`（有数值）、`NO_LOSSES`（总利润为正且无总亏损）、`UNDEFINED_ZERO_GROSS`（无总利润也无总亏损），或 `OVERFLOW`（尽管亏损非零，比率仍溢出）。

## 关键提醒

**时间分配**：花 20% 的时间产生想法，花 80% 的时间试图打破它们。

**无背景依赖要求**：如果策略需要"完美的背景"才能生效，它就不够稳健，不适合系统化交易。

**危险信号**：如果回测结果看起来好得过头（胜率 >90%、回撤极小、择时完美），请仔细审计是否存在前视偏差或数据问题。

**工具局限**：了解你的回测平台的怪癖（插值方法、低流动性处理、数据对齐问题）。

**统计显著性**：微小的优势需要大样本量才能证明。每笔交易 5% 的优势需要 100 笔以上交易才能与运气区分开。

## 主观交易与系统化交易的差异

本 Skill 关注的是**系统化/量化**回测，其中：
- 所有规则都提前固化成文
- 执行中没有主观裁量或"盘感"
- 测试覆盖所有历史案例，而不是挑选出来的案例
- 背景（新闻、宏观）被刻意剔除

主观交易者的研究方式不同——本 Skill 可能不适用于需要主观判断的交易场景。
