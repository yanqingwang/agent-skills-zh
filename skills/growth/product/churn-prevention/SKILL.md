# 客户流失预防

你是 SaaS 留存与客户流失预防专家。你的目标是通过精心设计的取消流程、动态挽留优惠、主动留存策略和催收机制，同时降低自愿流失（客户主动选择取消）与非自愿流失（付款失败）。

## 开始之前

**先检查产品营销上下文：**
如果存在 `.agents/product-marketing.md`（或在较旧配置中的 `.claude/product-marketing.md`，或旧文件名 `product-marketing-context.md`），请先阅读它，再提出问题。使用该上下文，仅询问尚未覆盖或本任务特有的信息。

收集以下上下文（如未提供则询问）：

### 1. 当前流失状况
- 月度流失率是多少？（如已知，区分自愿与非自愿）
- 有多少活跃订阅用户？
- 每位客户的平均 MRR 是多少？
- 目前是否有取消流程，还是取消即时生效？

### 2. 计费与平台
- 使用哪种计费服务商？（Stripe、Chargebee、Paddle、Recurly、Braintree）
- 按月、按年，还是两者都有？
- 是否支持套餐暂停或降级？
- 是否有现成的留存工具？（Churnkey、ProsperStack、Raaft）

### 3. 产品与使用数据
- 是否按用户跟踪功能使用情况？
- 能否识别参与度下滑？
- 是否掌握过往流失的取消原因数据？
- 激活指标是什么？（留存用户做了哪些流失用户没做的事？）

### 4. 约束条件
- B2B 还是 B2C？（影响流程设计）
- 是否要求自助取消？（部分法规要求取消必须便捷）
- 退订沟通采用什么品牌语气？（共情、直接、轻松）

## 本 Skill 的工作方式

流失分为两类，需要不同的策略：

| 类型 | 成因 | 解决方案 |
|------|------|----------|
| **自愿** | 客户主动选择取消 | 取消流程、挽留优惠、退出调研 |
| **非自愿** | 付款失败 | 催收邮件、智能重试、卡片更新服务 |

自愿流失通常占总流失的 50-70%。非自愿流失占 30-50%，但往往更容易修复。

本 Skill 支持三种模式：

1. **搭建取消流程**：从零设计，包含调研、挽留优惠与确认
2. **优化现有流程**：分析取消数据、提升挽留率
3. **配置催收**：通过重试与邮件序列挽回失败付款

## 取消流程设计

### 取消流程结构

每个取消流程都遵循以下顺序：


```
Trigger → Survey → Dynamic Offer → Confirmation → Post-Cancel
```


**第 1 步：触发**
客户在账户设置中点击“取消订阅”。

**第 2 步：退出调研**
询问取消原因，据此决定展示哪种挽留优惠。

**第 3 步：动态挽留优惠**
根据其原因展示定向优惠（折扣、暂停、降级等）。

**第 4 步：确认**
如果客户仍要取消，明确确认并说明在计费周期结束时生效。

**第 5 步：取消后**
设定预期，提供便捷的重新激活路径，触发召回序列。

### 退出调研设计

退出调研是基础。合理的原因分类：

| 原因 | 它告诉你什么 |
|--------|-------------------|
| 太贵 | 价格敏感，折扣或降级可能有效 |
| 用得不够多 | 参与度低，暂停或上手引导可能有效 |
| 缺少某功能 | 产品缺口，展示路线图或替代方案 |
| 转向竞品 | 竞争压力，弄清对方提供什么 |
| 技术问题 / bug | 产品质量，升级给支持团队 |
| 临时 / 季节性需求 | 使用模式，提供暂停 |
| 公司停业 / 业务变更 | 无法挽回，吸取经验并体面放手 |
| 其他 | 兜底选项，附带自由文本字段 |

**调研最佳实践：**
- 只设 1 个问题，单选并可选填自由文本
- 原因选项最多 5-8 个（避免决策疲劳）
- 把最常见的原因排在前面（每季度复盘数据）
- 不要让客户产生被指责感
- “帮助我们改进”的措辞比“您为什么要离开？”更有效

### 动态挽留优惠

关键洞察：**优惠要与原因匹配。** 折扣救不了根本不用产品的人，功能路线图也救不了付不起费用的人。

**优惠与原因的映射：**

| 取消原因 | 主推优惠 | 备选优惠 |
|---------------|---------------|----------------|
| 太贵 | 折扣（2-3 个月内优惠 20-30%） | 降级到更低套餐 |
| 用得不够多 | 暂停（1-3 个月） | 免费上手辅导 |
| 缺少功能 | 路线图预览 + 时间表 | 替代方案指南 |
| 转向竞品 | 竞品对比 + 折扣 | 反馈访谈 |
| 技术问题 | 立即升级给支持团队 | 补偿 + 优先修复 |
| 临时 / 季节性 | 暂停订阅 | 临时降级 |
| 公司停业 | 跳过优惠（尊重处境） | — |

### 挽留优惠类型

**折扣**
- 2-3 个月内优惠 20-30% 是最佳区间
- 避免 50%+ 的折扣（会训练客户为了优惠而取消）
- 给优惠设时限（“离开本页后此优惠即失效”）
- 展示节省的具体金额，而不只是百分比

**暂停订阅**
- 暂停上限 1-3 个月（更长的暂停很少能重新激活）
- 60-80% 的暂停用户最终会回到活跃状态
- 自动重新激活，并提前发送通知邮件
- 保留其数据与设置不变

**套餐降级**
- 提供更低档位，而非直接全额取消
- 展示客户保留什么、失去什么
- 定位为“把套餐调整到合适档位”，而非“降级”
- 准备好后提供便捷的升回路径

**功能解锁 / 延期**
- 解锁客户尚未体验过的高级功能
- 延长更高档位的试用
- 对“没获得足够价值”这类原因最有效

**人工触达**
- 针对高价值账户（按 MRR 排前 10-20%）
- 转给客户成功团队安排通话
- 对较小的公司，由创始人发送私人邮件

## 流失预测与主动留存

最好的挽留发生在客户点击“取消”之前。

### 风险信号

跟踪以下流失的先行指标：

| 信号 | 风险等级 | 时间窗口 |
|--------|-----------|-----------|
| 登录频率下降 50%+ | 高 | 取消前 2-4 周 |
| 关键功能使用停止 | 高 | 取消前 1-3 周 |
| 支持工单先激增后归零 | 高 | 取消前 1-2 周 |
| 邮件打开率下降 | 中 | 取消前 2-6 周 |
| 计费页访问增加 | 高 | 取消前数天 |
| 团队席位被移除 | 高 | 取消前 1-2 周 |
| 发起数据导出 | 严重 | 取消前数天 |
| 个人推荐评分为 0–6（贬损者） | 中 | 取消前 1-3 个月 |

### 健康分模型

用加权信号构建一个简单的健康分（0-100）。在应用权重之前，先把每个分量定义在**同一 0–100 量表**上，分值越高代表越健康。对原始使用量、情绪和计费数值，使用有文档记录、产品特定的映射；不要把登录次数、1–5 的情绪评分和百分比直接相加。下面的权重只是示意性起点，并非经过验证的流失预测。

把缺失或过期的信号视为“不可用”，而不是自动判定为健康或零分。在使用分数前，先设定新鲜度窗口和最低覆盖率策略。若策略允许计算部分分数，则用 `sum(weight × observed score) / sum(observed weights)` 计算，并同时报告覆盖率（即已观测权重之和）；否则返回“数据不足”。全部不可用即不产出分数。例如，仅有登录（80）和功能使用（60）时，得到 `(0.30×80 + 0.25×60)/0.55 = 70.91`，覆盖率为 55%。在达到覆盖率策略要求之前，不要把这个部分分数提升为针对健康账户的动作。

个人评分为 0–6 属于贬损者；汇总 NPS（−100 到 100）是另一项指标。

[Gainsight 的度量权重文档](https://support.gainsight.com/gainsight_nxt/05Scorecards/02Admin_Guides/Measure_Weights_in_Scorecards) 解释了不可用度量的权重再分配方式。

示意性的完整数据模型：


```
Health Score = (
  Login frequency score × 0.30 +
  Feature usage score   × 0.25 +
  Support sentiment     × 0.15 +
  Billing health        × 0.15 +
  Engagement score      × 0.15
)
```


在投入实际使用之前，先依据后续观测到的续约/流失结果验证分数映射与干预阈值；以下分级仅为示意。

| 分数 | 状态 | 动作 |
|-------|--------|--------|
| 80-100 | 健康 | 增售机会 |
| 60-79 | 需关注 | 主动回访 |
| 40-59 | 有风险 | 干预活动 |
| 0-39 | 严重 | 人工触达 |

### 主动干预

**在客户动念取消之前：**

| 触发条件 | 干预动作 |
|---------|-------------|
| 使用量连续 2 周下降 >50% | 发送“我们注意到您还没有使用 [feature]，需要帮助吗？”邮件 |
| 接近套餐额度上限 | 升级引导（不是拦截墙，这类由 paywalls 处理） |
| 连续 14 天未登录 | 附带近期产品更新的再激活邮件 |
| NPS 贬损者（0-6） | 24 小时内人工跟进 |
| 支持工单超过 48h 未解决 | 升级处理 + 主动同步状态 |
| 年度续约还有 30 天 | 价值回顾邮件 + 续约确认 |

## 非自愿流失：付款挽回

付款失败导致 30-50% 的全部流失，却是最容易挽回的部分。

### 催收体系


```
Pre-dunning → Smart retry → Dunning emails → Grace period → Hard cancel
```


### 催收前置（预防失败）

- **卡片到期提醒**：卡片到期前 30、15、7 天发送邮件
- **备用支付方式**：注册时提示添加第二种支付方式
- **卡片更新服务**：Visa/Mastercard 自动更新计划（可将硬拒付降低 30-50%）
- **预扣费通知**：年付套餐在扣费前 3-5 天发送邮件

### 智能重试逻辑

并非所有失败都相同。按拒付类型制定重试策略：

| 拒付类型 | 示例 | 重试策略 |
|-------------|----------|----------------|
| 软拒付（临时） | 余额不足、处理超时 | 在 7-10 天内重试 3-5 次 |
| 硬拒付（永久） | 卡片被盗、账户已注销 | 不要重试，直接要求提供新卡 |
| 需要身份验证 | 3D Secure、SCA | 引导客户更新支付信息 |

**重试时间最佳实践：**
- 第 1 次重试：失败后 24 小时
- 第 2 次重试：失败后 3 天
- 第 3 次重试：失败后 5 天
- 第 4 次重试：失败后 7 天（伴随催收邮件升级）
- 4 次重试之后：强制取消，并保留重新激活路径

**智能重试小技巧：** 在付款最初成功的那个日期重试（如果之前 Day 1 能成功，就在 Day 1 重试）。Stripe Smart Retries 会自动处理这一点。

### 催收邮件序列

| 邮件 | 时机 | 语气 | 内容 |
|-------|--------|------|---------|
| 1 | Day 0（失败当天） | 友好提醒 | “您的付款未成功，请更新卡片。” |
| 2 | Day 3 | 贴心提醒 | “温馨提醒，更新支付方式以保留访问权限。” |
| 3 | Day 7 | 紧迫 | “您的账户将在 3 天后暂停，请立即更新。” |
| 4 | Day 10 | 最后警告 | “保留账户活跃状态的最后机会。” |

**催收邮件最佳实践：**
- 直接链接到支付信息更新页（尽可能免登录）
- 说明客户将失去什么（其数据、团队的访问权限）
- 不指责客户（用“付款未成功”，而非“您未能付款”）
- 附上支持联系方式以便求助
- 催收场景中，纯文本邮件的效果优于设计精美的邮件

### 挽回基准

| 指标 | 差 | 平均 | 好 |
|--------|------|---------|------|
| 软拒付挽回率 | <40% | 50-60% | 70%+ |
| 硬拒付挽回率 | <10% | 20-30% | 40%+ |
| 整体付款挽回率 | <30% | 40-50% | 60%+ |
| 催收前置预防 | 无 | 10-15% | 20-30% |

完整的催收手册及各服务商配置，参见 [references/dunning-playbook.md](references/dunning-playbook.md)。

## 指标与度量

### 关键流失指标

| 指标 | 公式 | 目标 |
|--------|---------|--------|
| 月度流失率 | 流失客户数 / 月初客户数 | B2C <5%，B2B <2% |
| 收入流失（净） | (流失 MRR - 扩展 MRR) / 期初 MRR | 为负（净扩张） |
| 取消流程挽留率 | 挽留成功数 / 取消会话总数 | 25-35% |
| 优惠接受率 | 接受的优惠数 / 展示的优惠数 | 15-25% |
| 暂停后重新激活率 | 重新激活数 / 暂停总数 | 60-80% |
| 催收挽回率 | 挽回数 / 失败付款总数 | 50-60% |
| 取消耗时 | 从首个流失信号到取消的天数 | 跟踪趋势 |

### 同期群分析

按以下维度细分流失：
- **获客渠道**：哪些渠道带来的客户粘性更高？
- **套餐类型**：哪些套餐流失最多？
- **在网时长**：多数取消发生在什么时候？（30、60、90 天？）
- **取消原因**：哪些原因在增长？
- **挽留优惠类型**：哪些优惠对哪些细分群体最有效？

### 取消流程 A/B 测试

一次只测一个变量：

| 测试 | 假设 | 指标 |
|------|-----------|--------|
| 折扣幅度（20% vs 30%） | 更高折扣能挽留更多客户 | 挽留率、LTV 影响 |
| 暂停时长（1 vs 3 个月） | 更长的暂停能提高回流率 | 重新激活率 |
| 调研位置（在优惠之前 vs 之后） | 先调研能让优惠更贴合个人 | 挽留率 |
| 优惠呈现方式（弹窗 vs 整页） | 整页能获得更多关注 | 挽留率 |
| 文案语气（共情 vs 直接） | 共情能减少摩擦 | 挽留率 |

**如何开展取消流程实验：** 使用 **ab-testing** Skill 设计具备统计严谨性的测试。PostHog 很适合取消流程实验，它的 feature flags 可以在服务端把用户分到不同流程，其漏斗分析能跟踪取消流程的每一步（调研 → 优惠 → 接受/拒绝 → 确认）。配置参见 [PostHog 集成指南](https://github.com/coreyhaines31/marketingskills/blob/main/tools/integrations/posthog.md)。

## 常见错误

- **完全没有取消流程**：即时取消等于白白丢钱。哪怕只是简单调研 + 一个优惠，也能挽回 10-15%
- **把取消入口藏起来**：隐藏取消按钮会招致怨恨和差评。许多司法辖区要求取消必须便捷（FTC Click-to-Cancel 规则）
- **所有原因都用同一优惠**：一刀切的折扣解决不了“缺少功能”或“用得不够”
- **折扣力度过大**：50%+ 的折扣会训练客户为拿优惠而反复取消回流
- **忽视非自愿流失**：往往占总流失的 30-50%，且最容易修复
- **不发催收邮件**：任由付款失败悄无声息地注销账户
- **制造内疚感的文案**：“您确定要抛弃我们吗？”会损害品牌信任
- **不跟踪挽留优惠的 LTV**：一个 30 天后又流失的“已挽留”客户，其实根本没留住
- **暂停时间过长**：超过 3 个月的暂停很少能重新激活，要设上限
- **没有取消后路径**：让重新激活变简单并触发召回邮件，因为部分流失用户会想回来
