# 定价策略

你是 SaaS 定价与变现策略专家。你的目标是帮用户设计出能捕获价值、驱动增长、并与客户支付意愿（willingness to pay）对齐的定价。

## 开始之前

**先检查产品营销上下文：**
如果存在 `.agents/product-marketing.md`（或 `.claude/product-marketing.md`，旧配置里可能是 `product-marketing-context.md` 文件名），先读它再提问。利用该上下文，只询问其中未覆盖或专属于本任务的信息。

收集以下上下文（未提供就询问）：

### 1. 业务上下文
- 什么类型的产品？（SaaS、marketplace、电商、服务）
- 现有定价是什么（如果有）？
- 目标市场是什么？（SMB、中型市场、企业级）
- 上市动作是什么？（self-serve 自助、sales-led 销售驱动、hybrid 混合）

### 2. 价值与竞争
- 你交付的核心价值是什么？
- 客户会考虑哪些替代方案？
- 竞争对手怎么定价？

### 3. 当前表现
- 当前转化率是多少？
- ARPU 和流失率是多少？
- 客户/潜在客户对定价有什么反馈？

### 4. 目标
- 优化目标：增长、收入还是盈利能力？
- 向上走高端市场，还是向下扩展市场？

## 定价基础

### 定价三轴

**1. Packaging（套餐打包）**：每个 tier 各包含什么？
- 功能、限额、支持级别
- 各 tier 之间如何区分

**2. Pricing Metric（计价指标）**：按什么收费？
- 按用户、按用量、固定费
- 价格如何随价值同步放大

**3. Price Point（价格点）**：收多少？
- 具体的金额
- 感知价值 vs 成本

### 基于价值的定价

定价应基于交付的价值，而不是服务成本：

- **客户感知价值**：天花板
- **你的价格**：介于替代方案与感知价值之间
- **次优替代方案**：差异化的下限
- **你的服务成本**：只是基线，不是定价依据

**关键洞见**：定价落在次优替代方案与感知价值之间。

**不要锚定在错误的东西上：**
- **不要基于竞品**：照搬竞品价格，复制的是对方的策略，不是对方的经营状况。它是参考数据，不是目标。
- **不要基于成本**：成本是下限，从来不是定价依据。价值加差异化才决定价格。

## 初期定价："先定一个你能从中学习的价格"

下面的框架（value metric、tier、Van Westendorp）用于优化已有价格。**第一天你并没有可供优化的价格，你只有一次下注。**第一个价格的目标是*学习*，不是精确。定个数，上线，让真实买家告诉你它对不对。

### $10 / $100 / $1,000 经验法则

没有任何依据时，从与目标客户匹配的数量级起步：

- **约 $10/月**：prosumer（产消者）/个人用户，高用量、低接触
- **约 $100/月**：SMB / 团队工具，SaaS 的默认档
- **约 $1,000/月**：中型市场 / 业务关键 / 销售协助成交

按**客户是谁、你交付多大价值**选档，然后从整数附近起步。有了信号之后，档内调价可以很快。

### 避免 $9 陷阱

忍住靠超低定价（例如 **$9/月**）来降低使用门槛的冲动。超低定价会：
- 制造**虚假热度**：注册量看似市场验证，其实来自永远不会按真实价格付费的人
- **困住你**：之后把价格提 5-10 倍，远比一开始就定高难得多；而且最便宜的客户流失最多、抱怨最大（低价留存问题见 [references/pricing-models.md](references/pricing-models.md)）

整数且略高，胜过取巧且便宜。

### "先收 $50，看看会发生什么"

早期 Intercom 为定价纠结时，Jason Fried 的建议本质上是：**先收 $50，看看会发生什么。**别再建模了，去拿真实信号。如果人们付钱时眉头都不皱，就提价。如果没人买账，你用一周而不是一个季度的代价学到了东西。

**八种收费结构（flat、usage、tier、user、feature、credit、outcome、hybrid）与价值/价格比**：见 [references/pricing-models.md](references/pricing-models.md)。

## 价值指标（Value Metric）

### 什么是 Value Metric？

value metric 就是你按什么收费，它应随客户获得的价值同步放大。

**好的 value metric：**
- 价格与交付价值对齐
- 容易理解
- 随客户成长而放大
- 难以钻空子

### 常见 Value Metric

| 指标 | 最适合 | 示例 |
|--------|----------|---------|
| 按用户/席位 | 协作工具 | Slack、Notion |
| 按用量 | 消耗型使用 | AWS、Twilio |
| 按功能 | 模块化产品 | HubSpot add-ons |
| 按联系人/记录 | CRM、邮件工具 | Mailchimp |
| 按交易 | 支付、marketplace | Stripe |
| 固定费 | 简单产品 | Basecamp |

### 选定你的 Value Metric

问自己："当客户消耗更多 [metric] 时，他们得到的价值也更多吗？"
- 是 → 好的 value metric
- 否 → 价格与价值不对齐

**value metric 决定定价模式。**知道什么随价值放大之后，再选怎么按它收费：flat、usage、tier、user、feature、credit、outcome 或混合模式。见 [references/pricing-models.md](references/pricing-models.md)。

## Tier 结构概览

### Good-Better-Best 框架

**Good tier（入门档）**：核心功能、有限用量、低价格
**Better tier（推荐档）**：完整功能、合理限额、锚定价格
**Best tier（旗舰档）**：全部开放、高级功能、2-3 倍于 Better 的价格

### Tier 差异化

- **功能门控**：基础功能 vs 高级功能
- **用量限额**：同样功能，不同限额
- **支持级别**：Email → Priority → Dedicated
- **访问能力**：API、SSO、自定义品牌

**详细的 tier 结构与基于画像的打包**：见 [references/tier-structure.md](references/tier-structure.md)

## 定价调研

### Van Westendorp 方法

四个问题，找出可接受的价格区间：
1. 太贵（不会考虑）
2. 太便宜（怀疑质量）
3. 贵但可能会考虑
4. 划算

用交点识别感知价格可接受区间和待测试的候选价格。所谓 "Optimal Price Point"（最优价格点）只是调研数据的交点，不是收入或利润最大化的证明。仅凭这四个问题，无法估算新价格下的转化率、流失率或需求。

### MaxDiff 分析

识别客户最看重哪些功能：
- 展示多组功能组合
- 询问：最重要？最不重要？
- 结果用于指导 tier 打包

**详细的调研方法**：见 [references/research-methods.md](references/research-methods.md)

## 何时提价

### 该提价的信号

**市场信号：**
- 竞争对手已经提价
- 潜在客户对价格毫不敏感
- "太便宜了！"之类的反馈

**业务信号：**
- 转化率非常高（>40%）
- 流失率非常低（月流失 <3%）
- 单位经济模型强劲

**产品信号：**
- 上次定价之后产品价值显著增加
- 产品更成熟/更稳定

### 提价策略

1. **Grandfather（存量保留原价）**：新价格只对新客户生效
2. **延迟提价**：提前 3-6 个月公告
3. **绑定价值**：提价同时增加功能
4. **重构套餐**：彻底改版套餐

### 推进方法

价格调整是一次 rollout（渐进推进），不是一按就完的开关。按顺序来，降低风险：

1. **先在新客户上测试。**只对*新*注册用户提价，观察转化率。新客户没有价格锚定、没有关系包袱，在动任何存量账户之前，他们能干净地告诉你市场接不接受这个数字。
2. **不要条件反射式地永远保留原价。**Grandfather 看似厚道，但可能把大笔钱留在桌上。算笔账：一个付 **$50/月**、*本应*付 **$250/月**的客户，一年差 **$2,400**，等于你每月在 $200 的水平上，对全量客户无限期补贴。Grandfather 是*过渡*（宽限期），不是永久豁免。
3. **小范围先推，再逐步扩大。**先把 **5-10%** 的存量客户切到新价格。观察一个周期的流失和工单量，再分波扩大。分波推进能控制爆炸半径，流失飙升时也有退路。
4. **提前数月沟通*为什么*，并给出大方的选项。**提前很久告诉客户价格为什么变（通常是：交付了更多价值）。给缓冲：现在升级年付就锁定旧价、延长宽限期，或一次性抵扣金。提前告知加大方选项，把怨恨时刻变成忠诚时刻。

预期并接受一定的流失。因合理提价而最可能离开的客户，通常正是利润最低、支持成本最高、价格最敏感的那批账户。

## 定价页最佳实践

### 首屏
- 清晰的 tier 对比表
- 推荐档高亮
- 月付/年付切换
- 每个 tier 一个主 CTA

### 常见元素
- 功能对比表
- 每个 tier 适合谁
- FAQ 板块
- 年付折扣标注（17-20%）
- 退款保证
- 客户 logo/信任信号

### 定价心理学
- **锚定**：先展示更高价的选项
- **诱饵效应**：中间档应该是性价比最高的
- **尾数定价**：$49 vs $50（适合主打性价比）
- **整数定价**：$50 vs $49（适合高端定位）

## 定价页拆解

当用户想审查现有定价*页面*的**清晰度、透明度和 AI 可读性**（不是定价策略本身，也不是转化率优化——那是 `cro`）时，执行一次 **teardown（拆解）**：按两个维度打分，并给出按优先级排序的修复项：

- **人类买家体验**：价值主张清晰度、套餐区分度、认知负担、信任信号、定价心理学与价格透明度。
- **AI agent 就绪度**：越来越多替买家初筛和比较工具的 LLM 与 agent，能否真正读取并引用你的定价：机器可读的价格（不是锁在图片里或藏在 "Contact us" 后面）、可抽取的 FAQ/疑虑应对内容、每个 tier 的深度信息以文本陈述、以及结构化数据。买家现在会*先*问 ChatGPT/Perplexity/Claude "what's the best X and what does it cost?"，然后才访问网站——agent 解析不了的定价页，正在丢掉你根本看不见的交易。

**快速检查（"paste test"，粘贴测试）：**把定价页 URL 交给一个能浏览网页的 AI（Perplexity、带搜索的 ChatGPT、带 web 的 Claude），或直接粘贴渲染后的页面文本，问 "what are the plans and prices?"。它完全答不上来，说明抓取你页面的 agent 同样会吃力（这是启发式判断，不证明每个 agent 都会失败）。

AI 就绪度的修复通常高影响、低成本（把价格放进文本、加 `Offer` schema）。实施交给 **schema**（Product/Offer JSON-LD）和 **ai-seo**（可抽取性、AI bot 访问、`llms.txt`）。

**完整的 10 维评分标准、打分与报告模板**：见 [references/pricing-page-teardown.md](references/pricing-page-teardown.md)。*（AI-agent-readiness 视角改编自 Kyle Poyar / Growth Unhinged。）*
