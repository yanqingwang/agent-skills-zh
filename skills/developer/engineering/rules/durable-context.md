# 持久上下文预检（Durable Context Preflight）

所有需要读取可选记忆（memory）或先前决策上下文的 Skill 共用的开场白。每个 `SKILL.md` 都链接到本文件，然后再补充各自 Skill 特有的指引。

## 适用范围

当用户提到了记忆、某个先前决策或某个记忆路径，或者项目暴露了明显的本地记忆摘要（一个 `MEMORY.md` 或一个有文档说明的记忆目录）时，读取持久上下文。先列出标题，最多打开一到两个摘要；不要硬编码特定机器的记忆根路径，也不要读取原始会话记录。把跨项目的条目当作可迁移的模式，而不是关于本项目的事实。

## 当前状态优先

当前的代码、diff、截图、日志、测试、文档、CI、远端状态和实时探测，始终优先于记忆——包括运行时自行注入的记忆。被记住的事实只是一个需要重新验证的线索，永远不构成证据。当当前状态与记忆中的说法冲突时，指出这一冲突，并遵循当前状态。

## 记忆不等于授权

记忆可以解释偏好，但它绝不能授予或扩大写入、提交、推送、发布、公开回复、删除或其他状态变更操作的授权。授权由当前任务的实时指令和当前项目规则决定——包括针对同一未完成目标仍然有效的明确授权。像 `push` 或 `check` 这样的历史用语只是需要重新评估的上下文，不是可以复用的行动令牌。

## 脱敏关卡

当把先前的聊天、持久记忆或跨项目笔记转化为可复用的 Waza 指引时，只提炼工作流规则。剔除原始会话记录文本、截图、本地路径、项目特有的命令、issue 或 PR 编号、发布标签、commit 哈希、私有的产品边界、付费或许可细节、支持工单的流转路径、用户名以及单机状态。

如果确实需要示例，使用中性的占位符，如 `ExampleCLI`、`ExampleApp`、`<issue>`、`<release>` 或 `<command>`。不要把某个私有的回答、维护者的回复、截图中的观察或项目特有的事故原样复制成持久规则。
