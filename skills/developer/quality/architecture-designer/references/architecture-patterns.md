# 架构模式

## 模式对比

| 模式 | 最适合 | 团队规模 | 权衡 |
|---------|----------|-----------|------------|
| **单体（Monolith）** | 简单领域、小团队 | 1-10 | 部署简单；难以单独扩展某部分 |
| **模块化单体（Modular Monolith）** | 复杂度增长中 | 5-20 | 有模块边界；仍是单次部署 |
| **微服务（Microservices）** | 复杂领域、大型组织 | 20+ | 可独立扩展；运维复杂 |
| **Serverless** | 负载多变、事件驱动 | 任意 | 自动伸缩；冷启动、厂商锁定 |
| **事件驱动（Event-Driven）** | 异步处理 | 10+ | 松耦合；调试复杂 |

## 单体（Monolith）

```
┌─────────────────────────────────────┐
│            Application              │
│  ┌─────┐  ┌─────┐  ┌─────┐         │
│  │Users│  │Orders│ │Products│       │
│  └─────┘  └─────┘  └─────┘         │
│  └──────────┬──────────────┘        │
│          Database                    │
└─────────────────────────────────────┘
```

**何时使用**：
- 启动新项目
- 小团队（< 10 名开发者）
- 简单领域
- 需要快速迭代

**优点**：部署简单、调试容易、无网络延迟
**缺点**：难以独立扩展、技术锁定、部署风险

## 微服务（Microservices）

```
┌──────────┐  ┌──────────┐  ┌──────────┐
│  Users   │  │  Orders  │  │ Products │
│ Service  │  │ Service  │  │ Service  │
└────┬─────┘  └────┬─────┘  └────┬─────┘
     │             │             │
┌────▼────┐  ┌────▼────┐  ┌────▼────┐
│ User DB │  │Order DB │  │ Prod DB │
└─────────┘  └─────────┘  └─────────┘
```

**何时使用**：
- 大团队（20+ 名开发者）
- 边界清晰的复杂领域
- 各服务有不同的扩展需求
- 多语言技术栈需求

**优点**：独立扩展、团队自治、故障隔离
**缺点**：分布式系统复杂度、最终一致性、运维开销

## 事件驱动（Event-Driven）

```
┌──────────┐     ┌─────────────┐     ┌──────────┐
│ Producer │────▶│ Message Bus │────▶│ Consumer │
└──────────┘     │  (Kafka)    │     └──────────┘
                 └─────────────┘
                       │
                       ▼
                 ┌──────────┐
                 │ Consumer │
                 └──────────┘
```

**何时使用**：
- 需要异步处理
- 服务间松耦合
- 事件溯源（Event Sourcing）需求
- 高吞吐消息传递

**优点**：服务解耦、可扩展、有审计轨迹
**缺点**：最终一致性、调试复杂、消息顺序问题

## CQRS（命令查询职责分离）

```
┌─────────┐         ┌─────────────┐
│ Commands│────────▶│ Write Model │──┐
└─────────┘         └─────────────┘  │
                                     ▼
                              ┌──────────┐
                              │  Events  │
                              └──────────┘
                                     │
┌─────────┐         ┌─────────────┐  │
│ Queries │◀────────│ Read Model  │◀─┘
└─────────┘         └─────────────┘
```

**何时使用**：
- 读写比例严重倾斜
- 复杂的读查询
- 事件溯源架构
- 读写有各自不同的优化需求

## 快速参考

| 需求 | 推荐模式 |
|-------------|---------------------|
| 简单 CRUD 应用 | 单体 |
| 成长中的创业项目 | 模块化单体 |
| 企业级规模 | 微服务 |
| 负载多变 | Serverless |
| 异步处理 | 事件驱动 |
| 读多写少 | CQRS |
