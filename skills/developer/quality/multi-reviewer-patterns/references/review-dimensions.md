# 审查维度清单

并行代码审查中各审查维度遵循的详细清单。

## 安全审查清单

### 输入处理

- [ ] 所有用户输入都经过校验和净化
- [ ] SQL 查询使用参数化语句（不用字符串拼接）
- [ ] HTML 输出正确转义以防 XSS
- [ ] 文件路径经过校验以防路径穿越
- [ ] 请求大小限制得到执行

### 认证与授权

- [ ] 所有受保护端点都要求认证
- [ ] 授权检查核实用户拥有该操作的权限
- [ ] JWT token 经过校验（签名、过期时间、签发者）
- [ ] 密码哈希使用 bcrypt/argon2（不用 MD5/SHA）
- [ ] 会话管理遵循最佳实践

### 机密与配置

- [ ] 没有硬编码的机密、API key 或密码
- [ ] 机密从环境变量或密钥管理器加载
- [ ] .gitignore 包含敏感文件模式
- [ ] 调试/开发端点在生产环境已禁用

### 依赖

- [ ] 直接依赖中没有已知 CVE
- [ ] 依赖锁定到具体版本
- [ ] 没有增大攻击面的多余依赖

## 性能审查清单

### 数据库

- [ ] 没有 N+1 查询模式
- [ ] 查询使用合适的索引
- [ ] 大表上没有 SELECT \*
- [ ] 列表端点实现了分页
- [ ] 连接池已配置

### 内存与资源

- [ ] 没有内存泄漏（事件监听器已清理，流已关闭）
- [ ] 大数据集用流式处理，不整体载入内存
- [ ] 文件句柄和连接正确关闭
- [ ] 代价高的操作使用了缓存

### 计算

- [ ] 没有不必要的重复计算或冗余操作
- [ ] 算法复杂度与数据规模匹配
- [ ] I/O 密集处使用异步操作
- [ ] 主线程上没有阻塞操作

## 架构审查清单

### 设计原则

- [ ] 单一职责：每个模块/类只有一个变化理由
- [ ] 开闭原则：不改代码即可扩展
- [ ] 依赖倒置：依赖抽象而非具体实现
- [ ] 模块之间没有循环依赖

### 结构

- [ ] 关注点清晰分离（UI、业务逻辑、数据）
- [ ] 错误处理策略在代码库中保持一致
- [ ] 配置外置，不硬编码
- [ ] API 契约定义清晰且有版本

### 模式

- [ ] 全程使用一致的模式（不混用模式）
- [ ] 抽象层级恰当（不过度设计也不欠设计）
- [ ] 模块边界与领域边界对齐
- [ ] 共享工具真正共享（没有重复）

## 测试审查清单

### 覆盖

- [ ] 关键路径有测试覆盖
- [ ] 边界情况已测试（空输入、null、边界值）
- [ ] 错误路径已测试（失败时会发生什么）
- [ ] 集成点有集成测试

### 质量

- [ ] 测试是确定性的（没有 flaky 测试）
- [ ] 测试相互隔离（测试之间不共享状态）
- [ ] 断言具体（不是只断言"没抛错"）
- [ ] 测试名清楚描述被测内容

### 可维护性

- [ ] 测试不复刻实现逻辑
- [ ] mock/stub 最小且准确
- [ ] 测试数据清晰且相关
- [ ] 不读实现也能看懂测试

## 可访问性审查清单

### 结构

- [ ] 使用语义化 HTML 元素（nav、main、article、button）
- [ ] 标题层级合理（h1 → h2 → h3）
- [ ] ARIA 角色与属性使用正确
- [ ] landmark 标识页面区域

### 交互

- [ ] 所有功能可经键盘访问
- [ ] 焦点顺序合理且可见
- [ ] 没有键盘陷阱
- [ ] 触摸目标至少 44x44px

### 内容

- [ ] 图片有有意义的 alt 文本
- [ ] 颜色不是传达信息的唯一手段
- [ ] 文本对比度充足（常规 4.5:1，大字号 3:1）
- [ ] 内容在 200% 缩放下可读
