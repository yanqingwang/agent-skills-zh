# 审查清单

## 综合审查清单

| 类别 | 关键问题 |
|----------|---------------|
| **设计** | 符合既有模式吗？抽象层次合适吗？ |
| **逻辑** | 边界情况处理了吗？有竞态条件吗？空值检查了吗？ |
| **安全** | 输入验证了吗？鉴权检查了吗？秘密安全吗？ |
| **性能** | 有 N+1 查询吗？内存泄漏？需要缓存吗？ |
| **测试** | 覆盖充分吗？边界情况测了吗？mock 用得合适吗？ |
| **命名** | 清晰、一致、能表达意图吗？ |
| **错误处理** | 错误被捕获了吗？消息有意义吗？记录日志了吗？ |
| **文档** | 公开 API 有文档吗？复杂逻辑有解释吗？ |

## 审查流程

### 1. 上下文（5 分钟）
- [ ] 读 PR 描述
- [ ] 理解要解决的问题
- [ ] 查看关联的 issue/工单
- [ ] 记下预期的改动

### 2. 结构（10 分钟）
- [ ] 审查文件组织
- [ ] 检查架构契合度
- [ ] 核实所用设计模式
- [ ] 记下任何破坏性变更

### 3. 代码细节（20 分钟）
- [ ] 审查逻辑正确性
- [ ] 检查边界情况
- [ ] 核实错误处理
- [ ] 查找安全问题
- [ ] 检查性能隐患
- [ ] 审查命名清晰度

### 4. 测试（10 分钟）
- [ ] 核实测试覆盖
- [ ] 检查测试质量
- [ ] 寻找边界情况测试
- [ ] 确保 mock 使用合适

### 5. 最终过一遍（5 分钟）
- [ ] 记下正面模式
- [ ] 给反馈排优先级
- [ ] 写摘要

## 分类深挖

### 设计问题
- 这个改动应该放在这个文件/模块里吗？
- 抽象层次合适吗？
- 能不能更简单？
- 遵循既有模式了吗？
- 不修改就能扩展吗？

### 逻辑问题
- null/undefined 输入时会发生什么？
- 边界条件处理了吗？
- 会有竞态条件吗？
- 操作顺序正确吗？
- 所有代码路径都测过了吗？

### 安全问题
- 所有用户输入都验证了吗？
- SQL 查询参数化了吗？
- 输出正确编码了吗？
- 秘密处理安全吗？
- 认证（Authentication）检查了吗？
- 授权（Authorization）强制执行了吗？

### 性能问题
- 有 N+1 查询模式吗？
- 数据获取高效吗？
- 昂贵操作有缓存吗？
- 会导致内存泄漏吗？
- 实现分页了吗？

## 快速参考

| 审查重点 | 时间占比 |
|--------------|--------|
| 上下文与 PR 描述 | 10% |
| 架构与设计 | 20% |
| 代码逻辑与细节 | 40% |
| 测试与覆盖 | 20% |
| 最终审查与摘要 | 10% |
